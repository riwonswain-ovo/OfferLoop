# AI Coding 经历简历证据规则

当入选经历包含 Coding Agent、低代码/全栈平台、AI 辅助原型或应用交付时，与
`ai-product-resume.md` 一起读取。

## 动词与参与层级

| 已确认事实 | 可用表达 | 避免升级 |
|---|---|---|
| 跟随课程或复用仓库 | 复现、跑通、验证、学习 | 独立设计、从零搭建 |
| 配置第三方能力 | 配置、接入、联调 | 研发、实现底层能力 |
| 用 Coding Agent 生成并亲自验收 | 借助 AI 完成、搭建、迭代、验收 | 独立编码、全栈研发 |
| 定义规格并交付 MVP | 定义、拆解、推动、交付、验收 | 生产上线 |
| 与研发协作生产运行 | 设计、协同落地、上线、监控 | 一人完成全部技术栈 |

具体动词仍以材料中的本人动作和岗位语言为准。

## Bullet 证据结构

优先压缩为：

```text
用户任务/业务约束
→ 本人定义的规格或关键取舍
→ AI、模板、第三方平台、程序与人工的真实分工
→ 本人验收或修复的具体交付
→ 与真实成熟度匹配的结果
```

不把工具清单写成一条 bullet。技术栈只有能说明作用和取舍时才保留。

## “生产级”门禁

- 本地运行：不能写上线；
- 公网部署：可写“完成部署/可访问 Demo”，不能仅凭链接写生产；
- MVP：写核心链路和验收范围；
- 试点：必须有真实用户/数据和反馈；
- 生产：必须有持续运行、权限、监控、故障/回滚或业务结果证据。

“production deployment”是部署环境名称，不等于生产业务状态。

## 技能区

只有材料支持时，才写：

- AI Coding：需求拆分、上下文/规则、分阶段实现与人工验收；
- Spec/SDD：规格、计划、任务与验收闭环；
- API/数据库：真实接口、数据对象、状态或权限设计；
- Git/测试/部署：本人实际执行的版本、用例、发布或问题修复；
- Harness：环境、进度、工具、权限、验证和回退机制。

不写具体工具熟练度，除非用户能说明在真实项目中的反复使用和独立判断。

## 质量门

- 每个“开发/实现/搭建”都能回答本人做了什么、AI 做了什么；
- 每个“上线/生产”都能回答用户、环境、监控和运行证据；
- 每个架构词都能连接业务动作；
- 跟做课程没有变成独立项目设计；
- 安全、权限和测试没有因使用托管平台而被默认完成。
