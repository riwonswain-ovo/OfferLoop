# 求职者面试复盘规范

本文件只规范求职者视角文档。招聘者视角评估完整读取并遵守
`recruiter-analysis.md`。

## 目录

1. 核心目标
2. 证据与可信度
3. 整场表现概览
4. 真实表达诊断
5. 全题简评
6. 重点问题深度复盘

8. 改进优先级与训练计划

## 核心目标

围绕以下四层生成复盘：

1. 用户实际做过什么；
2. 用户在面试现场说出了什么；
3. 招聘者可能从回答中接收到什么；
4. 用户下一次怎样更准确、自然地表达。

不要把招聘者文档改写成温和版本。求职者复盘必须解释问题、还原错位，并给出能够执行和训练
的改法。

## 一、证据与可信度

对 ASR 片段使用：

- **高**：说话人和语义清楚；
- **中**：语义基本清楚，但有少量 ASR 错误或边界不明；
- **低**：说话人、关键词或句子结构无法可靠判断。

修正 ASR 时同时保留原片段和修正理由。不能为了形成流畅问答删除不利回答或补写未说内容。
低可信度片段不得支撑确定性评价。

严格区分三类材料：

- **现场原话**：来自用户确认后的 ASR；
- **已确认事实**：来自用户指定的简历、`experience-deepthink` 或后续确认；
- **分析推断**：包括面试官考察意图、招聘者印象和岗位影响。

用户事后补充只能进入“实际做过什么”和改进建议，不能改写成现场原话。面试官意图和招聘者
印象始终标记为推断。

## 二、整场表现概览

先给出能够帮助用户排序注意力的结论：

- 本轮面试呈现出的候选人形象；
- 最有效的 3 处表现；
- 最影响结果的 3 处问题；
- 问题主要属于表达、内容、证据、岗位匹配还是真实经历缺口；
- 下一场面试前最优先解决的 1–3 项。

不要把所有问题写成同等严重，也不要只给综合分数或空泛鼓励。

## 三、真实表达诊断

直接分析面试者未经书面化润色的原话，检查：

- 高频口头禅、重复词和无效连接词；
- 句子过长、未完成句和中途改变方向；
- 结论是否出现过晚，背景铺垫是否挤压核心回答；
- 模糊词、弱化词或防御性措辞是否影响可信度；
- 术语是否替代了事实、行动和解释；
- 被追问后是否失焦、回避、重复原答案或前后不一致；
- 自我修正是否提升清晰度；
- 回答的信息密度和层次是否足以让听者抓住重点。

每项判断引用代表性原句并说明实际影响。不要只写“表达冗长”“逻辑一般”。正常的少量口语
停顿不单独定性为问题；ASR 没有可靠时间或音频时，不评价语速、停顿时长、音量或语气。

## 四、全题简评

覆盖解析稿中的每组主问题和追问，不遗漏不利回答。每组至少记录：

- 主问题和追问摘要；
- 是否正面回答；
- 最有效的信息；
- 最主要的问题；
- 问题类型：表达 / 内容 / 结构 / 证据 / 一致性 / 岗位匹配 / 经历缺口；
- 对招聘判断的可能影响；
- 是否进入深度复盘。

简评保持短小。不能因为某题未进入深度复盘就省略其存在或改写其表现。

## 五、重点问题深度复盘

默认选择最影响结果的 3–5 组问题。面试较短时可以少于 3 组；只有用户明确要求时才对所有
问题进行同等深度分析。优先选择：

- 直接验证岗位核心能力的问题；
- 明显答非所问或证据不足的问题；
- 有真实亮点但现场没有说清的问题；
- 暴露所有权、数据或一致性风险的问题；
- 能代表跨题重复根因的问题。

每组深度复盘使用以下结构。

### 1. 问题与追问链

保留主问题、追问顺序、时间位置和必要原句。说明“可能考察什么”，并明确标记为推断。

### 2. 现场回答

引用能够反映真实表现的关键原话，概括回答路线，标记偏题、中断、遗漏和自我修正。不要用
润色后的摘要替代原始证据。

### 3. 有效部分

指出哪句话提供了什么事实、证据或能力信号，以及为什么可能帮助招聘判断。不要泛泛写
“回答得不错”。

### 4. 主要问题

按实际情况从以下维度判断：

- **内容**：是否回答了问题，事实是否准确；
- **结构**：结论、论据和层次是否清楚；
- **证据**：是否说明个人行动、决策、结果和可核验细节；
- **表达**：是否冗长、跳跃、含混、回避或防御；
- **岗位匹配**：是否呈现目标岗位真正需要的能力；
- **追问表现**：能否理解追问、澄清问题并保持一致。

每项判断引用回答证据，并区分“没有说出来”“证据不足”和“现有材料中确实缺少”。

### 5. 三层对照

| 层次 | 判断依据 |
|---|---|
| 用户实际做过什么 | 只使用已确认的简历、经历深挖和用户补充事实 |
| 用户现场说出了什么 | 只使用确认后的 ASR |
| 招聘者可能听到了什么 | 基于招聘者可见材料作推断，并说明不确定性 |

用三层对照识别遗漏表达、所有权模糊、证据错位、现场失真和真实经历缺口。材料没有提供事实时
写“待补充”，不得自行填补。

### 6. 下一次回答策略

说明：

- 开头先给什么结论；
- 哪些背景保留或删除；
- 哪个个人行动、决策、取舍或结果需要提前；
- 如何回应本题的关键追问；
- 哪些内容必须先向用户补齐事实才能使用。

根据问题选择自然结构，不机械套用 STAR。经历题可以使用“背景—任务—行动—结果—反思”，
观点题可以使用“结论—理由—例证—边界”，具体结构以问题为准。

### 7. 自然口语参考回答

只使用已确认事实生成一版可在真实面试中说出的回答：

- 保留自然口语节奏和用户常用词汇；
- 提高结构与信息密度，但不写成报告、演讲稿或简历 bullet；
- 不堆砌方法论，不补写未发生的行动；
- 不编造数据、结果、所有权或面试现场反应；
- 事实不完整时使用明确的待补充标记，不生成貌似完整的虚构答案；
- 作为表达示范，不要求用户逐字背诵。

## 六、跨题一致性与根因

在逐题分析后检查：

- 同一经历在不同题目中的角色、事实和结果是否一致；
- 数据、时间、项目所有权和求职动机是否前后一致；
- 是否反复使用同一案例，导致能力覆盖不足；
- 是否长期只描述执行，不呈现判断、取舍和复盘；
- 是否反复缺少个人贡献、结果证据或岗位关联；
- 是否在失败、冲突或负面结果上持续回避；
- 哪些逐题问题其实来自同一个表达或准备根因。

把重复问题合并成少量根因，不在行动清单中重复列出同一问题。

## 七、改进优先级与训练计划

按影响和紧迫性分级：

- **P1**：可能直接影响岗位判断，下一场面试前必须解决；
- **P2**：不一定直接淘汰，但明显降低可信度，需要持续训练；
- **P3**：长期表达习惯或锦上添花的优化。

每项训练任务包含：

- 问题表现；
- 对招聘判断的影响；
- 修正动作；
- 对应训练题或追问；
- 可验证的完成标准。

最后只突出 Top 1、Top 2、Top 3。完成标准应可观察，例如“在 60 秒内说清个人职责、关键
决定和结果，并承受两轮追问”，不要写“加强表达能力”。

## 八、材料回流建议

只提出回流建议，不自动修改其他材料：

- 事实、所有权或结果需要继续补齐：建议运行 `experience-deepthink`；
- 回答结构和追问承压需要训练：建议运行 `mock-lab`；
- 下一轮面试需要系统准备：建议运行 `interview-prep`；
- 简历与事实或现场表达不一致：列出精确位置，建议用户另行修订简历。

## 九、文档结构

```markdown
# <共享脚本生成的标题>

## 产物信息
## 面试概览
## 原始转写来源与质量
## 整场表现概览
## 表达习惯与口语特征
## 全部问题简评
## 重点问题深度复盘
## 跨题一致性与根因
## 准备命中与遗漏
## 优先改进与训练计划
## 简历与素材回流建议
## 下一轮行动清单
```

对话粘贴 ASR 时，“原始转写来源与质量”必须出现：

> 来源为对话粘贴、无持久化原始转写文档。
