# AI Coding 与产品交付面试复盘

当本场围绕 Coding Agent、应用搭建、技术原型、API/数据库、测试、部署或生产经历展开时，
与 AI 产品复盘视角一起读取。

## 观察维度

1. **参与层级**：跟做、配置、AI 辅助实现、独立交付或团队生产是否说清；
2. **规格与判断**：是否说明需求、约束、非目标、拆分和关键取舍；
3. **系统理解**：架构词是否连接真实业务动作、状态、权限和异常；
4. **验证责任**：是否有测试输入、人工验收、失败、修复和版本证据；
5. **成熟度**：本地、部署、MVP、试点和生产口径是否一致；
6. **所有权**：AI、模板、平台、研发和本人贡献是否分开。

## 失分标签

仅在现场原话支持时使用：

- **工具替代决策**：罗列工具但没有任务、备选和取舍；
- **生成等于完成**：以 Agent 的完成声明替代本人验收；
- **部署等于生产**：只有链接或部署环境，没有用户和运行治理；
- **跟做升级主导**：现成 PRD/仓库/教程被表述为独立设计；
- **托管等于安全**：默认平台已解决权限、密钥和数据隔离；
- **架构词悬空**：API、数据库、前后端等不能连接一条真实业务动作；
- **技术所有权越界**：把 AI/研发实现写成本人编码或架构成果；
- **工程事实缺失**：无法提供用例、报错、修复、版本或部署物证。

后续回答补出证据时，应更新标签强度。

## 追问解码

- 询问“是不是你写的”：可能在核验所有权；
- 要求现场画链路：可能在核验系统理解；
- 追问测试与报错：可能在区分演示与可靠交付；
- 询问用户、环境、监控：可能在核验生产成熟度；
- 反复问“你具体做了什么”：当前分工证据可能仍不清楚。

以上只能写为基于上下文的可能解释，不能断言面试官认定造假或技术不足。

## 精确回流

- 参与层级、系统事实、测试或成熟度缺失：`experience-deepthink`；
- 简历动词或“生产级”承诺过高：`resume-tailor`；
- 工程术语和岗位交付题准备不足：`interview-prep`；
- 有事实但现场无法承受所有权/系统追问：`mock-lab`。
