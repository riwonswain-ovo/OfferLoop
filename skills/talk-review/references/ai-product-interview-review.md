# AI 产品经理面试复盘视角

目标岗位以 AI 产品、AIGC、大模型、Agent、模型/数据平台或 AI+行业产品为核心时读取。本文只
改变复盘的专业观察角度，不改变 ASR 确认、证据可见性和推断边界。

## 一、动态评价维度

根据 JD 和本场问题选择二至四项深入评价：

1. **业务与用户**：是否先说明用户、任务、原流程、价值和错误代价；
2. **产品判断**：是否比较过替代方案、定义边界、MVP 和人机分工；
3. **AI 技术链路**：是否理解数据、Prompt/RAG/Workflow/Agent/训练如何作用于业务；
4. **评测与治理**：是否有实例、指标口径、Bad Case、准入、监控和人工接管；
5. **所有权与协作**：是否区分本人判断/交付与算法、研发、业务团队实现；
6. **结果与成熟度**：项目阶段、用户/运行证据、结果归因和局限是否一致。

不能因面试官没有追问某维度，就推断候选人不具备该能力。

## 二、AI 项目追问链解码

重建每组问题时，观察面试官是否从一个强主张继续索要：

```text
用户/问题
→ 机制
→ 具体实例
→ 指标口径或物证
→ 个人所有权
→ 失败、限制或反事实
```

记录追问实际发生到哪一层、候选人在哪一层开始重复或失去证据。该链只用于解释现场信息缺口，
不能把面试官意图写成确定事实。

## 三、现场行为的谨慎解释

| 行为 | 可能表示 | 不能直接断言 |
|---|---|---|
| 打断背景铺垫 | 需要更快得到用户、问题或结论 | 面试官不耐烦或否定项目 |
| 重复/换问法 | 原问题未被正面回答或口径不清 | 候选人一定答错 |
| 要求具体例子 | 抽象方法缺实例证据 | 面试官认定经历造假 |
| 追问公式/样本 | 数字证明范围不清 | 数据一定虚假 |
| 询问团队/本人 | 所有权需要验证 | 候选人只是参与者 |
| 询问 PRD/Demo/部署 | 项目成熟度需要验证 | 没展示就等于没做 |
| 突然转题 | 可能时间有限或已取得足够信息 | 上一题通过或失败 |

解释必须引用前后问题和候选人回答，并使用“可能”“本场未满足”等证据语言。

## 四、高频失分标签

只在有具体原话支持时使用：

- **技术先于问题**：先讲架构，没有用户和任务；
- **术语替代机制**：只说用了 Agent/RAG/微调，没说链路如何工作；
- **实例缺失**：多轮追问仍只有“通常、比如、我们会”；
- **指标无口径**：数字没有定义、基线、样本、窗口或测量；
- **归因越界**：把同期变化或团队结果完全归因于本人方案；
- **所有权模糊**：个人与团队动作混写，决策权不清；
- **成熟度冲突**：简历、主回答和追问中的 Demo/试点/上线口径不同；
- **只讲成功路径**：没有失败、人工接管、限制或未达成；
- **重复原答案**：追问后没有补充新证据；
- **技术硬撑**：超出职责仍给出确定实现结论；
- **知识未连接产品**：概念正确，但说不出适用条件和产品影响。

每个标签同时指出正向反证；例如用户后续补出真实样本时，应把“实例缺失”更新为“现场出现
较晚”，不能保留过强结论。

## 五、三层诊断

对重点问题分别判断：

1. **真实经历层**：指定材料中是否有该事实；
2. **准备层**：用户是否知道但没有组织好，或公司/JD/术语准备不足；
3. **现场表达层**：是否因结论过晚、答非所问或追问失稳没有呈现。

避免把所有问题都归为表达。真实材料没有数据、样本或本人贡献时，必须标记为经历缺口。

## 六、精确回流

| 发现 | 回流 |
|---|---|
| 项目事实、实例、指标口径、所有权或限制缺失 | `experience-deepthink` |
| 简历使用了材料无法支持的技术词、数字或成熟度 | `resume-tailor` |
| 公司业务、JD 专业知识、术语或轮次准备不足 | `interview-prep` |
| 已有事实但回答失焦、重复、无法承受追问 | `mock-lab` |

回流建议必须写出精确任务。例如：

> 继续深挖“知识库问答项目”的召回率口径：确认测试集来源、分母、标注人和本人负责的验证动作。

不要只写“加强 AI 技术学习”或“多练面试”。

## 七、参考回答边界

- 项目回答只使用已确认事实；
- 可以补充推荐结构，不能补充未发生的技术决策；
- 用户事后补充的项目事实只能进入下一次回答，不能改写成现场已说；
- 不会的技术细节可以给出诚实边界表达；
- 课程案例、固定阈值、模型榜单和个人题库答案不得进入用户参考回答。
