# Interview Question Bank

统一管理两份 Markdown 飞书文档：

- `待学习题库`：用户仍需准备或练习的问题。
- `已学会题库`：用户明确表示已经掌握的问题。

本 Skill 不自行生成面试题，不从其他训练文档批量猜题，也不判断用户是否已经学会。

运行相对路径前，先从当前 `SKILL.md` 定位 Skill 根目录。

## 前置读取

1. 完整读取 `references/question-bank-contract.md`。
2. 定位兄弟 `offerloop-workspace`，完整读取其
   `references/artifact-contract.md`。
3. 读取 `lark-wiki` 和 `lark-doc` Skill。
4. 用共享脚本分别解析 `question_bank_pending` 和
   `question_bank_mastered` 文档 locator。
5. schema、locator 或权限未就绪时路由到 `offerloop-setup` /
   `offerloop-workspace`。首次创建空白题库或登记用户上传题库前，展示目标并取得确认。

## 初始化与导入

- 用户没有题库时，经确认创建两份空白 Markdown 文档并登记。
- 用户已有题库时，先读取并展示导入摘要；只把用户确认的题目规范化后写入
  `待学习题库`，原文档不移动、不改写、不删除。
- `已学会题库` 不从外部材料自动推断；只有用户明确说已经学会的题目才能进入。

## 接收候选题

`resume-deepthink`、`pm-sense`、`interview-prep`、`mock-lab` 和
`talk-review` 只能提交用户本轮明确选择的候选题。接收时：

1. 保留来源 Skill、`run_id`、来源文档、简历版本、方向、公司、岗位和面试环节等已知信息。
2. 同时读取两份题库，按 `question_id` 和规范化题干检查重复。
3. 已在任一题库中的题目不重复添加，只补充不冲突的来源信息。
4. 新题生成稳定 `question_id`，写入 `待学习题库`。
5. 冲突或疑似同题不同表述时展示候选，让用户决定合并、分别保留或跳过。
6. 写后重新读取并验证；未验证成功不得声称已经加入题库。

## 查询与练习

可按关键词、题型、岗位方向、面试环节、来源 Skill 或简历版本筛选。默认只返回必要字段和少量
候选；用户要求全文时再读取完整答案与备注。

本 Skill 只管理题目状态。用户要进行真实模拟面试时路由到 `mock-lab`。

## 标记已学会

1. 按 `question_id` 优先匹配；没有 ID 时按题干检索。
2. 唯一命中也要展示题干并让用户确认；多条候选不得取第一条。
3. 先把完整题目追加到 `已学会题库`，写入 `mastered_at` 和用户给出的掌握说明。
4. 重新读取已学会题库确认写入成功，再从 `待学习题库` 删除同一 `question_id`。
5. 最后重新读取两份题库，确认题目只存在于已学会题库。
6. 如果追加成功但移除失败，保留两边数据并报告“迁移待修复”；不得为了消除重复而删除已
   验证的已学会记录。

用户说“还没学会”“放回待学习”时采用相反顺序：先写入并验证待学习题库，再从已学会题库
移除。

## 安全边界

- 任何批量导入、批量移动、整库覆盖或删除都先展示差异并取得确认。
- 不根据模拟评分、复盘结论或回答质量自动移动题目。
- 不把简历正文、ASR 全文或私人材料复制进题库；只保留必要的来源链接和关联名称。
- 两份题库发生并发变化时重新读取并重新计算补丁，不用旧快照覆盖新内容。
