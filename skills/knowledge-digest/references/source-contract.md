# 信息源与增量状态契约

## 来源模式

每个来源必须选择一种主模式：

- `知识库`：包含多篇文章，目标是全量盘点、知识地图和阅读完成度。
- `新闻站点`：持续更新，目标是发现用户感兴趣的新增新闻。
- `混合`：首次按知识库盘点，之后按新闻站点增量追踪。

## 读取方式

支持：

1. RSS 2.0、Atom。
2. 官方 API。
3. 用户指定的飞书 Base 或飞书知识库目录。
4. 无需登录且文章链接结构稳定的公开栏目页。
5. 用户有权访问的登录态浏览器页面，包括跨空间 FlowUs 知识库。

登录态浏览器可以读取当前账号可见内容，但不等于机器人 API 获得了该空间权限；会话失效后
必须暂停。公众号动态流、验证码页面、付费墙和复杂脚本目录不承诺稳定支持。不得绕过访问
控制，也不得把搜索结果摘要当作原文。

## 信息源表

表名固定为 `信息源`：

| 字段 | 类型 | 说明 |
|---|---|---|
| 来源 ID | 单行文本 | `src-` 开头的稳定 ID |
| 来源名称 | 单行文本 | 用户可读名称 |
| 来源模式 | 单选 | 知识库、新闻站点、混合 |
| 来源类型 | 单选 | RSS、API、公开栏目、飞书 Base、飞书知识库、登录态浏览器 |
| 来源链接 | URL | 用户登记的入口 |
| 关注主题 | 多行文本 | 可执行兴趣规则 |
| 排除主题 | 多行文本 | 明确不要的内容 |
| 阅读目标 | 多行文本 | 知识库模式使用 |
| 计划完成日 | 日期 | 知识库模式使用 |
| 文章总数 | 数字 | 当前可访问且去重后的文章数 |
| 已读数量 | 数字 | 用户确认完成的文章数 |
| 下一批 | 多行文本 | 下一阅读批次的标题和预计时长 |
| 阅读计划 | URL | 完整计划文档 |
| 同步频率 | 单选 | 手动、每天、每周 |
| 单次上限 | 数字 | 新闻默认 20；知识库按分页能力设置 |
| 启用状态 | 单选 | 已启用、已暂停 |
| 游标 | 多行文本 | 来源私有、可序列化状态 |
| 上次成功时间 | 日期时间 | 最近完整成功 |
| 同步状态 | 单选 | 待盘点、盘点中、待同步、同步中、正常、部分失败、需处理 |
| 状态说明 | 多行文本 | 克制的错误摘要，不含秘密 |

表名固定为 `知识清单`：

| 字段 | 类型 | 说明 |
|---|---|---|
| 条目 ID | 单行文本 | `itm-` 开头的稳定 ID |
| 来源 ID | 单行文本 | 关联信息源 |
| 标题 | 单行文本 | 原文标题 |
| 原文链接 | URL | 规范化文章链接 |
| 目录路径 | 多行文本 | 从根入口到文章的层级 |
| 一级主题 | 单选 | 知识地图主类 |
| 二级主题 | 单行文本 | 知识地图子类 |
| 内容类型 | 单选 | 概念、方法、案例、观点、工具、资料 |
| 难度 | 单选 | 入门、进阶、高阶 |
| 重要度 | 单选 | 必读、推荐、选读 |

## 游标原则

- 知识库：保存待续扫目录、分页游标、已见 URL 集合或压缩映射、盘点完成标志。
- RSS：保存最新已提交 entry ID、发布时间和回看窗口。
- API：保存官方游标和安全回看窗口。
- Base/Wiki：保存最近成功更新时间、记录或文档 ID 与版本映射。
- 栏目页：保存最近已见文章 URL 集合和最近发布时间；始终回看最近一页。
- 登录态浏览器：保存已见 URL 和目录续扫位置，不保存 Cookie 或 token。

发现顺序可以变化，游标不能只依赖列表位置。候选读取或索引写入失败时不推进对应候选的完成
状态；来源级游标只推进到连续成功位置。

## 状态机

```text
知识库：待盘点 → 盘点中 → 正常
                    ├→ 部分失败 → 续扫 → 正常
                    └→ 需处理 → 用户修复权限 → 待盘点

新闻：待同步 → 同步中 → 正常
                  ├→ 部分失败 → 下次补偿 → 正常
                  └→ 需处理 → 用户修复来源或权限 → 待同步

已启用 ↔ 已暂停
```

连续三次出现相同结构或权限错误时标记 `需处理`，停止自动重试；网络瞬时错误保持
`部分失败`。
