# 知识库全量阅读工作流

## 盘点

1. 识别根入口、目录层级、分页方式和文章链接规则。
2. 遍历所有当前可访问节点，记录每一页的发现状态。
3. 将目录页、文章页、附件、重复链接和不可访问项分开。
4. 规范化 URL，并用 `source_id + canonical_url` 生成 `item_id`。
5. 输出盘点完整性：
   - 已遍历目录数；
   - 已发现文章数；
   - 去重后文章数；
   - 无法访问或解析数；
   - 是否仍有未完成分页。

登录态浏览器来源必须在会话有效时遍历。浏览器关闭、登录失效或目录懒加载未完成时，将盘点
标记为 `部分完成`，保留续扫位置。

## 知识地图

为每篇文章记录：

- 一级主题和二级主题；
- 内容类型：概念、方法、案例、观点、工具或资料；
- 难度：入门、进阶、高阶；
- 重要度：必读、推荐、选读；
- 前置文章；
- 预计阅读分钟数；
- 一句话用途。

同层分类应互斥且覆盖主要内容。分类不稳定时先保留“待归类”，不要强行塞入已有主题。

## 阅读计划

优先收集：阅读目标、截止时间、每周可投入时间、单次偏好时长和已有基础。缺少信息时使用
以下草案假设并明确展示：

- 每周 5 天；
- 每次 30 分钟；
- 每周保留一次复习；
- 先必读和前置内容，再推荐内容，最后选读内容。

按以下原则排期：

1. 先基础概念，再方法和案例。
2. 同主题集中阅读，但每个批次避免连续堆叠高难内容。
3. 每批阅读量不超过用户单次预算。
4. 每完成一个主题安排一次回顾或知识检查。
5. 计划需要覆盖全部可访问文章；选读也必须进入末尾批次，除非用户明确排除。

## 完成度

阅读状态固定为：

```text
待读 → 阅读中 → 已读
   └→ 暂缓

任意状态 → 无法访问
```

只有用户确认读完、完成阅读检查，或用户明确授权以其他信号认定完成时，才能进入 `已读`。
摘要已生成不等于用户已读。

每次更新报告：

- `已读 / 可访问总数`；
- 必读完成率和全库完成率；
- 本周计划与实际；
- 下一批文章及预计用时；
- 当前预计完成日；
- 新增文章对计划的影响。
