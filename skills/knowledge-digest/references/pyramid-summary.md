# 金字塔摘要协议

## 思考顺序

先自下而上理解，再自上而下表达：

1. 提取原子信息：事实、数据、作者观点、因果解释、预测、建议和未知项。
2. 按一个主要逻辑关系归组：因果、时间、结构、重要性或立场；不要混用万能维度。
3. 为每组写能够统领组内信息的结论。
4. 检查同层是否重叠、混层、断链或缺少决定性分支。
5. 归纳总判断及其成立条件。

## 工作台速览

工作台索引只保留：

- `一句话结论`：直接回答“这篇内容最值得知道什么”，不超过 120 个中文字符。
- `核心要点`：二至四条，每条一行，同层并共同支撑总判断。
- `价值说明`：对用户关注主题意味着什么，不超过 160 个中文字符。
- `边界`：最重要的不确定性、反方或限制，不超过 120 个中文字符。

## 完整摘要文档

```markdown
# <标题>

## 一句话结论
<总判断与必要条件>

## 核心要点
### 1. <组结论>
- 事实或证据：
- 机制或解释：

### 2. <组结论>
- 事实或证据：
- 机制或解释：

## 这意味着什么
<影响、取舍和可行动方向>

## 边界与不确定性
- <来源局限、争议、反例、未知项>

## 来源信息
- 原标题：
- 来源：
- 作者：
- 发布时间：
- 原文：
- 读取时间：
- digest_id：
- 内容指纹：
```

## 多来源专题

- 先给综合结论，再分为“共同确认”“主要差异”“证据强弱”“尚未确认”。
- 每条关键事实附来源归属。
- 不用多数来源数量代替证据质量。
- 报道同一事件时优先保留事件发生时间，不把文章发布时间当作事件时间。
