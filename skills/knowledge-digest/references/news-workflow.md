# 新闻站点增量追踪工作流

## 兴趣规则

将用户兴趣拆成可执行字段：

| 维度 | 示例 |
|---|---|
| 主题 | AI 产品、基础模型、智能硬件 |
| 实体 | 指定公司、人物、产品或政策机构 |
| 事件类型 | 发布、融资、监管、研究突破、重大故障 |
| 地域和语言 | 中国、全球；中文、英文 |
| 重要性 | 只看重大变化，或允许行业动态 |
| 排除项 | 课程广告、转载、招聘、纯观点、重复快讯 |

用户只给宽泛主题时，先按来源栏目和近期样本提出规则草案。规则必须可被用户查看和修改。

## 发现优先级

1. RSS 或 Atom。
2. 官方 API。
3. 稳定公开栏目及分页。
4. 用户已授权的登录态浏览器。

前三类可用于后台自动任务。登录态浏览器适合用户在场或会话持续有效的运行，不承诺长期
无人值守。

## 增量与去重

- RSS：保存 entry ID、规范化 URL、发布时间和更新时间。
- API：保存官方游标或最近成功时间，并保留安全回看窗口。
- 栏目页：保存最近已见 URL、最近发布时间和最近一页回看。
- 登录态浏览器：保存已见 URL 和可续扫的目录位置。

同一事件的多篇报道可以合并为专题，但必须保留各来源归属；标题相似不能直接判重。

## 相关性筛选

按以下顺序评分：

1. 是否命中排除项；
2. 是否命中主题、实体或事件类型；
3. 是否为来源中的新增内容；
4. 是否包含实质变化，而非重复转载或旧闻改写；
5. 是否达到用户要求的重要性。

低置信度内容进入“待确认”，不要静默永久排除。每篇入选内容保存简短的“入选原因”，每类
过滤内容保存数量和主要原因。

## 每次同步输出

```text
扫描 N 篇
├── 新增 N
│   ├── 与用户相关 N
│   ├── 待确认 N
│   └── 已过滤 N
├── 重复 N
└── 失败 N
```

同时报告来源游标、自动任务状态和下一次计划运行时间。
