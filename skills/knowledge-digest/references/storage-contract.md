# 存储与工作台契约

## 资源结构

使用一个“知识速览”Base，包含三张表：

```text
知识速览 Base
├── 信息源
├── 知识清单
└── 知识摘要
```

完整产物保存到知识库固定目录：

```text
08｜新闻与知识摘要
├── 阅读计划
├── 新闻摘要
├── 知识文章
└── 多来源专题
```

Base 是来源状态、阅读进度和工作台索引的事实源；完整摘要与阅读计划文档是正文事实源。

## 知识摘要表

| 字段 | 类型 | 说明 |
|---|---|---|
| 摘要 ID | 单行文本 | `dig-` 开头，重试时保持不变 |
| 条目 ID | 单行文本 | 知识库文章可关联 `item_id` |
| 来源 ID | 单行文本 | 关联信息源 |
| 标题 | 单行文本 | 原文标题 |
| 信息源 | 单行文本 | 来源名称 |
| 来源类型 | 单选 | 新闻、知识文章、多来源专题 |
| 作者 | 单行文本 | 缺失时留空 |
| 发布时间 | 日期时间 | 缺失时留空 |
| 一句话结论 | 多行文本 | 工作台首屏 |
| 核心要点 | 多行文本 | 每行一条，二至四条 |
| 价值说明 | 多行文本 | 与用户目标或兴趣的关系 |
| 入选原因 | 多行文本 | 新闻为何进入用户兴趣范围 |
| 边界 | 多行文本 | 限制或不确定性 |
| 标签 | 多选 | 主题标签 |
| 原文链接 | URL | 可追溯来源 |
| 完整摘要 | URL | 飞书文档链接 |
| 内容指纹 | 单行文本 | `sha256:` 开头 |
| 状态 | 单选 | 已完成、已更新、待确认、需补充、失败 |
| 读取时间 | 日期时间 | 实际读取正文的时间 |

## 幂等写入

1. 知识条目用来源 ID 和规范化文章 URL 生成 `item_id`。
2. 摘要用来源 ID 和内容指纹生成 `digest_id`。
3. 写入前按对应 ID 精确查询。
4. 内容变化时保留旧摘要并创建新版本；阅读状态仍关联稳定 `item_id`。
5. 文档已创建但 Base 写入失败时，重试沿用原文档和稳定 ID。
6. 只有来源、清单或摘要状态成功写入后才能推进对应游标。

## 工作台接口

工作台使用三个必需环境变量：

- `KNOWLEDGE_BASE_TOKEN`
- `KNOWLEDGE_DIGEST_TABLE_ID`
- `KNOWLEDGE_SOURCE_TABLE_ID`

`KNOWLEDGE_ITEM_TABLE_ID` 为可选扩展，供后续展示逐篇阅读清单。当前工作台先从“信息源”表的
文章总数、已读数量、下一批、计划完成日和阅读计划字段展示知识库进度。

缺少任一必需变量时接口返回 `configured: false`，不能导致招聘工作台整体失败。工作台只读取
和展示，不在浏览器中发现来源、抓取正文或调用模型。
