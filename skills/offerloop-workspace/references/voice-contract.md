# OfferLoop 个人语言画像契约

## 来源优先级

按与目标产物的接近程度使用用户本人内容：

1. 用户亲自写作并确认的同类产物；
2. 真实面试 ASR 或其他自然口语；
3. 用户对 Agent 草稿的实际改写；
4. 多轮自然 Chat；
5. 用户对自己表达风格的抽象描述。

只读取用户主动提供或明确授权的文档。Agent 生成后未经用户改写的内容不是用户语言样本。

## 提取维度

观察句子长短与节奏、开头方式、转折和连接、叙事顺序、观点与例子的距离、具体程度、情绪强度、
自我指称、确定/保留语气，以及用户如何收尾。不要把错字、ASR 错误、无意义口头禅或一时情绪
当成需要模仿的风格。

单条消息只能形成低置信度观察。多份独立样本一致，或用户明确确认后，才写成稳定语言特征。
画像更新遵循 `career-profile` 的 `language-profile-workflow.md`：展示特征、来源和适用范围，
每次只确认一条，确认后写入。口语与书面、不同产物场景分别归纳，不自动泛化。

## 生成顺序

生成自我评价、自我介绍、面试逐字稿或参考回答时：

1. 先完成事实、专业逻辑和岗位要求检查；
2. 读取 `语言表达习惯｜<显示名>` 中已确认语言特征和最接近本产物的样本；新文档尚未建立时才
   兼容读取旧 `用户画像｜<显示名>`；
3. 在不改变事实含义的前提下调整句子节奏、连接方式、叙事顺序和用词；
4. 用“用户是否可能自然说出/写出”复读检查，删除报告腔、模板腔和机械框架提示；
5. 没有足够样本时明确按自然口语生成，不声称“已经模仿用户”。

不要机械复制完整句子，不为了像用户而保留影响清晰度的赘余，也不要把用户在私聊中的敏感内容
迁移到求职产物。

## 持续学习

任何 OfferLoop 业务 Skill 都可以在不打断主任务的情况下观察新样本。出现重复模式，或用户修改
了 Agent 的草稿时，在该轮主要任务结束后最多提出一条语言画像候选更新；用户确认后交给
`career-profile` 更新同一份语言表达习惯文档。未确认候选可写入“待确认与继续观察”，但不得影响生成。
不得每条消息都弹出确认，也不得静默固化新风格。
