# OfferLoop 用户画像前置门禁

## 目的与范围

`career-profile` 是 OfferLoop 完整模式的首次使用入口。先读取 `installation-mode.md` 并运行
`../scripts/install_mode.py`。只有输出为 `full` 时，除 `career-profile` 自身外的下面 8 个
OfferLoop 业务 Skill 才执行本门禁；输出为 `single` 时立即跳过本门禁：

- `job-collection`
- `recruiting-reminder`
- `experience-deepthink`
- `resume-tailor`
- `competency-lab`
- `interview-prep`
- `mock-lab`
- `talk-review`

本门禁不适用于安装器、升级/修复流程和单 Skill 模式，也不适用于 `lark-doc`、`lark-wiki`、PDF 等通用工具
Skill。`career-profile` 自身直接进入建档或校准流程，不递归执行本门禁。

## 执行时机

门禁是上述业务 Skill 的第一项动作。必须在以下动作之前完成：

- 询问该业务 Skill 的输入；
- 读取该业务 Skill 的其他参考文件或用户私人材料；
- 搜索外部资料；
- 运行业务脚本；
- 创建、更新或同步任何业务数据与产物。

先读取 `lark-wiki`、`lark-doc` 和同目录的 `artifact-contract.md`，定位
`02｜用户画像`。只检查其直接子节点中以下标题，并兼容旧文档：

- `岗位选择偏好｜<显示名>`；
- `个人性格探索｜<显示名>`；
- `语言表达习惯｜<显示名>`；
- 旧 `用户画像｜<显示名>`。

1. 同一显示名零个候选：状态为 `missing`。
2. 每种标题最多一个时，读取已有文档的完整正文并合并判定；三份新文档同时存在是正常结构，
   不属于多匹配。
3. 同一显示名、同一种标题出现多个候选时，只列标题与 URL，让用户选择；不得自行选“最新”。
4. 无法唯一确定显示名时，只列显示名候选让用户选择，不读取无关用户正文。

可将正文传给 `../scripts/profile_gate.py` 做确定性判定。脚本只分析传入的 Markdown，不访问
飞书、不保存正文，也不输出用户的具体画像值。

## 空画像判定

全部候选文档都符合以下情况时视为 `empty`，不得启动原业务 Skill：

- 文档缺失、正文为空或只有空白；
- 只有文档标题、章节标题或 Markdown 骨架；
- 只有空字段、占位符或模板说明，例如“待补充”“未知”“未填写”“无”“N/A”“-”“[]”；
- 只有 `incomplete` 状态，没有任何用户确认过的真实信息；
- 只有“未确认推断：不得写入正式画像”等规则文字。

只要至少存在一条用户明确提供并已确认的有效认识，状态就是 `ready`。有效认识可以是用户如何
理解自己、当前求职方向、现实条件、教育/职能背景、岗位迁移判断或已确认语言特征。画像可以
继续标记为 `incomplete`；不要求用户首次就把所有部分填完。

## 未通过时的交互

状态为 `missing` 或 `empty` 时：

1. 暂停原业务 Skill，不执行其提问、读取、搜索、脚本或写入流程。
2. 用一句话说明需要先建立最小可用的求职画像，并切换到 `career-profile`。
3. 一次只问一个高信息量问题，不发送整张表格或一组问卷。已知信息不重复询问，用户可以跳过
   私人问题。
4. 每得到一条用户明确回答并确认的信息，立即自动创建或更新对应的
   `岗位选择偏好｜<显示名>`、`个人性格探索｜<显示名>` 或 `语言表达习惯｜<显示名>`，保存为
   `incomplete`；不要等完整深访结束才保存。旧 `用户画像｜<显示名>` 只作迁移来源，不再新建。
5. 如果画像文档缺失且无法从当前飞书身份唯一确定显示名，先单独询问用户希望使用的显示名；
   否则个人性格探索固定询问“如果暂时不用从‘求职者’的角度介绍自己，你觉得自己是一个什么样
   的人？”，不从岗位表单或焦虑事件开始。来源为 `job-collection` 时改走岗位选择偏好固定流程。
6. 用户暂停时保留现有内容和待补问题。保存失败时在 Chat 中交付完整 Markdown，不声称已写入。

写入第一条有效确认信息后，全局门禁即可通过。保留用户原始请求；用户愿意继续时返回原业务 Skill，
再执行该 Skill 自己的材料门禁和输入要求。用户没有表示继续时，不在同一轮擅自启动原任务。

`job-collection` 另有更严格的专用门禁：必须存在已完成且无待补节点的
`岗位选择偏好｜<显示名>`。全局状态为 `ready` 不能替代该专用门禁。

## 已通过时

状态为 `ready` 时不打断用户，也不要求补全画像。继续原业务 Skill，并只在当前任务确实需要某个
缺失字段时按该 Skill 的规则追问。生成用户口吻的内容时同时读取 `voice-contract.md`。后续发现
的自我认识、迁移边界或语言画像候选更新仍须遵循 `career-profile`：展示来源与影响，用户确认后
更新，不把单次表现直接固化为稳定结论。
