# OfferLoop 使用指南与目录契约

## 首页定位

首页固定为 `00｜OfferLoop 使用指南`，服务于新手指引、功能说明和导航，不承担实时业务数据
展示。第一操作入口必须是首页中的工作台按钮，不再为工作台单独创建知识库节点。工作台负责
查看实时数据；三张求职业务 Base 是招聘数据源，“知识速览” Base 是信息源、游标和摘要
索引的数据源。

首页应包含：

- 从这里开始：工作台链接与一句职责说明。
- 第一次使用清单与日常流程。
- 按“求职基础能力 / 求职训练能力 / 知识输入能力”介绍十一个 Skill，每项包含用途和自然语言示例。
- 核心功能和数据位置说明。
- 可对当前 Agent 使用的自然语言命令；未实现能力须标注“即将支持”。
- 数据不重复维护原则与常见问题。

## 固定目录

```text
00｜OfferLoop 使用指南
01｜当前简历
02｜简历深挖
03｜面试准备文档
04｜面试复盘 / ASR待复盘、已完成复盘
05｜产品 Sense
06｜模拟面试
07｜题库 / 待学习题库、已学会题库
08｜新闻与知识摘要 / 新闻摘要、知识文章、多来源专题
```

## 数据与维护边界

- 求职企业清单、求职进展和笔面试中心不可复制到知识库文档，也不为它们创建目录；首页只登记
  其入口与用途。
- `job-collection` 只更新招聘信息；`recruiting-reminder` 只更新笔面试中心和求职进展。
- 面试准备、复盘和训练文档必须按 `artifact-contract.md` 命名并包含 `run_id`。
- 知识摘要按 `knowledge-digest/references/storage-contract.md` 命名和去重，不使用面试
  训练 `run_id`。
- 不按公司新建顶级目录；所有新增材料必须归入现有目录。
- 自动化不得改写首页的说明文字，除非用户明确要求重构首页。
