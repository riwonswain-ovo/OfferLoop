# OfferLoop 首页与目录契约（v5）

首页固定为 `00｜OfferLoop 使用指南`，只负责导航、数据边界、三条闭环和 9 个长期 Skill 的说明。旧工作台入口已经退役，不得继续展示或作为就绪条件。

首页必须说明首次使用顺序：其他 OfferLoop 业务 Skill 先检查 `02｜用户画像`；缺失、空白或
只有占位内容时转入 `career-profile`，通过一次一个问题的 Chat 建档。第一条确认信息保存后即可
继续原任务，不要求一次完成整份画像。

## 固定目录

```text
00｜OfferLoop 使用指南
01｜核心求职数据
  ├── 企业清单（原 Base 的知识库快捷节点）
  ├── 求职进展（原 Base 的知识库快捷节点）
  └── 笔面试中心（原 Base 的知识库快捷节点）
02｜用户画像
03｜定制简历
04｜经历深挖
05｜岗位能力与训练
  ├── 岗位能力画像
  ├── 专项训练
  │   ├── 方法论训练
  │   └── 行业认知训练
  ├── 每日三题
  └── 周报
06｜面试准备
07｜模拟面试
08｜真实面试复盘
  ├── ASR 待复盘
  └── 已完成复盘
```

## 数据边界

- 三张 Base 必须沿用原 token 与记录；知识库节点只是指向同一对象的入口，不得复制 Base。
- Base 是求职事实真源；知识库保存用户画像与生成产物。
- 首页不得复制业务记录。
- 产物必须按 `artifact-contract.md` 的目录、标题与 `completed` / `incomplete` 状态保存。
- `run_id` 只存在于内部元数据，不进入文档标题。
- 自动化只能更新受控入口块，不能覆盖用户自行维护的正文。
