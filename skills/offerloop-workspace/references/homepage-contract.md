# OfferLoop 使用指南与目录契约

## 首页定位

首页固定为 `00｜OfferLoop 使用指南`，负责新手指引、知识库导航和三张 Base 入口，不承担实时
业务数据展示。工作台入口是可选块：配置 `workbench_url` 时展示，未配置时明确说明不影响核心
能力，不能把它标为缺失或失败。

首页应包含：

- 三张业务 Base 和训练目录的第一操作入口。
- 第一次使用清单。
- 十一个 Skill 的用途与自然语言示例。
- 工作台的可选状态说明。
- 数据不重复维护原则与常见问题。

## 固定目录

```text
00｜OfferLoop 使用指南
01｜核心求职数据
  ├── 企业清单（Base）
  ├── 求职进展（Base）
  └── 笔面试中心（Base）
02｜当前简历
03｜简历深挖
04｜面试准备
05｜面试复盘 / ASR 待复盘、已完成复盘
06｜产品 Sense
07｜模拟面试
```

## 数据与维护边界

- 三张 Base 作为既有 Base 对象纳入知识库，不复制字段、记录或表结构。
- Base 是业务真源；知识库节点、首页和工作台都只是入口或投影。
- `job-collection` 只更新招聘信息；`recruiting-reminder` 只更新笔面试中心、求职进展和日历。
- 面试准备、复盘和训练文档必须按 `artifact-contract.md` 命名并包含 `run_id`。
- 不按公司新建顶级目录；所有新增材料必须归入现有目录。
- 自动化不得改写首页说明文字；工作台部署后只更新受控的可选入口块。
