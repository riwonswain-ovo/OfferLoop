# OfferLoop 使用指南

OfferLoop 把招聘信息、真实投递、笔试面试、当前简历和训练产物组织在同一个私有知识库中。
三张业务 Base 是唯一事实源；知识库负责统一导航和长期材料沉淀。

## 从这里开始

1. 打开“01｜核心求职数据”中的企业清单、求职进展或笔面试中心。
2. 打开“02｜当前简历”或对应训练目录查看 Markdown 产物。
3. 直接对 Agent 描述目标，它会调用对应 OfferLoop Skill。

## 第一次使用

1. 运行 `offerloop-setup`，完成飞书身份、三张 Base 和私有知识库初始化。
2. 在企业清单中筛选岗位，将真实投递的记录改为“已投递”。
3. 在求职进展中补充岗位、JD、投递简历版本和投递日期。
4. 启用邮件提醒后，确认识别结果和日历方案，再写入笔面试中心与个人日历。
5. 每次训练结束后，在固定目录查看 Markdown 飞书文档；经历深挖会持续更新同一经历与方向的
   专属文档。

## 日常流程

1. 用企业清单持续收集、筛选岗位。
2. 在求职进展中维护真实投递及所用简历版本。
3. 在笔面试中心确认待办，并按需同步个人日历。
4. 面试前运行准备或模拟训练，面试后导入 ASR 复盘。
5. 回到知识库固定目录复用每次训练生成的 Markdown 材料。

## OfferLoop 的 12 个 Skill

### 核心与业务能力

| Skill | 负责什么 | 可以这样说 |
| --- | --- | --- |
| `offerloop-setup`｜安装与配置 | 初始化知识库、三张 Base、飞书授权和公共配置 | “检查 OfferLoop 是否已经完成初始化。” |
| `offerloop-workspace`｜求职知识库 | 维护知识库、三张 Base 入口和训练产物 | “检查我的 OfferLoop 知识库是否完整。” |
| `job-collection`｜招聘信息同步 | 从指定信息源收集岗位并整理到企业清单 | “同步我的招聘信息源。” |
| `recruiting-reminder`｜笔试面试提醒 | 从邮件识别安排，并在确认后同步笔面试中心和日历 | “检查最近 7 天的笔试面试邮件，先不要写入。” |
| `offerloop-workbench`｜可选工作台 | 按需部署可视化工作台和 OAuth | “为我的 OfferLoop 搭建飞书工作台。” |
| `offerloop-agent`｜可选 Codex Agent | 在已有工作台中加装本机 Codex 右侧栏 | “把 Codex 接入我现有的 OfferLoop 工作台。” |

### 求职训练能力

| Skill | 负责什么 | 可以这样说 |
| --- | --- | --- |
| `experience-deepthink`｜经历深挖 | 直接从 Chat 中的经历讲述和岗位方向开始，持续维护口述稿、事实边界和故事素材 | “我想讲一段竞赛经历，用来准备财务分析岗，请开始深挖。” |
| `resume-tailor`｜Resume Tailor | 按岗位组合用户选定的真实经历，补齐固定信息并生成一页 PDF 简历 | “根据这个岗位和我选的三段经历，制作一页 PDF 简历。” |
| `pm-sense`｜产品思维训练 | 训练产品与场景题，完善口语回答 | “让我先回答一道产品场景题，再帮我完善。” |
| `interview-prep`｜面试准备 | 结合 JD、投递简历和素材生成针对性准备文档 | “根据下一场面试和实际投递简历帮我准备。” |
| `mock-lab`｜模拟面试 | 按真实节奏一题一答，结束后统一点评 | “用刚才的准备文档模拟面试。” |
| `talk-review`｜真实面试复盘 | 根据 ASR 或转写还原问答并生成改进方案 | “根据这份 ASR 复盘刚结束的面试。” |

## 核心功能与数据位置

| 内容 | 入口 | 用途 |

| 企业清单 | {{target_base_url}} | 招聘信息事实源与投递状态 |

## 常见问题

### 没有工作台还能使用 OfferLoop 吗？

可以。知识库、三张 Base、日历和训练文档都是独立真源；工作台只是可选聚合界面。

### 数据应该在哪里修改？

招聘信息在企业清单维护，真实申请在求职进展维护，笔试面试安排在笔面试中心维护。

### Skill 更新会覆盖我的材料吗？

不会。当前简历、训练文档、ASR 和业务数据留在你的飞书空间；Skill 目录只保存流程和定位信息。
