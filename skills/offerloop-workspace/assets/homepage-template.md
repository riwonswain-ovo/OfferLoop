# OfferLoop 使用指南

OfferLoop 把招聘信息、真实投递、笔试面试和求职材料组织在同一个私有求职空间中。
三张求职业务 Base 保存招聘数据；本首页只负责说明和导航，不复制实时业务数据。

## 从这里开始

[打开 OfferLoop 招聘工作台]({{workbench_url}})

工作台集中展示招聘企业、求职进展和笔面试安排。需要编辑完整记录时，从工作台进入对应 Base。

## 第一次使用

1. 运行 `offerloop-setup`，选择当前要启用的能力并完成预检。
2. 在企业清单中筛选岗位，将真实投递的记录改为“已投递”。
3. 在求职进展中手动补充投递岗位、岗位 JD、投递简历版本和投递日期。
4. 启用邮件提醒后，确认识别结果和日历方案，再写入笔面试中心与个人日历。

## OfferLoop 的 9 个 Skill

### 求职基础能力

| Skill | 负责什么 | 可以这样说 |
| --- | --- | --- |
| `offerloop-setup`｜安装与配置 | 首次配置、环境检查、飞书授权和完整部署 | “介绍 OfferLoop 的九个 Skill，并帮我完成第一次使用。” |
| `offerloop-workspace`｜求职空间 | 管理知识库、工作台和材料目录 | “检查我的 OfferLoop 求职空间是否完整。” |
| `job-collection`｜招聘信息同步 | 从指定信息源收集岗位并整理到企业清单 | “同步我的招聘信息源。” |
| `recruiting-reminder`｜笔试面试提醒 | 从邮件识别安排，并在确认后同步笔面试中心和日历 | “检查最近 7 天的笔试面试邮件，先不要写入。” |

### 求职训练能力

| Skill | 负责什么 | 可以这样说 |
| --- | --- | --- |
| `resume-deepthink`｜简历深挖 | 连续追问真实经历，生成简历表达和面试素材 | “追问深挖我简历中的一段实习经历。” |
| `pm-sense`｜产品思维训练 | 训练产品与场景题，完善口语回答 | “让我先回答一道产品场景题，再帮我完善。” |
| `interview-prep`｜面试准备 | 结合 JD、投递简历和素材生成针对性准备文档 | “根据下一场面试和实际投递简历帮我准备。” |
| `mock-lab`｜模拟面试 | 按真实节奏一题一答，结束后统一点评 | “用刚才的准备文档模拟面试。” |
| `talk-review`｜真实面试复盘 | 根据 ASR 或转写还原问答并生成改进方案 | “根据这份 ASR 复盘刚结束的面试。” |

## 日常流程

1. 用 `job-collection` 同步招聘信息。
2. 在工作台查看企业清单，并维护真实投递状态。
3. 用 `recruiting-reminder` 整理笔试面试邮件。
4. 用 `resume-deepthink` 或 `pm-sense` 完成训练并保存文档。
5. 收到面试后用 `interview-prep` 准备，再用 `mock-lab` 练习。
6. 面试结束后用 `talk-review` 复盘 ASR。

## 常见问题

### 为什么首页不展示实时表格和日历？

实时数据统一由招聘工作台和三张 Base 展示，避免首页产生副本、过期内容或重复维护。

### 数据应该在哪里修改？

招聘信息在求职企业清单维护，真实申请在求职进展维护，笔试面试安排在笔面试中心维护。

### Skill 更新会覆盖我的材料吗？

不会。当前简历、训练文档、ASR 和业务数据留在你的飞书空间；Skill 目录只保存流程、
资源入口和必要的本地定位信息。
