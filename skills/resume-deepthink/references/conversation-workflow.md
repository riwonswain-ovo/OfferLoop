## 文档身份与岗位路由

开始前确认：

- 当前简历版本；
- 具体经历名称；
- 完整目标岗位和投递方向；
- 主岗位 playbook；
- 可选的一个辅助岗位 playbook；
- 是否存在相同三元组的未完成文档。

文档身份三元组是 `(简历版本, 经历名称, 目标岗位/投递方向)`。只有三项完全一致才可续写。
同一简历和经历面向产品、运营等不同岗位时，分别启动新运行并生成不同文档。

岗位名称不明确或属于复合岗位时，询问：

> 这次你希望面试官重点看到哪类能力？请确认一个主岗位；如果是复合岗位，可以再确认一个
> 辅助岗位。

常见名称按以下方式路由：

- 产品经理、AI 产品、策略产品、产品运营中的产品主方向 → 产品；
- 用户运营、内容运营、活动运营、增长运营、策略运营 → 运营；
- 项目管理、项目经理、项目运营、项目管理办公室 → PMO；
- 商分、商业分析、经营分析、战略分析 → 商业分析；
- 数分、数据分析、BI 分析 → 数据分析；
- 算法工程、机器学习、推荐/搜索/NLP/CV 算法 → 算法；
- Web 前端、客户端前端、小程序前端 → 前端；
- 服务端、后端开发、Java/Go/Python 后端 → 后端；
- 功能测试、测试开发、质量工程、QA → 测试。

职位名称与实际工作内容冲突时，以这次目标岗位希望验证的能力为主，并让用户确认，不能只按
简历上的实习职位名称路由。

## 对话节奏

- 第一个问题让用户自然、完整地介绍经历，不先给 STAR 或答案。
- 每轮默认只提出一个问题，顺着用户刚才的回答追问，不同时抛出多个独立问题。
- 用户回答后，先简短复述当前理解，再指出一个最关键缺口并继续。
- 不一次展示完整题库，不在信息收集阶段反复输出整篇文档。
- 每完成背景、目标、方案或结果中的一个主题，生成简短阶段草稿让用户确认。
- 用户确认的是事实和口径，不要求逐字确认每个措辞。
- 事实尚未确认前，不替用户生成“标准经历”；可以解释问题、提供回忆脚手架，但不得让提示
  反向污染事实。

## 线索钻取与发散

把用户提到的关键动作、决策、难点和结果视为独立线索。优先选择与目标岗位、目标 JD 和个人
区分度最相关的线索，沿下列阶梯纵向钻取；一条高价值线索尚未达到当前所需深度时，不因题库
顺序轻易换题。

### 五层钻取阶梯

1. **根因层**：区分直接触发因素与更上层根因，确认依据来自数据、用户/业务反馈、战略要求、
   技术约束、合规风险或其他真实来源；追问“不做会怎样”和为什么当时要做。
2. **归属层**：区分团队、协作方和用户本人，确认本人执行步骤、关键判断、决策权和可验收
   交付。可用“没有你的参与，结果会在哪些方面不同”检验边际贡献，但不得诱导用户宣称自己
   不可替代。
3. **落地层**：追问实施链路、关键卡点、异常、协作接口、分歧和解决动作，确认选择依据及
   验证方式；技术岗位必须保留岗位 playbook 要求的专业深度。
4. **价值层**：按岗位 playbook 确认业务、用户或专业价值。量化结果必须追到指标定义、基线、
   最终值、变化类型、样本/周期、测量方法和归因边界；没有直接业务指标时，使用真实可验收的
   质量、稳定性、风险、效率或交付结果，不强迫用户编造数字。
5. **复盘层**：追问未达预期部分、原因判断、当时信息条件下的权衡、重来会改变的判断，以及
   继续、缩小、回滚或停止的条件。

不是每条线索都机械走完五层。只追与该线索和岗位相关的层级，但关键贡献、关键决策和关键
难点必须分别达到足以回答面试官继续追问的深度。内部可以记录线索及当前层级，用于选择下一
题；不得把该记录、诊断或成熟度标签写入最终 Markdown。

### 钻取与发散切换

默认继续钻取用户上一句中的关键线索。仅在以下情况切换为发散：

- 用户卡壳、重复、明确不知道或无法回忆；
- 当前线索已经达到所需的复盘或事实深度；
- 发现会影响结论的重要岗位盲区；
- 同一线索连续追问三至四轮，需要换气或改用另一回忆入口。

发散时一次提供二至三个互相区分的思考角度让用户选择，不替用户选择，也不把选项写成已确认
事实。常用压力测试按岗位适配后选择，不要求每项都问：

- 投入的人力、时间、系统或机会成本是否与收益匹配；
- 价值是一次性结果，还是形成可持续机制、资产或复用能力；
- 是否存在负向影响、风险转移、体验损失或资源挤占；
- 为什么该事项优先于其他候选事项，资源减半时保留什么；
- 当前指标与上层用户、业务、质量或公司目标有什么关系。

## 项目全景介绍

按以下顺序收集，生成时再把 1 分钟和 3 分钟版本放到最前。

### 1. 自由讲述

询问：

> 请先像真实面试一样完整介绍这段经历。暂时不用套模板，重点讲清为什么做、你的职责、
> 怎么做以及结果。

从回答中识别背景、目标、方案、结果和个人贡献的缺口，并结合岗位 playbook 选择下一题。

### 2. 背景

追到岗位 playbook 定义的事实依据和数据，包括范围、口径、基线、来源和结论。再让用户把
背景归纳成二至三个核心问题，每个问题由前述数据或事实支撑。

完成标准：

- 项目为什么发生；
- 原有状态或基线是什么；
- 核心问题有数据或事实依据；
- 用户亲历事实与外部材料没有混写。

### 3. 目标

按岗位 playbook 追问业务/用户/专业目标、成功指标和个人交付目标。

完成标准：

- 团队目标与个人目标分开；
- 成功标准明确；
- 多目标冲突时的优先级可解释。

### 4. 方案

从整体方案逐层收缩到本人工作，追问输入、处理、输出、关键选择、协作接口、异常处理和验证
方式。专业细节以岗位 playbook 为准。

完成标准：

- 能讲清完整链路；
- 能明确本人负责边界和交付物；
- 关键选择有依据；
- 能说明如何验证方案。

### 5. 结果

分别追问项目整体结果、负责模块结果和个人产出。量化指标必须确认定义、基线、最终值、变化
类型、样本/周期、测量方法和归因范围。根据岗位和事实，对高价值线索补充投入产出、持续性、
负向影响、机会成本及其与上层目标的关系；不适用时不强行追问。

完成标准：

- 不混用绝对值、百分点和相对提升；
- 团队结果不冒充个人结果；
- 不同章节数字一致；
- 没有业务结果时有可验收的专业或交付结果。

### 6. 压缩介绍

详细内容确认后，先生成 3 分钟版本，再压缩为 1 分钟版本。两版均围绕目标岗位选取信息：

- 3 分钟版保留关键方法、难点、个人贡献和结果；
- 1 分钟版只保留最能证明目标岗位能力的主线；
- 两版不得引入详细章节中未确认的新事实。

## 项目细节深挖

固定覆盖六类：

1. 方案实现细节类；
2. 异常问题归因类；
3. 决策判断权衡类；
4. 项目推进经历类；
5. 产品价值拔高类；
6. 个人规划认知类。

每类至少一题、最多四题。默认两题；根据岗位 playbook 和项目复杂度扩展或缩减。问题必须
来自目标岗位能力、项目事实或目标 JD，不平均凑数。

真实经历题按以下顺序：

1. 先让用户回答；
2. 追问缺失的背景、动作、依据和结果；
3. 使用五层阶梯继续钻取其中最关键的缺口；
4. 生成参考回答；
5. 让用户校正事实；
6. 再进入下一题。

假设分析题可先让用户表达判断；用户没有思路时，基于题设生成示范答案，但不得将推演写成
真实经历。

## 信息不足与暂停

用户答不上真实经历题时：

1. 缩小到用户实际参与的部分；
2. 先换一种开放问法或提供时间顺序、角色分工、材料类型等回忆坐标；
3. 仍然卡壳时，提供二至三个可能方向作为脚手架，并明确这些只是提示、尚未成为事实；
4. 仍无法确认时生成带 `[待补充：具体事实]` 的回答结构。

普通暂停只说明当前阶段、已确认主题和下次要问的问题，不生成正式文档。恢复时必须先核对
文档身份三元组，防止续写到另一目标岗位。

正常完成需同时满足：

- 背景、目标、方案和结果达到各自完成标准；
- 关键贡献、关键决策和关键难点已达到岗位所需深度，且至少完成一条真实复盘；
- 六类问题已有足够事实生成非空参考回答。

用户明确提前结束时按不完整产物处理，不为满足完成条件而补造事实。

## 成稿检查

生成最终 Markdown 前检查：

- 只存在两个规定的一级部分；
- 岗位语言与主岗位 playbook 一致；
- 1 分钟、3 分钟和详细章节事实一致；
- 每类问题一至四题，每题有参考回答；
- 关键贡献没有被反事实问题夸大为“不可替代”，业务价值也没有压过岗位所需的专业深度；
- 发散选项、内部线索层级和未确认假设没有混入事实；
- 另一目标岗位文档中的判断或答案没有被直接复用；
- 标题能够识别简历版本、经历名称和目标岗位/方向。
