# OfferLoop 首次使用欢迎

## 目标

首次安装或用户要求“介绍 OfferLoop / 十一个 Skill”时，先建立完整能力地图，再选择当前目标。
不要只列技术名称，也不要在介绍前运行线上检查。

## 欢迎顺序

1. 明确十一个 Skill 已安装，但“安装完成”不等于飞书或邮箱已经配置。
2. 说明私有知识库和三张 Base 是 OfferLoop 完成初始化后的必备空间。
3. 说明飞书工作台是可选体验，未部署不影响任何业务或训练 Skill。
4. 按以下两组介绍十一个 Skill，并给出自然语言示例。
5. 展示两个常用闭环和隐私边界。
6. 请用户选择当前目标，再进入离线预检。

## 十一个 Skill

### 核心、业务与可选体验

| Skill | 用途 | 可以这样说 |
| --- | --- | --- |
| `offerloop-setup`｜安装与配置 | 初始化知识库、三张 Base、飞书身份和公共配置 | “检查 OfferLoop 是否完成初始化。” |
| `offerloop-workspace`｜求职知识库 | 维护必需的知识库、Base 节点和训练产物 | “检查我的 OfferLoop 知识库是否完整。” |
| `job-collection`｜招聘信息同步 | 从指定来源同步岗位到企业清单 | “同步我的招聘信息源。” |
| `recruiting-reminder`｜笔试面试提醒 | 从招聘邮件识别安排并写入笔面试中心和日历 | “检查最近 7 天的笔试面试邮件，先不要写入。” |
| `offerloop-workbench`｜可选工作台 | 按需部署妙搭可视化工作台和 OAuth | “为我的 OfferLoop 搭建飞书工作台。” |
| `offerloop-agent`｜可选 Codex Agent | 在已有工作台中加装本机 Codex 智能助手右侧栏 | “把 Codex 接入我现有的 OfferLoop 工作台。” |

### 求职训练能力

| Skill | 用途 | 可以这样说 |
| --- | --- | --- |
| `resume-deepthink`｜简历深挖 | 连续追问真实经历，生成简历表达和面试素材 | “追问深挖我简历中的一段实习经历。” |
| `pm-sense`｜产品思维训练 | 训练产品与场景题并沉淀 Markdown 产物 | “让我先回答一道产品场景题，再帮我完善。” |
| `interview-prep`｜面试准备 | 结合 JD、简历和素材生成准备文档 | “根据下一场面试和实际投递简历帮我准备。” |
| `mock-lab`｜模拟面试 | 按真实节奏一题一答，结束后统一点评 | “用刚才的准备文档模拟面试。” |
| `talk-review`｜真实面试复盘 | 根据 ASR 还原问答并生成改进方案 | “根据这份 ASR 复盘刚结束的面试。” |

## 常用闭环

- 招聘信息同步 → 真实投递 → 邮件识别 → 笔试面试安排。
- 简历深挖 / 产品思维 → 面试准备 → 模拟面试 → 真实面试复盘。

所有核心数据与训练产物都进入私有知识库；工作台只做可选聚合展示。

## 隐私说明

> 安装只添加了 Skill；尚未读取你的飞书、邮箱或简历，也没有创建或修改线上数据。接下来先做
> 离线只读检查；创建知识库、Base、工作台或任何业务写入都会另行说明并获得确认。

## 首次选择

介绍结束后只问当前想推进哪一项，不询问目标岗位：

1. 初始化或检查核心求职知识库 → `workspace`
2. 找到和同步招聘岗位 → `collection`
3. 整理投递、笔试和面试安排 → `reminder`
4. 深挖简历、训练产品思维或准备面试 → `coaching`
5. 额外搭建飞书工作台 → `workbench`
6. 给已有工作台加装 Codex 右侧栏 → `agent`
7. 搭建包含工作台的完整 OfferLoop → `full`

任何选择都会检查必需知识库和三张 Base；第 5、7 项可部署工作台，第 6 项只复用已有工作台。
