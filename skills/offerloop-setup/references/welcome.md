# OfferLoop 首次使用欢迎

## 目标

首次安装或用户要求“介绍 OfferLoop / 十一个 Skill”时，先建立完整能力地图，再选择当前要启用的
一项能力。不要只列技术名称，也不要在介绍前运行线上检查。

## 欢迎顺序

1. 明确十一个 Skill 已安装，但“安装完成”不等于飞书、邮箱或工作台已经配置。
2. 告诉用户不必记住 Skill 名称，日常描述目标即可自动路由。
3. 按以下三组完整介绍十一个 Skill。每项同时给出用途和一句自然语言示例。
4. 展示三个常用闭环。
5. 说明隐私边界。
6. 请用户从六个日常目标中选择一个，再进入对应离线预检。

## 十一个 Skill

### 求职基础能力

| Skill | 用途 | 可以这样说 |
| --- | --- | --- |
| `offerloop-setup`｜安装与配置 | 首次配置、环境检查、飞书授权和完整部署 | “检查一下 OfferLoop 是否配置完整。” |
| `offerloop-workspace`｜求职空间 | 管理飞书知识库、招聘工作台和材料目录 | “检查我的 OfferLoop 求职空间是否完整。” |
| `job-collection`｜招聘信息同步 | 从用户指定的信息源收集岗位并整理到企业清单 | “同步我的招聘信息源。” |
| `recruiting-reminder`｜笔试面试提醒 | 从招聘邮件识别安排，并在确认后同步笔面试中心和日历 | “检查最近 7 天的笔试面试邮件，先不要写入。” |

### 求职训练能力

| Skill | 用途 | 可以这样说 |
| --- | --- | --- |
| `resume-deepthink`｜简历深挖 | 连续追问真实经历，生成简历表达和面试素材 | “追问深挖我简历中的一段实习经历。” |
| `pm-sense`｜产品思维训练 | 训练产品与场景题，完善口语回答并沉淀素材 | “让我先回答一道产品场景题，再帮我完善。” |
| `interview-prep`｜面试准备 | 结合 JD、投递简历和素材生成针对性准备文档 | “根据下一场面试和实际投递简历帮我准备。” |
| `mock-lab`｜模拟面试 | 按真实节奏一题一答，结束后统一点评 | “用刚才的准备文档模拟面试。” |
| `talk-review`｜真实面试复盘 | 根据 ASR 或转写还原问答并生成改进方案 | “根据这份 ASR 复盘刚结束的面试。” |
| `interview-question-bank`｜面试题库 | 管理待学习和已学会题目，统一接收训练候选题 | “把我确认的题加入待学习题库。” |

### 知识输入能力

| Skill | 用途 | 可以这样说 |
| --- | --- | --- |
| `knowledge-digest`｜知识速览 | 梳理知识库阅读计划，追踪兴趣范围内的新增新闻 | “帮我读完这个知识库。” |

## 常用闭环

- 招聘信息同步 → 真实投递 → 邮件识别 → 笔试面试安排。
- 简历深挖 / 产品思维 → 面试准备 → 模拟面试 → 真实面试复盘 → 面试题库持续积累。
- 知识库盘点 → 阅读计划与进度；新闻兴趣规则 → 增量发现与金字塔摘要。

不要声称 `mock-interview` 属于 OfferLoop，也不要把央国企结构化面试专项列为已支持能力。

## 隐私说明

使用以下表述，不把安装误报为线上就绪：

> 安装只添加了 Skill；尚未读取你的飞书、邮箱或简历，也没有创建或修改线上数据。接下来先做
> 离线只读检查；任何线上读取、授权或写入都会另行说明。

## 首次选择

介绍结束后只问当前想推进哪一项，不询问目标岗位：

1. 找到和同步招聘岗位 → `collection`
2. 整理投递、笔试和面试安排 → `reminder`
3. 打开或整理飞书求职空间 → `workspace`
4. 深挖简历、训练产品思维或准备面试 → `coaching`
5. 订阅新闻或知识来源并自动摘要 → `knowledge`
6. 搭建完整 OfferLoop → `full`

用户不确定时，解释六项所需条件并让其选择；不要读取私人材料来猜。选择后再按 `SKILL.md`
运行对应离线预检。用户只选一项时，不要求配置其他能力。
