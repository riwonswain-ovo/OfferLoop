# 求职进展 schema v6

本契约是完整安装、已有 Base 接管和在线验收时的唯一结构依据。简历选择不持久化到业务 Base。

## 核心字段

| 字段 | 类型 | 规则 |
|---|---|---|
| 求职记录 | Formula | 公司与投递岗位的可读组合标题 |
| 进展状态 | SingleSelect | 当前状态唯一真源；使用下方固定选项 |
| 最近完成节点 | SingleSelect | 只在用户确认完成或可靠事件证明完成后推进 |
| 公司 | Text | 来源同步可刷新 |
| 投递岗位 | Text | 用户维护，来源同步不得覆盖 |
| 岗位 JD | Text | 用户维护 |
| 投递日期 | DateTime | 首次投递日期；无法可靠恢复时为空 |
| 公告链接 | Text | 与企业清单逐值同步 |
| 投递链接 | Text | 与企业清单逐值同步 |
| 企业清单 record_id | Text | 可重复父级关联键 |
| 投递记录 ID | Text | 每次岗位投递的唯一技术键 |

`进展状态` 固定选项：

```text
待反馈
待笔试
待面试
待群面
待一面
待二面
待三面
待 HR 面
待 OC
Offer
未通过
主动放弃
岗位关闭
状态待确认
```

`最近完成节点` 固定选项：

```text
投递完成
笔试完成
面试完成
群面完成
一面完成
二面完成
三面完成
HR面完成
```

## schema v5 兼容字段

已有 Base 可以暂时保留 `当前阶段`、`下一环节`、`流程结果`、`当前状态`。它们只用于迁移与旧
客户端兼容，不作为判断、筛选或自动推进的真源。新逻辑必须优先读取 `进展状态`；只有该字段
为空时才能从兼容字段迁移，无法可靠判断时写 `状态待确认`。

迁移完成且所有写入方均通过 schema v6 验收前，不删除兼容字段。

## 视图

- 全部求职记录：不限制状态。
- 已完成节点视图：按 `最近完成节点` 筛选，并限制 `进展状态` 为进行中的待办状态。
- Offer、已结束、状态待确认：只按 `进展状态` 筛选。
- 所有受管视图按 `投递日期 desc, 公司 asc` 排序。

## 新建默认值

企业记录第一次变为 `已投递` 时创建默认进展：

```text
进展状态 = 待反馈
最近完成节点 = 投递完成
当前阶段 = 已投递（兼容）
下一环节 = 待反馈（兼容）
流程结果 = 进行中（兼容）
投递岗位 = 空
岗位 JD = 空
```
