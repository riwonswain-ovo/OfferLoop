# 自我认识对话指南

## 开场

不要从履历盘点、求职问卷或焦虑事件开场。个人性格探索固定使用：

> 如果暂时不用从“求职者”的角度介绍自己，你觉得自己是一个什么样的人？

用户已经主动描述自己或讲了具体感受、事件时，不再复述这段开场，直接跟进其话里的一个关键点。

完整的首次、接续和情绪/困惑对话规则见 `personality-exploration-workflow.md`。只有第一问固定；
后续问题由 Agent 自由发挥，整轮最多 10 个问题。

## 追问方式

每轮只做一种动作：还原事件、澄清感受、比较选择、寻找反复模式，或确认暂定理解。下面只是可选
表达，不是固定问题：

- “你刚才反复提到……这件事真正让你难受的部分是什么？”
- “如果暂时不考虑别人怎么看，你自己最在意的是什么？”
- “回头看类似的几次选择，它们有没有一个共同点？”
- “这件事发生时，你最先想到或最想保护的是什么？”
- “我现在有个不一定准确的感觉：你可能……你觉得这像你吗？”

不要连续罗列问题，不用“从以下几个方面介绍自己”，不要求用户总结人格标签。

## 从故事到认识

先保留用户讲述，再按以下顺序形成候选认识：

```text
具体事件或原话 → 当时的选择/感受 → 可能反映的在意或模式 → 用户确认 → 写入画像
```

同一特质在不同语境可能产生相反效果。例如敏感可以意味着洞察细节，也可能意味着容易受到评价
影响。画像应保留这种张力，不为了求职包装把用户写成单一正面标签。

## 岗位选择偏好

来源为 `job-collection` 或用户要建立岗位选择偏好时，不使用本文件的自我探索开场；完整执行
`job-preference-workflow.md`。不得临时改成自由问卷、合并多个节点或遗漏旧 Base 迁移。

不问“哪段经历最能证明你适合”，不要求用户为每个方向先举业绩。Agent 先提出迁移路径，再请
用户判断是否合理。

## 语言样本

语言画像建档和更新完整执行 `language-profile-workflow.md`。用户说内容“不像自己”时，
优先邀请提供真实样本：

> 如果你愿意，可以发一段完全由你自己写的逐字稿、自我介绍或回答。我会先总结其中的语言习惯
> 给你确认，再用于后续改写，不会把样本文字机械复制到不相关内容里。

平时 Chat 不需要专门追问。累积到重复模式后，在主要任务结束后最多用一条简短候选更新
请用户确认。
