# 岗位选择偏好固定建档流程

本流程只建立 `岗位选择偏好｜<显示名>`。空文档按以下顺序一次只推进一个节点；已有值跳过，
缺失值不得推断成“不限”。每个节点经用户确认后立即更新同一文档并保持 `incomplete`，最后整体
确认后改为 `completed`。

## 旧答案迁移

文档缺失或为空时，优先读取可唯一定位的旧 Base `用户偏好` 和旧 `用户画像｜<显示名>`：

- `graduation_year` → 预计毕业年份；
- `target_cities`、`city_filter_mode` → 城市筛选模式、可直接保留的城市；
- `selected_industries`、`excluded_industries` → 可保留、明确排除行业；
- `target_job_preferences` → 已确认愿意考虑的岗位方向；
- `target_companies`、`excluded_companies` → 优先关注、明确排除公司；
- `excluded_recruitment_types` → 明确排除的招聘类型。

只迁移用户原有明确值。无冲突字段不重问；冲突字段在对应节点展示差异后让用户选择。飞书用户
标识、Base URL、来源链接、app token、table ID、同步游标、权限和 workflow 配置不得进入文档。

## 固定节点与默认问法

### 1. 基本教育信息

> 先确认一下你的求职阶段：你目前是什么学历、读什么专业，预计哪一年毕业？

只记录当前学历、所学专业和预计毕业年份，不追问学校排名或成绩。

### 2. 过往岗位接触

> 你之前实习、兼职或正式工作接触过哪些岗位方向？只列岗位即可，不需要讲成果。

只记录岗位方向。不得改问“哪段经历最能证明你适合”或要求业绩证据。

### 3. Agent 生成岗位建议并由用户判断

根据前两步生成两组简短建议：`直接匹配方向` 和 `可能具备迁移路径的方向`。每组默认 3–6 个，
每个可迁移方向用一句话说明专业、通用方法或相邻职能如何迁移。没有同名实习不得成为排除理由。

随后问：

> 这是我根据你的专业和过往岗位整理出的方向。哪些你愿意考虑，哪些你不想考虑？如果还有我没想到但你感兴趣的岗位，也可以一起补充。

分别保存用户确认的直接匹配、可迁移、补充兴趣和明确不考虑方向。Agent 建议本身不是用户结论。

### 4. 高专业门槛边界

根据用户背景动态生成 3–8 个“目前未看到清晰迁移路径”的方向，说明学科、技术、执业或长期训练
门槛；不得根据性格、情绪或没有同名实习判断，不得机械固定为研发、算法。

随后问：

> 基于目前的信息，我暂时没有看到你和下面这些方向之间的清晰迁移路径：……这些里面，哪些是你确认完全不考虑的？如果你暂时不想设置这条边界，也可以直接说都不排除。

只有用户明确确认的方向才能写入“用户明确不考虑”。其余保留为“当前未见清晰迁移路径”或
“信息不足”，不得写成永久岗位黑名单。

### 5. 城市范围

> 哪些城市的招聘信息可以直接保留？如果全国都可以，直接说“全国”。

城市列表保存为 `指定城市`；用户明确说全国才保存为 `全国`。缺失不等于全国。

### 6. 招聘类型

> 你希望保留哪些招聘类型？例如校招、暑期实习、日常实习、社招；如果都可以，可以直接说“不限”。

同时保存可保留和明确排除的招聘类型；“不限”必须由用户明确说出。

### 7. 行业范围

> 行业上你希望怎么筛选？可以告诉我哪些行业可以保留、哪些明确不考虑；如果不想按行业筛选，直接说“不限行业”。

分别保存可保留与明确排除行业。“不限行业”与未回答严格区分。

### 8. 企业偏好

> 有没有希望优先关注的公司，或者明确不要写入求职清单的公司？没有的话直接说“没有”。

优先关注公司只影响展示顺序；明确排除公司才参与硬筛。

## 最终确认

完成或迁移全部节点后，展示按 `profile-schema.md` 生成的完整文档，再问：

> 我会按照下面这份岗位选择偏好保存，并供招聘信息同步使用。你看有没有理解错或需要修改的地方？

用户确认后保存为 `completed`。用户纠正时先更新对应节点，再重新展示一次受影响的摘要；不得重新
播放所有问题。

## 给 job-collection 的结论

除 `career-profile` 自身外，只有 `job-collection` 必须读取本文件生成的文档。它把已确认值镜像
到 Base `用户偏好` 后执行筛选，不得向用户重新询问上述八个节点。

岗位不作逐条名称硬筛。只有可靠来源展示了企业完整招聘范围，并且全部岗位都是用户确认完全不
考虑的方向时，才在写入企业清单前确认。用户接受某一次边界外机会不自动修改长期偏好。
