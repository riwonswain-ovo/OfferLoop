# 语言表达习惯建档与更新流程

本流程维护 `语言表达习惯｜<显示名>`。它从用户真正写过、说过或修改过的内容中学习，
不使用抽象风格问卷。

## 首次建档

文档为空且用户没有先提供真实样本时，固定问：

> 你可以发一段完全由你自己写、而且你觉得比较像自己平时表达的内容吗？可以是逐字稿、
> 自我介绍、问题回答或一段聊天文字。如果暂时没有，也可以直接告诉我。

用户已提供样本时不重复邀请。用户暂时没有样本时不强迫建档；保持文档为 `incomplete`，
后续从自然 Chat 开始积累低置信度观察。

## 样本校准

只问解释当前样本所必需的问题，每次只问一个：

1. 样本的口语/书面属性或使用场景不明时，先确认“这段内容原本是准备说出来的，
   还是作为书面材料使用的？”已经明确时不重问。
2. Agent 直接从样本中提炼一条可观察的候选特征，说明证据和可能适用的产物，再请用户
   判断是否准确。不要一次展示整套风格标签。
3. 用户确认后再提下一条；用户否认时保留纠正，不换个近义词继续说服。
4. 已有足够样本时，可选择一小段做一次模仿改写，询问“这个版本像你会自然说出或写出
   的话吗？哪里还不像？”用户的实际修改比抽象评价更优先。

不主动问用户喜欢长句还是短句、希望听起来专业还是亲切、偏好什么语言风格或禁用哪些措辞。
这些结论应从真实表达和用户修改中归纳。

## 证据与写入门槛

按与目标产物的接近程度记录样本类型和使用场景，不把 Agent 生成但用户没有修改的内容当作
用户样本。一条消息只能进入“待确认与继续观察”；用户明确确认，或多份独立样本反复
出现同一模式后，才能写入“已确认的语言画像”。

已确认特征必须记录其适用场景；口语特征不自动泛化到简历，书面表达也不自动泛化到面试口语。
保存样本标题、来源或链接和少量必要例句，不整段复制逐字稿、ASR 或私人 Chat。

## 长期更新

任何 OfferLoop 业务 Skill 都可在不打断主任务的情况下观察新样本。出现以下情况时，在主任务
结束后最多提出一条候选更新：

- 用户修改了 Agent 的草稿；
- 用户说“这不像我”或指出具体表达问题；
- 多轮自然 Chat 出现重复模式；
- 新增用户自写稿或真实 ASR。

用户确认后立即更新同一份 `语言表达习惯｜<显示名>`。用户没有确认时可记入待观察，但不得影响
后续生成。不得每条消息都弹出确认，也不得静默把新特征固化为长期语言画像。
