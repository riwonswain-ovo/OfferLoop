# 分轮与面试性质适配规范

## 两个判断维度

准备深度同时取决于：

1. 当前是第几轮；
2. 本轮是什么性质的面试。

同公司、同岗位的不同轮次必须改变考察重点、题目、回答深度和反问，不能只换标题。用户手动
指定上一轮准备文档时，沿用已确认事实并减少基础重复。

以下规则是缺少更可靠信息时的启发式模型，不是公司真实流程。公司官方信息、用户明确说明或
高相关面经更可靠时，以证据为准。

## 回答深度

- `D1｜事实层`：背景、职责、行动、结果、数字口径和专业基础。
- `D2｜决策层`：为什么、备选方案、取舍、指标、协作和失败复盘。
- `D3｜系统层`：资源约束、失败条件、组织影响、长期价值、反方观点和认知边界。

## 按轮次调整

### 一面

以真实性、专业基础、岗位基本匹配和可执行能力为默认重点。战斗卡以 D1 为主、核心经历达到
D2；但技术一面、案例一面等明确形式应优先执行对应专业要求。

### 二面

以决策质量、复杂问题、协作和能力上限为默认重点。核心经历达到 D2，重要问题加入 D3；减少
已确认的基础重复。

### 三面、终面或负责人面

以系统影响、资源约束、长期判断、Ownership 和成长潜力为默认重点。不得仅根据“三面”名称
断言面试官是 VP。

### HR 面

以经历主线、求职动机、公司与岗位选择、规划、稳定性和现实条件为重点。仍按岗位画像选择
2–3 段能证明价值观、协作和成长的经历，不机械堆放专业题。

## 按面试性质调整

| 面试性质 | 重点 |
|---|---|
| HR/招聘沟通 | 动机、履历、稳定性、价值观和现实条件 |
| 专业职能面 | 专业知识、岗位方法、事实准确性和实践证据 |
| 技术面 | 原理、实现、质量、性能、系统与技术取舍 |
| 案例面 | 问题拆解、假设、分析、建议、风险与表达 |
| 作品集面 | 问题、过程、判断、迭代、协作和效果 |
| 角色演练 | 场景判断、互动策略、异议处理和目标达成 |
| 业务负责人面 | 业务价值、复杂决策、资源、协作和成长上限 |
| 跨部门面 | 接口、冲突、影响力、协同和共同目标 |
| 高管/终面 | 长期判断、组织价值、认知边界和关键动机 |

## 组合规则

先用岗位画像决定“考什么”，再用面试性质决定“怎么考”，最后用轮次决定“问多深”。例如：

- 研发岗 × 技术一面：技术基础、编码/实现和项目 D1–D2；
- 销售岗 × 业务二面：客户决策、谈判取舍和业绩归因 D2–D3；
- 设计岗 × 作品集面：作品过程、关键判断、迭代与效果；
- 财务岗 × HR 面：动机、履历与稳定性，不把专业问答塞满文档。

## 信息不足

轮次未知时先请用户确认；面试性质未知时可根据邀请内容和高相关面经形成低置信度判断，但必须
标记为推断。两者都未知时生成通用版本，以岗位画像、D1–D2 和跨轮高频问题为主。
