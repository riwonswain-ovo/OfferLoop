# 岗位画像适配规范

## 核心原则

岗位画像用于决定“本轮准备什么”，不是把用户塞入固定岗位分类。真实 JD 和用户确认的信息是
最高优先级；预设岗位族只提供启发，不是白名单，也不能覆盖 JD。

## 建立画像

从岗位名称、JD 和可选的部门信息归纳：

| 维度 | 要回答的问题 |
|---|---|
| 行业与组织场景 | 公司处于什么行业，岗位服务哪个部门、业务、客户或内部职能 |
| 岗位族 | 岗位主要属于哪类职能，是否具有明显复合属性 |
| 工作对象 | 主要面对用户、客户、系统、数据、资金、人才、项目、供应链或专业事项中的什么 |
| 核心任务 | 日常最重要的三至六项任务 |
| 交付物 | 岗位最终交付产品、系统、分析、收入、活动、制度、项目、作品或专业意见中的什么 |
| 成果指标 | 招聘方可能用什么结果判断工作有效 |
| 核心能力 | 面试需要验证的三至六项能力 |
| 决策与取舍 | 岗位经常面对什么冲突和约束 |
| 专业风险 | 哪些事实、合规、技术或职责边界不能夸大 |
| 面试形式 | 可能采用经历面、专业问答、技术题、案例、作品集、角色演练或管理面中的什么 |
| 来源策略 | 哪些官方、专业和面经来源最可能有高相关信息 |

优先级：

```text
用户确认的 JD 与岗位信息
→ 公司、监管、专业机构等一手资料
→ 同公司同岗位高相关面经
→ 下列岗位族启发
→ Agent 的一般性推断
```

推断不能写成公司事实。岗位名称模糊但 JD 足够时直接按 JD 建模；只有歧义会实质改变准备方向时
才询问用户确认。

## 常见岗位族启发

| 岗位族 | 常见能力与结果 | 常见面试形式 |
|---|---|---|
| 产品 | 用户洞察、需求判断、方案、协作、指标与业务价值 | 经历深挖、产品题、业务题、案例 |
| 研发/工程 | 技术基础、实现、系统设计、质量、性能与工程取舍 | 技术问答、编码、系统设计、项目深挖 |
| 算法/数据科学 | 原理、数据、实验、评估、泛化与工程落地 | 理论题、算法题、实验设计、项目深挖 |
| 数据分析 | 数据口径、分析方法、因果意识、洞察与业务落地 | SQL/统计、分析案例、项目深挖 |
| 商业分析/咨询 | 问题拆解、假设验证、测算、商业判断与影响决策 | 案例面、估算、分析展示、经历面 |
| 运营 | 人群/供给、策略、执行、资源效率和复盘 | 业务题、案例、数据题、经历深挖 |
| 市场/品牌 | 市场洞察、定位、内容、渠道、投放与品牌效果 | 案例、方案展示、作品、经历面 |
| 销售/商务 | 客户判断、拓展、方案、谈判、关系和收入结果 | 角色演练、业绩深挖、异议处理、案例 |
| 项目/PMO | 目标、计划、依赖、风险、资源与组织交付 | 情景题、项目深挖、冲突与推动 |
| 财务 | 专业准则、数据准确、分析、预算、风险和业务支持 | 专业问答、案例、数据测试、经历面 |
| 人力资源 | 人才、组织、招聘、绩效、员工关系和业务理解 | 情景题、案例、经历面、价值观 |
| 法务/合规 | 规则适用、事实识别、风险判断、谈判与合规边界 | 专业问答、案例分析、文本或情景题 |
| 设计 | 用户问题、设计判断、过程、协作、迭代与效果 | 作品集、白板题、设计挑战、经历面 |
| 供应链/采购 | 计划、成本、质量、履约、供应商和风险 | 专业案例、数据题、谈判情景、经历面 |
| 研究/科研 | 研究问题、方法、证据、有效性、创新与局限 | 论文/项目深挖、专业问答、研究计划 |

这些岗位族不是穷尽清单。教育、医疗、制造、公共事务、专业服务及其他岗位未命中时，直接使用
画像表按 JD 生成，不得拒绝、降级或强行归入产品岗。

## 复合岗位

复合岗位保留真实名称，通常只组合一至两个最相关岗位族。例如：

- AI 产品经理：产品 + 算法/数据科学；
- 解决方案顾问：销售/商务 + 咨询或技术；
- 数据运营：运营 + 数据分析；
- 财务 BP：财务 + 商业分析。

组合后重新按 JD 排序能力，不能简单拼接两个题库。

## 如何驱动面试准备

岗位画像必须影响：

1. 选择哪 2–3 段经历作为战斗卡；
2. 检索平台、官方资料和专业来源；
3. 十道题的问题类型与专业深度；
4. 参考答案的内部推理骨架；
5. 当前轮次和面试性质的权重；
6. 候选人反问的对象与内容；
7. 需要守住的专业事实、数字和职责边界。

不要在成品中机械展示完整岗位分类表。只在有助于用户理解准备重点时，用简短文字说明岗位画像
和判断依据。
