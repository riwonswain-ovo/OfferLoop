# 高阶自我介绍方法论

## 适用范围与必读要求

本方法用于 `interview-prep` 生成公司与岗位定制的 1—2 分钟自我介绍。每次生成、改写或检查
自我介绍前，必须完整读取本文件；不得仅依赖通用回答框架或历史自我介绍。

自我介绍的本质不是复述简历，而是主动替面试官完成一次“人岗匹配总结”：用最短时间说明
候选人为什么适合当前岗位，并有意识地把后续提问引向准备最充分、最能证明优势的经历。

核心公式：

```text
身份定位
→ 三点匹配结论
→ 业务/经历证据
→ 能力证据
→ 岗位或产品洞察与动机
→ 留下追问钩子并交回话题
```

“三点匹配”指经历匹配、能力匹配和岗位/产品理解三个展开维度，不是三个能力标签，也不是三个
自我评价。能力匹配段内部只选择两个互补能力。

建议时长为 1—2 分钟，以真实、自然口述时间为唯一长度标准，不设置汉字数上下限，也不为命中
固定字数预先删减自然过渡、具体证据和岗位迁移。每个模块只讲“结论 + 一个证据”，完整项目
故事留给后续追问。

## 两个核心目标

### 降低面试官的认知成本

直接帮助面试官形成“为什么应该录用这位候选人”的三个关键词，而不是让面试官从按时间排列的
经历中自行寻找重点。

### 设计后续提问路径

将候选人最熟悉、结果最好、最能体现岗位能力的经历放进自我介绍。在关键结果、判断或冲突处
适时收住，不展开完整 STAR，使面试官能够顺着这些强项继续追问。

## 五段式组织框架

### 第一段：身份定位与三点预告

用 10—15 秒完成姓名、最高学历学校与专业、相关实习或工作背景，并预告三个展开维度。
通常使用“相关经历、核心能力、岗位/产品理解”，具体措辞可按岗位调整，但后文必须逐一兑现。

示意结构：

```text
老师您好，我是……，目前是……，有……相关经历。
结合岗位要求，我想从过往经历、个人能力和岗位理解三个方面，介绍我和岗位匹配的地方。
```

身份信息只完成定位，不介绍学校历史、课程，不罗列所有教育经历，也不在开头堆奖项。

### 第二段：业务或经历匹配

用 25—35 秒直接指出最匹配的经历，优先选择 1—2 段。每段只讲：

```text
在哪里/做什么 → 主要关注什么核心问题
```

最后必须完成迁移判断：这些经历让候选人对目标岗位的哪个场景、角色、链路或矛盾形成了理解，
为什么能帮助其快速进入目标公司的具体工作。

经历匹配的证据优先级：

1. 做过相关业务领域内的相关岗位；
2. 有高度相关的个人项目、兴趣实践或副业；
3. 对目标赛道有持续、可验证的研究与输出。

根据证据强度选择其中一至两个角度，不为凑结构全部展开。不要在此复述项目背景、完整动作和
全部结果；在最能体现价值的位置收住。

### 第三段：能力匹配

用 30—40 秒只选择两个互补能力。能力必须来自 JD、岗位实际工作和用户材料的交集，并采用：

```text
能力结论 → 一个具体案例 → 一个关键动作或结果
```

优先选择能构成工作闭环的能力组合，例如：

- 发现和定义问题 + 推进和验证方案；
- 用户/业务洞察 + 数据分析；
- 产品设计 + 技术业务连接；
- 专业判断 + 跨团队落地。

能力证据可以来自第二段未展开的经历，也可以从已出现的经历中选择不同事实，但不得重复讲述
同一段信息。不要说“学习能力强”“沟通能力好”等无证据形容词。

### 第四段：岗位/产品理解与求职动机

用 20—25 秒说明对目标公司、目标业务或岗位独特价值的理解，再连接职业规划和做该类工作的
内在动机。本段不重复过往经历。

有效表达应回答：

1. 这个产品或岗位不只是表层的什么；
2. 它真正连接了哪些角色、资源、关系或业务机制；
3. 为什么候选人希望长期参与这种工作。

产品理解必须具有公司独特性。把公司名替换成竞品后仍完全成立的句子，应继续改写。公开资料
不足时使用条件性判断，不把推断包装成公司内部事实。

### 第五段：感谢并交回话题

用约 10 秒表达感谢和明确的加入意愿，同时邀请面试官选择感兴趣的经历或判断继续展开。

示意结构：

```text
以上是我的简要介绍，非常荣幸获得……的面试机会，我也希望有机会加入……。
如果您对其中哪段经历感兴趣，我可以再具体展开，谢谢老师。
```

结尾不再增加新项目、新能力或新数字。

## 组织内容的关键原则

### 从经历视角切换到岗位视角

不要按时间顺序回答“我经历过什么”，而要围绕目标岗位回答“为什么需要我”。经历只是人岗
匹配结论的证据。

### 先结论，后证据

先说匹配在哪里，再用一个业务场景、个人动作、结果或判断证明。即使面试官没有记住全部细节，
也应能复述候选人的三个匹配关键词。

### 三个关键词贯穿全文

第一段给出的三个匹配维度，应与第二至第四段一一对应。不得开头预告一套、正文又展开另一套。

### 钩子要强而未尽

只选择候选人能经受追问的案例。讲清负责什么、关注什么以及最有价值的结果或判断后收住，
不要在自我介绍中讲完完整项目故事。

### 表达必须可验证

用业务场景、个人动作、协作范围和量化结果代替抽象形容词。数字不是越多越好；每个模块最多
保留一个真正帮助证明结论的结果，且必须统一时间、分母和实验阶段。

### 根据岗位动态改写

身份信息可以相对固定，但三个匹配点、案例顺序、迁移判断和岗位洞察必须随公司、业务、岗位、
轮次与面试性质变化，不能用同一版话术海投。

轮次只调整证据和洞察的权重，不改变个人事实：

- 一面突出具体动作、专业基础和结果；
- 二面突出关键判断、取舍、指标和协作；
- 三面、负责人面突出组织或业务影响、系统思考和成长潜力；
- HR 面突出经历主线、求职动机、规划和稳定性。

### 采用当前任务的真实语言样本

本方法同时是自我介绍的唯一语言规则，不再读取其他语言契约。事实和逻辑确认后，按以下优先级
调整句子节奏、连接方式和叙事顺序：

1. 当前任务中用户已经明确确认的自我介绍；
2. 用户在当前任务中主动提供或明确授权的自然口语、真实面试 ASR；
3. 用户对本轮自我介绍草稿的实际改写；
4. 当前对话中反复出现的稳定表达特征。

用户已经确认过一版自我介绍时，必须以该版本为底稿；除非用户明确要求推倒重写，不得为了重新
调用 Skill、控制字数或追求“更精炼”而另写一版。未经用户确认的 Agent 文案不是用户语言样本。
样本不足时使用清晰、自然的默认口语，不声称已经模仿用户，也不模仿错字、ASR 错误或无意义
口头禅。语言调整不得改变事实、指标、责任边界和结论。

## 生成流程

1. 从 JD 提炼三个最重要且可被个人材料证明的匹配维度。
2. 为经历段选择 1—2 段最接近目标业务的经历，并写出目标岗位迁移判断。
3. 为能力段选择两个互补能力，每项只配一个强证据。
4. 基于公司和岗位研究写出不可轻易替换公司名的岗位/产品洞察，并连接真实求职动机。
5. 设计 2—4 个候选人能够深入回答的追问钩子。
6. 先形成信息完整、过渡自然的连续口语，再真实试读两次，检查时长、重复、证据口径和自然度；
   不根据字符数预先压缩。
7. 按下方检查表验收；任一硬项不满足时重写，不交付履历流水账作为正式版本。

## 交付前检查

- [ ] 第一段完成身份定位，并清楚预告三个匹配维度。
- [ ] 正文依次兑现经历匹配、两个互补能力、岗位/产品理解与动机。
- [ ] 经历段只选 1—2 段最相关经历，并明确说明可以迁移到目标岗位的原因。
- [ ] 两个能力都有“能力结论 + 具体案例 + 关键动作或结果”，没有空泛标签。
- [ ] 岗位/产品理解具有目标公司独特性，没有重复个人经历。
- [ ] 全文从岗位视角组织，不按简历时间线罗列公司和任务。
- [ ] 三个关键词前后一致，每段只完成一个信息任务。
- [ ] 至少留下 2 个“强而未尽”、且候选人确实能接住的追问钩子。
- [ ] 数字、职责和结果来自用户材料，且没有混用不同实验阶段或统计口径。
- [ ] 结尾包含感谢、加入意愿和自然的交回话题。
- [ ] 自然口述为 1—2 分钟，没有超过两个能力点，也没有展开完整 STAR。
- [ ] 当前任务已有用户确认版时，以确认版为底稿，没有未经要求推倒重写。
- [ ] 已按本文件的语言样本优先级完成口语检查；样本不足时没有冒充用户语气。

## 压缩规则

只有连续口述两次后确实超过两分钟，才按以下顺序删减；不得用字符数代替口述计时：

1. 行业背景枚举；
2. 项目过程和技术实现细节；
3. 重复结论；
4. 泛化形容词；
5. 次要数字。

不要优先删除具体证据、经历到岗位的迁移判断、公司独特的岗位理解和求职动机。

## 方法来源

本方法由用户确认的《1-高阶自我介绍方法论｜1—2分钟建立人岗匹配框架》提炼并固化。原始思路
来自《80场秋招面试验证过的高阶自我介绍框架》，本 reference 结合 `interview-prep` 的公司研究、
事实边界和口径检查要求整理。私人材料的直达链接不进入仓库或安装包。
