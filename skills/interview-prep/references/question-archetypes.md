# 面试问题原型与覆盖规范

## 用途

先按 `question-prediction.md` 形成证据驱动的候选问题池，再用问题原型检查本轮是否遗漏关键
考察面，不把原型变成固定题库。真实 JD、用户材料、当前轮次、面试性质和高相关面经决定最终
问题；原型只提供内部覆盖和追问启发，不能直接承担问题生成。

正式十题仍必须是只有了解目标公司、组织场景、专业领域或岗位背景才能针对性回答的问题。
替换公司名仍普遍成立的基础题不得占用十题名额，只保留为内部追问提醒。

## 通用问题原型

| 原型 | 主要验证 | 优先取证位置 |
|---|---|---|
| 动机与选择 | 为什么公司、岗位、行业和当前机会 | 自我介绍、履历主线、公司研究 |
| 履历与转向 | 经历连续性、方向变化、空档和现实约束 | 简历、用户确认事实 |
| 角色与贡献 | 本人做了什么、为什么由本人负责 | 个人材料 D1 |
| 方法与专业基础 | 是否掌握岗位常用方法、工具和事实 | JD、专业资料、个人材料 |
| 决策与取舍 | 判断标准、备选方案、指标和代价 | 个人材料 D2 |
| 协作与影响 | 冲突、资源、依赖、沟通和推动 | 个人材料 D2 |
| 失败与复盘 | 责任承担、归因、修正和迁移 | 个人材料 D2–D3 |
| 系统与长期影响 | 约束、组织影响、失败条件和长期价值 | 个人材料 D3、公司研究 |
| 公司与业务判断 | 对目标公司当前场景的理解 | 高相关面经、官方和可靠资料 |
| 场景与案例 | 面对新问题如何拆解、验证和行动 | 岗位画像、专业参考 |
| 价值观与工作方式 | 稳定性、原则、节奏和团队适配 | 用户真实经历、HR 轮次信息 |
| 候选人反问 | 是否真正理解岗位并会判断机会 | JD、公司研究、已确认面试官性质 |

## 内部覆盖步骤

1. 从预测阶段的 15–25 道候选问题池开始，不另起一套通用问题。
2. 参考面试情报矩阵，按原型归类候选问题并语义去重。
3. 检查每项核心能力是否至少有一个证据充分的验证入口。
4. 检查动机、履历、个人贡献、协作/复盘是否存在明显风险。
5. 把公司化、岗位场景化的问题送入正式十题候选池。
6. 把通用但高风险的问题保留为内部提醒，不另建经历、快速复习或通用题库章节。
7. 按轮次和面试性质调整覆盖，不要求每轮机械覆盖全部原型。

## 分轮启发

- 一面：优先角色与贡献、方法与基础、履历一致性和事实口径。
- 二面：优先决策与取舍、协作与影响、失败复盘和复杂场景。
- 负责人/终面：优先系统影响、长期判断、关键动机和认知边界。
- HR 面：优先动机、履历主线、价值观、规划、稳定性和现实条件。

面试性质提供更强信号时以性质为准，例如技术一面仍应优先技术基础和实现，作品集面优先作品
过程和设计判断。

## 基础风险题

只在用户材料或轮次显示真实风险时选择一至三道，例如：

- 为什么选择这家公司和岗位；
- 为什么转向、离开上一段经历或没有留用；
- 多段经历之间的主线是什么；
- 最大短板、失败或分歧是什么；
- 当前求职规划和现实限制是什么。

为基础风险题准备一句话口径和三至五个记忆关键词，不生成未经材料支持的完整故事。没有明显
风险时省略，不为凑数制造问题。

## 去重与边界

- 同一考察点的不同措辞只保留与本轮最贴近的一题。
- 面经中的追问链可以映射到用户真实经历，但不能虚构为用户事实。
- 题库、课程或历史材料只能启发问题原型，不能证明目标公司的当前事实。
- 不采用带有歧视、诱导造假或明显过时假设的问题口径。
- 不把来源不明的“出现率”写成统计事实。
