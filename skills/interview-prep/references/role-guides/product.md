# 产品岗位面试适配指南

## 适用条件

仅当岗位画像显示核心工作是产品发现、定义、设计、策略、平台建设或产品经营时读取。岗位名称
含“产品”但 JD 主要是销售、项目交付、运营执行或纯技术研发时，不机械套用。

本指南提供问题和证据方向，不是固定题库，也不能替代目标公司的当前资料。

## 方向识别

| 方向 | 主要对象与结果 | 常见考察 |
|---|---|---|
| C 端/用户产品 | 用户任务、体验、增长、留存与商业价值 | 用户洞察、产品判断、指标、实验 |
| B 端/企业产品 | 业务流程、角色权限、效率、成本与交付 | 业务抽象、流程、实施、协作和复杂度 |
| 平台/中台产品 | 多方能力复用、规则、稳定性与治理 | 边界、抽象、服务水平、迁移和治理 |
| 策略产品 | 规则、算法/策略、供需和目标函数 | 指标、实验、约束、误伤和长期效果 |
| 数据产品 | 数据生产、治理、分析与决策支持 | 口径、质量、权限、可用性和业务闭环 |
| 商业化产品 | 流量/用户价值、客户工具与收入效率 | 商业模式、链路、指标、体验和风险 |
| AI 产品 | 模型能力与用户任务的产品化 | 场景、评估、数据、成本、幻觉和迭代 |

复合方向只选择 JD 中真正重要的一至两个，不拼接全部问题。

## 核心考察地图

1. `需求与问题`：需求来源、用户是谁、问题是否真实、优先解决什么。
2. `产品判断`：目标、原则、备选方案、取舍和不做什么。
3. `方案与落地`：流程、角色、边界、依赖、灰度、上线和异常处理。
4. `数据与验证`：北极星指标、过程指标、实验、归因和长期影响。
5. `协作与推动`：业务、设计、研发、算法、运营和管理者之间如何对齐。
6. `业务价值`：用户价值如何连接收入、效率、成本、风险或战略目标。
7. `复盘与成长`：失败条件、错误、反馈和可迁移的方法。

## 常见问题骨架

### 需求或功能判断

```text
目标与用户 → 证据 → 价值/风险 → 备选方案 → 优先级 → 验证
```

先判断是否值得解决，再讨论功能。用户口述与行为数据冲突时，检查样本、场景、指标和因果，不
机械服从任一方。

### 产品设计或优化

```text
明确目标与边界 → 用户/角色和场景 → 当前链路与痛点
→ 方案与取舍 → 指标和实验 → 风险与迭代
```

### 数据异动

```text
确认数据真实与口径 → 定位发生环节 → 按人群/渠道/场景/时间拆解
→ 排查外部、产品、运营和技术因素 → 验证原因 → 止损与长期修复
```

### 竞品分析

先明确目的，再选择直接竞品、替代方案和必要标杆；比较产品机制、用户路径、指标/商业模式和
底层能力，最后回到目标公司的机会与约束。

### 协作与资源冲突

```text
共同目标 → 分歧原因与约束 → 影响和优先级 → 可选方案
→ 决策机制与升级条件 → 同步、执行和复盘
```

不能用“沟通协调”概括全过程，必须说明本人判断和实际动作。

## 经历选取

优先选择能分别证明以下内容的二至三段经历：

- 发现并定义真实问题；
- 在约束下完成关键判断和取舍；
- 推动跨团队落地并用结果验证；
- 对失败、数据口径和本人边界保持诚实。

同一段经历可以覆盖多个能力，但不能靠重复叙述制造覆盖感。

## 专业边界

- 不把通用产品框架冒充目标公司的工作流程。
- 不把相关性写成因果，不把上线后增长全部归功于本人。
- 不编造研发实现、算法机制、实验结果或用户反馈。
- AI 产品问题必须区分模型能力、产品体验、工程成本、安全与评估。
- 商业化产品明显命中时同时读取 `references/role-guides/commercialization-product.md`。
