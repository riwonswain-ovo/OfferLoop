# 金字塔式回答与记忆规范

## 核心原则

思考时可以从材料归纳，表达时必须自上而下：

1. 先用一句话直接回答问题；
2. 用二至四个同层支撑点解释结论；
3. 在每个支撑点下放事实、数据、机制或例子；
4. 最后补充边界、反思或行动。

同一组内容必须属于同一类型，例如全部是原因、能力、步骤或判断标准。不要把原因、动作、结果
和例子并列在同一层。支撑点按时间、结构、重要性或逻辑递进排序；MECE 只要求对当前问题足够
不重不漏，不追求穷尽所有可能。

## 每段回答的固定记忆卡

自我介绍、面经题参考回答和补充题参考回答都先输出：

```markdown
#### 一句话结论

<直接回答问题，不写“我有三点”之类空结论>

#### 记忆关键词

`关键词1 → 关键词2 → 关键词3 → 回扣`

#### 逻辑类型

归纳 / 演绎

#### 逻辑骨架

<用箭头列出能够复原回答的推理链>

#### 个人参考回答

<自然口语版本>
```

关键词保留三至五个短语，每个短语代表一个完整信息块。关键词用于复原逻辑，不是把完整回答
压缩成一串难懂名词。

## 归纳结构

适用于自我介绍、项目复盘、能力证明、为什么适合岗位和多数经历题。先给总判断，再用同类事实
或理由支撑：

```text
结论 → 支撑 A → 支撑 B → 支撑 C → 回扣结论
```

支撑点使用同一种分组标准：

- 按能力：洞察、决策、落地；
- 按过程：识别问题、设计方案、验证结果；
- 按重要性：决定性证据、次要证据、补充证据；
- 按结构：用户价值、业务价值、实现可行性。

组结论必须概括支撑点共同说明了什么，不能只说“主要有三点”。

## 演绎结构

适用于方案判断、产品设计、策略题和“为什么选择 X”。口头表达仍然先亮结论，再展开推理：

```text
结论 → 判断标准/一般原则 → 本题事实 → 推论或行动
```

例如回答方案选择时，先说明选什么，再说明采用的判断标准、关键事实如何满足标准，以及由此
推出的行动。演绎链控制在必要步骤内，不用长前提把结论藏到最后。

## 自我介绍

使用归纳结构，围绕一个岗位定位组织二至四个同层证据块：

```text
岗位定位 → 证据块 A → 证据块 B → 证据块 C → 岗位匹配
```

证据块优先按能力分组，每块引用一项最强经历或结果。不同轮次只调整证据权重，不改变事实：

- 一面：具体动作、专业基础、项目结果；
- 二面：关键判断、取舍、指标和协作；
- 三面：业务影响、系统思考和成长潜力；
- HR 面：经历主线、动机、规划和稳定性。

## 质量检查

- 一句话结论是否真正回答了问题；
- 第二层是否只有二至四个同类型支撑点；
- 每个支撑点是否有事实或机制，而不是口号；
- 归纳结构的组结论是否能概括全部支撑点；
- 演绎结构的原则、事实和推论是否连续；
- 关键词能否在不看全文时复原主要逻辑；
- 回答是否保留真实边界，没有为了结构漂亮而补造经历。
