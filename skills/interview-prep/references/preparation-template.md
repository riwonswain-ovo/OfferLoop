# 面试准备文档范式

## 目标

生成一份“前短后长”的面试作战手册：

- 前部支持面试前 10 分钟快速复习；
- 后部支持系统练习和追问准备；
- 外部来源、逻辑标签和证据审计保持可追溯，但不把 Agent 内部工作底稿塞给用户。

## 内部准备

生成前完成但不直接展示：

1. 确认公司、岗位、完整 JD、当前轮次和可选部门/业务线/职能方向。
2. 确认用户指定的经历深挖产物或上传简历；上一轮准备只在用户手动指定后读取。
3. 按 `role-adaptation.md` 建立岗位画像和可能的面试性质。
4. 按 `round-preparation.md` 确定本轮考察重点和深度。
5. 按 `retrieval-blueprint.md` 拆解 JD，生成检索任务和面试情报矩阵。
6. 按 `interview-source-search.md` 研究面经、公司、组织场景、专业和行业资料，逐项填充矩阵。
7. 按 `question-prediction.md` 生成 15–25 道带 E1–E6 信号和预测依据的候选问题。
8. 按 `question-archetypes.md` 做覆盖检查和问题路由，识别一至三道真实基础风险题。
9. 选择 2–3 段经历，集中形成事实源战斗卡及其高概率追问。
10. 从符合证据门槛的候选池选择并排序十道题：3 道必练、4 道重点、3 道了解。

## 正式结构

```markdown
# <公司>｜<岗位>｜<轮次>面试准备

## 本轮快速复习
## 90 秒自我介绍
## 个人经历战斗卡
## 公司、组织场景与岗位强相关的十道题
## 候选人反问
## 信息来源
```

用户确认保存飞书时，在标题后加入产物契约要求的最小“产物信息”，正文六个章节和顺序不变。
不新增公司百科、通用题库、独立完整性审计或长篇研究报告。

## 本轮快速复习

控制在几屏内，所有内容必须与后文一致：

```markdown
## 本轮快速复习

### 本轮最重要的考察点

1. <考察点>｜<为什么重要>
2. ...

### 自我介绍记忆链

`岗位定位 → 证据 A → 证据 B → 证据 C → 岗位回扣`

### 高概率经历

| 战斗卡 | 一句话价值 | 必须记牢 |
|---|---|---|
| 战斗卡 1｜<经历> | <价值> | <数字/职责/关键判断> |

### 十道题速记

| 题目 | 优先级 | 一句话结论 | 记忆关键词 |
|---|---|---|---|
| Q1｜<问题摘要> | 必练 | <结论> | `A → B → C` |

### 优先反问

1. ...
2. ...
3. ...

### 基础风险题

- <问题>｜一句话口径：<口径>｜记忆：`A → B → C`

### 必须守住的事实边界

- ...
```

本轮考察点控制在 3–5 个。高概率经历只写摘要。十道题速记必须覆盖全部 10 道。优先反问固定
选后文最值得问的 3 个。基础风险题只在动机、履历、个人贡献、失败/短板或现实条件存在真实
风险时保留 1–3 道；没有明显风险时省略。事实边界集中放数字、职责、技术、时间线和外部事实
中最危险的 3–6 项。

## 90 秒自我介绍

强关联公司、组织场景、JD、当前轮次、面试性质和用户材料。正常语速目标约 300–400 个汉字，
以自然说完约 90 秒为准。

```markdown
## 90 秒自我介绍

### 一句话岗位定位

### 记忆链

`岗位定位 → 同层证据 A → 同层证据 B → 同层证据 C → 岗位回扣`

### 90 秒口语版

### 预计追问

### 30 秒压缩版

<仅在群面/短时开场、用户明确需要或邀请信息显示时间受限时出现>
```

不展示“归纳/演绎”标签和独立逻辑骨架；记忆链本身应能复原金字塔结构。

## 个人经历战斗卡

固定选择 2–3 段。每张卡是后文引用个人事实的统一来源，十道题不重复抄写整段经历。

```markdown
## 个人经历战斗卡

### 战斗卡 1｜<经历名称>

`被问概率：高｜对应 JD：<能力>｜适用题目：Q1、Q4`

#### 30 秒经历主线

#### 必须记牢的事实与数字

#### 本轮高概率追问

- D1｜事实：
- D2｜决策：
- D3｜系统：

#### 面试前待回忆

#### 不可夸大的边界
```

只展示本轮实际需要的深度；不适用的 D2/D3 可省略。材料没有披露的信息进入“面试前待回忆”，
不得补造。

## 十道公司与岗位场景题

固定 10 道并按重要性排序：

- Q1–Q3：必练；
- Q4–Q7：重点；
- Q8–Q10：了解。

题目优先来自高相关面经，语义去重后不足再根据可靠资料生成。替换公司名仍普遍成立的通用题
不能入选。

每道正式题在内部都必须保留可追溯的预测依据，但不把 E1–E6 信号表、评分过程或候选池展示给
用户。

每题先用一行压缩元信息：

```text
来源：NC-01｜优先级：必练｜JD：<能力>｜经历：战斗卡 1
```

来源类型和具体编号必须保留，但不再逐项展示“为什么可能问、考察点、JD、经历”等多行字段。

### 必练题模板

```markdown
### Q1｜<问题>

`来源：<编号/类型>｜优先级：必练｜JD：<能力>｜经历：<战斗卡>`

#### 一句话结论

#### 记忆链

#### 个人参考回答

<完整、可直接练习的口语答案>

#### 可能追问

#### 特殊风险

<仅在本题存在战斗卡未覆盖的特殊风险时展示>
```

### 重点题模板

```markdown
### Q4｜<问题>

`来源：<编号/类型>｜优先级：重点｜JD：<能力>｜经历：<战斗卡或无>`

#### 一句话结论

#### 记忆链

#### 精简参考回答

#### 关键追问

#### 特殊风险

<仅有时展示>
```

### 了解题模板

```markdown
### Q8｜<问题>

`来源：<编号/类型>｜优先级：了解｜JD：<能力>｜经历：<战斗卡或无>`

#### 一句话结论

#### 答题路径

#### 可用个人证据

#### 简洁参考回答
```

十道题都必须有参考答案。必练题最完整，重点题保留足够练习内容，了解题用于建立认知和答题
方向。事实边界优先引用战斗卡和快速复习区；只有本题存在额外风险时才新增“特殊风险”。
涉及公司、行业或业务判断时，在自然语言中明确哪些是来源支持的事实、哪些是条件性推断或
候选人判断，不额外堆叠内部标签表。

## 候选人反问

准备 4–6 个，最优先的 3 个同步进入快速复习区：

```markdown
## 候选人反问

### 优先反问

1. <问题>
   `适合：<面试官类型>｜目的：<希望确认什么>`

### 备选反问

4. ...

### 本轮不建议询问

<仅在存在明显踩坑项时展示>
```

反问来自本轮研究和 JD；公开资料已经明确回答的问题不应再次询问。
“适合”依据已确认的面试官职能或本轮面试性质填写；未知时写“适合业务/专业面试官”等宽泛
对象，不因一面、二面名称断言对方层级。

## 信息来源

必须是最后一个二级章节，只列实际读取并用于正文的直达链接：

```markdown
## 信息来源

### 小红书面经
- [XHS-01｜<标题或摘要>](<直达链接>)｜发布：<日期或未知>｜相关性：<说明>｜读取：<时间>

### 牛客面经
- [NC-01｜<标题或摘要>](<直达链接>)｜发布：<日期或未知>｜相关性：<说明>｜读取：<时间>

### 其他高相关面经
- [<平台编号>｜<标题或摘要>](<直达链接>)｜发布：<日期或未知>｜相关性：<说明>｜读取：<时间>

### 公司官网、官方组织与产品/服务资料
- [OFF-01｜<标题>](<直达链接>)｜发布：<日期或未知>｜用途：<说明>｜读取：<时间>

### 财报、专业与可靠行业资料
- [PRO-01｜<标题>](<直达链接>)｜发布：<日期或未知>｜用途：<说明>｜读取：<时间>
```

某类没有有效来源时说明原因。正文引用过的来源不得遗漏；“信息来源”之后不得再出现二级章节。
