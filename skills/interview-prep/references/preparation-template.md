## 内部准备

生成前完成但不直接堆入成品：

1. 确认公司、岗位、实际投递简历、面试时间和本轮环节。
2. 按 `round-preparation.md` 直接应用本轮固定深度。
3. 拆解 JD 必备、加分和隐含能力，并映射用户已确认经历。
4. 研究公司官网、招聘公告、产品、财报、官方动态和可靠行业资料。
5. 按 `interview-source-search.md` 检索、精读、去重和编号小红书与牛客面经。
6. 审计简历数字、强动词、角色边界、技术实现和跨轮口径。
7. 建立面经问题、JD 能力、简历要点、个人经历和本轮深度的覆盖关系。

缺少非关键输入时允许生成降级版本，但必须说明影响和补充动作。缺少公司、岗位、JD/岗位画像
或简历正文等硬输入时，只询问最少必要信息。

## 问题和参考回答

面经问题按语义去重、按本轮优先级排序，不按平台分组。每道采用的问题使用：

```markdown
### Q<n>｜<问题>

- 优先级：必练 / 高频 / 建议
- 来源：XHS-01、NC-02
- 适用轮次与深度：二面 / +2 业务面 / D2–D3
- 考察点：
- 对应 JD 能力：
- 关联经历或简历要点：

#### 一句话结论

<直接回答问题>

#### 记忆关键词

`关键词1 → 关键词2 → 关键词3 → 回扣`

#### 逻辑类型

归纳 / 演绎

#### 逻辑骨架

<按照 answer-logic.md 写出箭头推理链>

#### 个人参考回答

<基于用户已确认经历生成的自然口语版本>

#### 可能追问

1. ...
2. ...

#### 证据边界

<可以确认、需要核实和不能夸大的内容>
```

所有采用的面经问题都必须有个人参考回答。必练题给出可直接练习的完整口语版本；高频题给出
简洁口语版本；补充题至少给出一句话结论、记忆关键词、逻辑骨架、关联经历和关键表达。不得把
他人的面经答案改写成用户经历。

## 金字塔式记忆

自我介绍和每道回答都执行 `answer-logic.md`：

- 先给一句话结论；
- 再列三至五个记忆关键词；
- 标明归纳或演绎；
- 用箭头写出逻辑骨架；
- 最后给口语参考回答。

默认使用归纳结构表达自我介绍、经历题和能力证明；使用演绎结构表达方案判断、产品设计、策略
题和选择题。无论使用哪种逻辑，都先展示结论，再展开二至四个同层支撑点。

## 完整性审计

面经问答后，检查：

- 小红书与牛客在当前可访问结果下是否充分检索；
- JD 必备能力是否都有问题和个人证据；
- 实际投递简历是否达到本轮要求的覆盖深度；
- 本轮应考题型是否覆盖；
- 核心问题是否能承受本轮要求的追问层级；
- 数字、角色、技术实现、动机和跨轮口径是否可靠；
- 是否存在面经没有覆盖但本轮必须准备的内容。

给出“完整 / 基本完整 / 不完整”结论、依据、缺口和补充动作。对缺口生成独立的“补充问题与
参考回答”；必须标记为基于 JD、简历或完整性审计生成，不能伪装成面经原题。

除标题和产物契约要求的简短“产物信息”外，“自我介绍”必须是正文第一个章节。“面经原始链接”
必须是最后一个二级章节，按平台列出实际采用的帖子直达链接、发布日期或未知、岗位/环节相关性
和读取时间；之后不得再出现其他二级章节。
