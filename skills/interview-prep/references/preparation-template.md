# 面试准备文档范式

## 目标

生成一份“先完成开场表达，再理解业务与专业，最后系统练题”的面试作战手册：

- 第一部分给出可直接开场的 90 秒自我介绍；
- 第二、三部分补齐公司、业务、岗位与专业知识；
- 第四、五部分用于系统练题和反问；
- 外部来源、逻辑标签和证据审计保持可追溯，但不把 Agent 内部工作底稿塞给用户。

## 内部准备

生成前完成但不直接展示：

1. 确认公司、岗位、完整 JD、当前轮次和可选部门/业务线/职能方向。
2. 确认用户指定的经历深挖产物或上传简历；上一轮准备只在用户手动指定后读取。
3. 按 `role-adaptation.md` 建立岗位画像和可能的面试性质。
4. 按 `round-preparation.md` 确定本轮考察重点和深度。
5. 按 `retrieval-blueprint.md` 拆解 JD，生成检索任务和面试情报矩阵。
6. 按 `interview-source-search.md` 先研究公司、业务领域和岗位背景，形成独立认知模块；再研究
   面经并预测问题和反问，逐项填充矩阵。
7. 按 `question-prediction.md` 生成 15–25 道带 E1–E6 信号和预测依据的候选问题。
8. 按 `question-archetypes.md` 做覆盖检查和问题路由，识别一至三道真实基础风险题。
9. 选择最相关的个人经历形成内部证据映射，用于自我介绍和能力迁移题，不单独输出战斗卡。
10. 从符合证据门槛的候选池选择并排序十道题：3 道必练、4 道重点、3 道了解。

## 正式结构

```markdown
# <公司>｜<岗位>｜<轮次>准备

## 90 秒自我介绍
## 公司、业务与岗位认知
## 业务领域专业知识补齐
## 10 道公司、业务与岗位强相关问题
## 候选人反问
## 信息来源
```

用户确认保存飞书时，继续使用稳定的用户可见标题
`<公司>｜<岗位>｜<轮次>准备`。标题不得追加日期、`run_id` 或其他内部追踪字段；正文不得加入
“产物信息”章节，不展示运行编号、生成状态、生成 Skill、locator 或空的关联记录字段。
`run_id` 仅保留在会话执行上下文中用于幂等和失败重试。正文六个章节和顺序不变，不新增个人
经历战斗卡、快速复习、通用题库、独立完整性审计或与岗位无关的长篇公司百科。

## 公司、业务与岗位认知

作为正文第二个二级章节，使用经过验证的公司、JD 与专业资料，至少回答：

1. 公司是做什么的：核心产品/服务、客户、价值链或商业模式、当前业务阶段；
2. 目标业务领域如何运转：关键场景、参与方、核心指标、约束与当前问题；
3. 岗位是做什么的：在业务链路中的位置、核心任务、交付物、协作对象；
4. 需要什么候选人：从 JD 归纳三至六项能力，并说明各自会如何在工作和面试中被验证；
5. 用户的主要匹配点和待补足项：只基于用户材料，保持事实边界。

不得写成泛泛公司百科；每项信息都要帮助面试者理解岗位、准备问题或判断自己的匹配度。

## 90 秒自我介绍

强关联公司、组织场景、JD、当前轮次、面试性质和用户材料。正常语速目标约 300–400 个汉字，
以自然说完约 90 秒为准。

```markdown
## 90 秒自我介绍

### 90 秒口语版

### 结构提示

`学校与专业 + 总领句 → 差异化契合点 + 关联经历链 + 迁移判断 → 通用方法能力 + 跨经历抽象 → 通用落地能力 + 岗位价值 → 个性化自评 + 成长轨迹 → 抗压 + 事实 → 责任感/结果导向 + 工作表现 → 感谢与入职意愿`
```

口语版固定遵守：

1. 开头只点明最高学历就读学校和专业，不介绍学校历史，不展开课程，不罗列多段教育经历；
2. 学校和专业之后接一句总领句，引导下文的两个部分，例如“接下来我将从岗位契合点和自我
   评价两个方面展开介绍自己”；
3. 第一个契合点写个人最差异化的经历组合：先给结论，再把相关经历按能力递进串联起来，最后
   完成目标岗位迁移判断。允许一项契合点引用多段相关经历；
4. 第二个契合点从多段经历中抽象岗位通用方法，证明这是一套稳定、可复用的工作能力，而不是
   某次项目的偶然结果；
5. 第三个契合点补齐推动落地、技术业务连接或跨团队协作等通用能力，篇幅可短于前两点；
6. 自我评价固定写三个最适合目标岗位的评价点。最具辨识度的一点可用成长轨迹、选择和内在
   驱动力展开；其他评价用简洁事实和具体工作行为证明；
7. 评价责任感、结果导向、沟通或抗压时，必须定义其工作表现，例如持续跟进、效果复盘、
   问题闭环或多任务下稳定输出，不能停留在形容词；
8. 使用“除此之外”“同时”“在自我评价上”等自然过渡形成连续口语。按重要性分配篇幅，不
   要把六个要点写成同长度的条目，也不展开项目数字、算法实现和次要细节；
9. 结尾感谢对方提供面试机会，并明确表达希望获得入职机会、加入公司或在该方向长期发展的
   意愿。

不展示“归纳/演绎”标签和独立逻辑骨架；记忆链本身应能复原金字塔结构。

## 业务领域专业知识补齐

作为正文第三个二级章节，位于公司认知之后、十道题之前。根据 JD、岗位专业方法和用户材料中
暴露的知识缺口，选择面试前必须掌握的核心概念，不追求百科全书式覆盖。

每个知识点使用：

```text
概念是什么 → 与目标业务/岗位有什么关系 → 面试时至少应会回答什么
```

优先覆盖基础分级/分类、核心系统或业务链路、关键术语、常见指标、风险与验收方法。数量通常为
5–10 个；若岗位涉及高安全、强监管或工程系统，必须包含边界、降级/异常和测试验收。所有标准、
法规、技术定义和时效性事实都要引用可靠专业来源，不能凭印象解释。

## 10 道公司、业务与岗位强相关问题

固定 10 道并按重要性排序：

- Q1–Q3：必练；
- Q4–Q7：重点；
- Q8–Q10：了解。

十道题整体必须覆盖以下四类，并在内部做覆盖检查：

1. **业务理解题**：对目标公司、目标业务领域、客户、产品、商业模式、指标、竞争或当前问题
   的理解；
2. **能力迁移题**：过往经历中的方法、判断、协作或结果如何迁移到目标岗位；
3. **场景解决方案题**：给出目标公司业务领域中的具体场景、问题或约束，要求提出分析和完整
   解决方案；
4. **投递意图题**：为什么投递该公司/业务领域、为什么转行或为什么希望长期深耕。

允许一题同时命中多类，但四类均不得缺失。题目排序仍以本轮被问概率和重要性为准，不机械按
类别分组。

题目优先来自高相关面经，语义去重后不足再根据可靠资料生成。替换公司名仍普遍成立的通用题
不能入选。

每道正式题在内部都必须保留可追溯的预测依据，但不把 E1–E6 信号表、评分过程或候选池展示给
用户。

每题先用一行压缩元信息：

```text
来源：NC-01｜优先级：必练｜JD：<能力>｜个人证据：<经历或无>
```

来源类型和具体编号必须保留，但不再逐项展示“为什么可能问、考察点、JD、经历”等多行字段。

### 必练题模板

```markdown
### Q1｜<问题>

`来源：<编号/类型>｜优先级：必练｜JD：<能力>｜个人证据：<经历或无>`

#### 一句话结论

#### 记忆链

#### 个人参考回答

<完整、可直接练习的口语答案>

#### 可能追问

#### 特殊风险

<仅在本题存在额外事实或表达风险时展示>
```

### 重点题模板

```markdown
### Q4｜<问题>

`来源：<编号/类型>｜优先级：重点｜JD：<能力>｜个人证据：<经历或无>`

#### 一句话结论

#### 记忆链

#### 精简参考回答

#### 关键追问

#### 特殊风险

<仅有时展示>
```

### 了解题模板

```markdown
### Q8｜<问题>

`来源：<编号/类型>｜优先级：了解｜JD：<能力>｜个人证据：<经历或无>`

#### 一句话结论

#### 答题路径

#### 可用个人证据

#### 简洁参考回答
```

十道题都必须有参考答案。必练题最完整，重点题保留足够练习内容，了解题用于建立认知和答题
方向。个人经历直接嵌入相关题目的证据位置；只有本题存在额外风险时才新增“特殊风险”。
涉及公司、行业或业务判断时，在自然语言中明确哪些是来源支持的事实、哪些是条件性推断或
候选人判断，不额外堆叠内部标签表。

每道题的答案都使用金字塔表达：一句话结论先直接回答问题；第二层给二至四个同类型支撑点；
每个支撑点后立即接对应事实、机制、业务依据或个人证据；最后回扣岗位、行动或边界。不得先
集中罗列所有观点，再集中罗列证据。

## 候选人反问

准备 4–6 个：

```markdown
## 候选人反问

### 优先反问

1. <问题>
   `适合：<面试官类型>｜目的：<希望确认什么>`

### 备选反问

4. ...

### 本轮不建议询问

<仅在存在明显踩坑项时展示>
```

反问来自本轮研究和 JD；公开资料已经明确回答的问题不应再次询问。
“适合”依据已确认的面试官职能或本轮面试性质填写；未知时写“适合业务/专业面试官”等宽泛
对象，不因一面、二面名称断言对方层级。

## 信息来源

必须是最后一个二级章节，只列实际读取并用于正文的直达链接：

```markdown
## 信息来源

### 小红书面经
- [XHS-01｜<标题或摘要>](<直达链接>)｜发布：<日期或未知>｜相关性：<说明>｜读取：<时间>

### 牛客面经
- [NC-01｜<标题或摘要>](<直达链接>)｜发布：<日期或未知>｜相关性：<说明>｜读取：<时间>

### 其他高相关面经
- [<平台编号>｜<标题或摘要>](<直达链接>)｜发布：<日期或未知>｜相关性：<说明>｜读取：<时间>

### 公司官网、官方组织与产品/服务资料
- [OFF-01｜<标题>](<直达链接>)｜发布：<日期或未知>｜用途：<说明>｜读取：<时间>

### 财报、专业与可靠行业资料
- [PRO-01｜<标题>](<直达链接>)｜发布：<日期或未知>｜用途：<说明>｜读取：<时间>
```

某类没有有效来源时说明原因。正文引用过的来源不得遗漏；“信息来源”之后不得再出现二级章节。
