# 面试准备质量检查

本检查只用于交付前内部验收。发现问题时补齐、降级或明确说明需要用户补充什么，不把检查模板
原样塞进成品。

## 红线

出现任一项时停止交付并修正：

- 编造经历、职责、数字、结果、技术实现、面试官身份或面试流程。
- 用其他版本简历替代实际投递简历，却没有显式说明。
- 把弱来源、过期面经或推测写成公司官方事实。
- 擅自偏离固定轮次模型：一面 +1、二面 +2、三面 VP、最后 HR。
- 生成 HR 初筛准备。
- 把协助、参与或 AI 辅助实现夸大为独立负责、主导或完整开发。
- 在外部平台输入或上传简历、转写稿、联系方式或私人经历素材。
- 伪造、猜测或用搜索结果页代替面经直达链接。
- 正式文档残留提示词、占位符、调试信息、record ID 或 node token。

## 本轮与来源

- [ ] 一场已确认面试只生成一份本轮文档。
- [ ] 已直接按轮次字段应用固定深度：一面 +1、二面 +2、三面 VP、最后 HR。
- [ ] 默认从业务一面开始，未生成 HR 初筛。
- [ ] 已使用实际投递简历，并读取可用的上一轮准备和真实复盘。
- [ ] 中国大陆互联网岗位已通过登录态浏览器分别尝试检索小红书和牛客。
- [ ] 每个平台优先精读 3–5 篇高相关内容；结果不足或访问受阻时已记录缺口。
- [ ] 面经已去重并分配 `XHS-xx` 或 `NC-xx` 编号。

## 自我介绍与问答

- [ ] 除标题和简短产物信息外，正文第一章是当前轮次的自我介绍。
- [ ] 自我介绍包含一句话定位、三至五个记忆关键词、逻辑类型、逻辑骨架、60–90 秒口语版和
      预计追问。
- [ ] 自我介绍与前序轮次事实一致，只调整当前轮次的信息权重。
- [ ] 每道采用的面经问题都标注来源、本轮深度、考察点、JD 能力和关联经历。
- [ ] 每道采用的面经问题都有一句话结论、三至五个记忆关键词、归纳或演绎标签、箭头逻辑骨架、
      个人参考回答、可能追问和证据边界。
- [ ] 回答只引用用户真实经历，没有万能答案或伪个人化内容。
- [ ] 第二层支撑点为二至四个同类型、同层级内容，没有混放原因、动作、结果和例子。
- [ ] 归纳回答的组结论能概括支撑点；演绎回答的判断标准、事实与推论连续。

## 本轮覆盖深度

- [ ] 业务一面覆盖所有简历要点 D1 口径，核心项目达到 D2。
- [ ] 业务二面覆盖关键决策、备选方案、取舍、指标和协作，核心问题达到 D2–D3。
- [ ] 三面/负责人面覆盖系统影响、业务判断、资源约束、失败条件和认知边界。
- [ ] HR 面覆盖动机、规划、稳定性和现实条件，并与业务面口径一致。
- [ ] 仅执行与本轮性质相符的一组要求；轮次不明时按 `incomplete` 通用版本处理。
- [ ] 数字、强动词、角色边界和技术实现均有证据或明确不确定性。

## 完整性与成品

- [ ] 面经问答后给出“完整 / 基本完整 / 不完整”结论和具体依据。
- [ ] 完整性检查覆盖面经检索、JD、投递简历、本轮题型、回答深度和风险口径。
- [ ] 所有缺口均有补充动作；需要补题时同时给出个人参考回答。
- [ ] 补充题明确标记为根据 JD、简历或审计生成，没有伪装成面经原题。
- [ ] 文档包含面试前快速复习项，重点与距离面试的时间匹配。
- [ ] 最后一个二级章节是“面经原始链接”。
- [ ] 正文引用过的面经均有可点击直达链接，并记录平台、发布日期或未知、相关性和读取时间。

## 交付状态

- `completed`：无红线问题，本轮适用的核心要求全部满足。
- `incomplete`：无红线问题，但存在无法自动补齐的信息、登录态、来源或轮次缺口；文档已说明
  影响和补充动作。
- 中国大陆互联网岗位未完成小红书或牛客任一平台检索，且用户未明确同意跳过时，不得标记为
  `completed`。
- 不得仅因为文档格式完整就标记为 `completed`。
