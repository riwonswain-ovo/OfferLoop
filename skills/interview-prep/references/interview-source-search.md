## 适用范围

中国大陆互联网岗位的面试准备必须分别尝试检索小红书和牛客。其他市场按当地主要面经平台
替换，并在文档中说明来源覆盖。

面经用于发现问题、追问方式、考察重点和候选人踩坑点，不能证明公司存在固定面试流程，也不能
替代用户给出的面试邀请、JD 或实际投递简历。

## 登录态与浏览器

1. 读取并遵守 `chrome:control-chrome` Skill，通过用户现有浏览器会话访问平台。
2. 优先使用已登录的小红书和牛客页面，不读取或导出 cookie、local storage、密码或会话文件。
3. 若未登录，明确请用户在当前浏览器完成登录并告知已就绪，然后继续原平台。
4. 遇到验证码、风控或人工确认时暂停，让用户亲自完成；不得绕过验证、复制会话或改用其他方式
   规避登录。
5. 只做完成本轮准备所需的小规模检索和阅读，不批量爬取。

## 查询组合

在两个平台分别使用站内搜索，按已知信息从精确到宽泛组合：

1. `<公司> <部门/业务线> <岗位> <环节> 面经`
2. `<公司> <岗位> 面试`
3. `<公司> <相近岗位名称> 面经`
4. 校招岗位补充毕业届别、暑期实习、秋招或春招；社招岗位补充职级或方向。

按当前轮次补充固定关键词：“一面”“二面”“三面/VP 面”或“HR 面”。不要默认加入“HR 初筛”，
也不要根据面试官身份改变本轮深度。

不要把简历正文、私人经历、手机号、邮箱、面试邀请截图内容或内部信息放入搜索词。

## 筛选和精读

按以下顺序选择：

1. 同公司、同部门或业务线、同岗位、同环节；
2. 同公司、同岗位、相近环节；
3. 同公司、相近岗位；
4. 仅在精确结果不足时使用同类公司同岗位作补充，并明确标记为旁证。

优先近期内容。每个平台在可用结果中精读 3–5 篇高相关面经；不足 3 篇时读取全部可用结果并
记录覆盖缺口。重复转载、营销软文、无岗位上下文的题库和只有标题没有正文的信息不计入有效
样本。

## 来源记录

为实际读取的面经分配来源编号：

- 小红书：`XHS-01`、`XHS-02`……
- 牛客：`NC-01`、`NC-02`……

每条至少记录：

| 字段 | 内容 |
|---|---|
| 来源编号 | XHS 或 NC 编号 |
| 平台 | 小红书 / 牛客 |
| 标题或可识别摘要 | 不大段复制原文 |
| 公司、岗位、业务线、环节 | 页面明确披露的内容 |
| 发布日期 | 页面显示值；未知则写未知 |
| 相关性 | 高 / 中 / 低及理由 |
| 适用轮次与深度 | 一面 / 二面 / 三面 / HR 面；D1 / D2 / D3 |
| 提取内容 | 问题、追问、反馈、踩坑点 |
| 直达链接 | 具体笔记或帖子链接 |
| 读取时间 | 含时区 |

只保留完成任务所需的摘要，不长篇复制帖子正文。

## 整理与融合

先按语义合并重复问题，再建立融合表：

| 问题主题 | 来源编号 | 本轮相关性 | 深度 | 可能考察点 | 对应 JD 能力 | 用户经历/简历要点 | 参考回答 | 证据边界 | 可能追问 |
|---|---|---|---|---|---|---|---|---|---|

- 统计出现情况时只计算本轮实际读取的独立帖子，不把转载或同一作者重复内容重复计数。
- 优先准备与本轮岗位、环节和用户经历同时相关的问题。
- 每道采用的问题都必须有参考回答，并落到用户已确认的经历或产品素材；没有对应证据时写缺口
  和训练动作，不生成伪个人化答案。
- 不把面经中的他人答案改写成用户经历，不编造用户做过的项目、数据或职责。
- 将去重后的问题按本轮优先级组织，不按平台拆成两个孤立题库。

## 失败与降级

- 一个平台无相关结果：记录查询组合和“无有效结果”，继续另一平台，产物标记来源覆盖有限。
- 一个平台未登录或被验证阻塞：暂停并请用户处理；用户明确跳过后才能继续降级生成。
- 两个平台均未形成有效覆盖：可以交付已有材料形成的 `incomplete` 版本，但不得称为完整面试
  准备。

## 文档末尾链接

最终文档的最后一个二级标题固定为：

```markdown
## 面经原始链接

### 小红书
- [XHS-01｜<标题或摘要>](<直达链接>)｜发布：<日期或未知>｜相关性：<说明>｜读取：<时间>

### 牛客
- [NC-01｜<标题或摘要>](<直达链接>)｜发布：<日期或未知>｜相关性：<说明>｜读取：<时间>
```

只列实际读取并用于正文的直达链接。若某平台无有效来源，在对应小节写明“本轮未获得有效
来源”及原因；“面经原始链接”之后不得再出现其他二级章节。
