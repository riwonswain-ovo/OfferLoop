# JD 驱动的面试情报检索蓝图

## 目标

拿到公司、岗位和完整 JD 后，先把招聘要求转换成具体研究问题，再开始搜索。检索目标不是写公司
百科，而是回答：

```text
公司和目标业务现在为什么需要这个岗位
→ 岗位入职后要解决什么问题
→ 面试官最可能验证哪些能力和判断
```

## 1. 拆解 JD

逐项抽取并去重：

| 维度 | 要识别的内容 |
|---|---|
| 核心任务 | 高频动词、负责范围和必须完成的事情 |
| 工作对象 | 用户、客户、商家、系统、数据、资金、人才、项目或专业事项 |
| 交付物 | 产品、系统、分析、收入、策略、项目、制度、作品或专业意见 |
| 成果指标 | 规模、效率、质量、收入、成本、风险、满意度或专业结果 |
| 专业能力 | 知识、方法、工具、技术和行业经验 |
| 协作关系 | 上下游团队、决策者、客户和外部伙伴 |
| 决策与约束 | 常见取舍、资源限制、合规/技术/事实风险 |
| 加分项 | 可能用于区分候选人的复合能力 |

把相近表述合并为三至六项核心能力。不能只抽关键词，必须说明招聘方会如何验证。

## 2. 生成检索任务

围绕每项核心能力分别建立问题，至少覆盖五层：

### 公司

- 当前核心业务、收入/价值来源和战略重点是什么；
- 最近一年与目标岗位有关的投入、调整、产品动作或公开表述是什么；
- 公司正面对哪些竞争、增长、盈利、技术、交付或监管问题。

### 部门、业务线或职能方向

- 服务谁、解决什么需求，在公司内承担什么角色；
- 业务/工作链路、关键参与方、产品或服务如何运转；
- 商业模式、关键指标、核心矛盾、竞争者和替代方案；
- 当前阶段最重要的增长点、瓶颈和风险。

### 岗位

- 岗位位于业务/工作链路的哪一环；
- 入职后最可能负责的任务、交付物、指标和协作界面；
- 公司语境下该岗位与通用同名岗位有什么不同；
- 为什么现在招聘，最可能需要解决哪三至五个问题。

### 专业领域

- 完成这些任务需要哪些稳定的专业知识、方法和工具；
- 常见决策、案例、数据口径和事实边界是什么；
- 哪些近期行业、技术、法规或客户变化会影响岗位。

### 面经

- 同公司、同业务线、同岗位、同轮次出现过什么原题和追问；
- 面试从简历、专业基础、业务判断还是案例切入；
- 哪些内容被连续深挖，轮次之间深度如何变化。

## 3. 按 JD 排定检索优先级

先研究与核心职责直接相关的业务线和专业问题，再补公司整体背景。每个核心 JD 能力至少对应：

1. 一个公司/业务场景问题；
2. 一个岗位实际工作问题；
3. 一个可能的面试验证方式；
4. 至少一个可用来源或明确的证据缺口。

集团介绍、创始人故事和与岗位无关的新闻默认不检索。找不到目标部门资料时，缩小结论并明确
未知，不用集团事实替代。

## 4. 建立内部面试情报矩阵

研究完成后形成内部矩阵，不原样交付：

| JD 能力 | 公司/业务事实 | 当前问题或矛盾 | 岗位任务 | 可能验证方式 | 来源 | 置信度 |
|---|---|---|---|---|---|---|

同时记录三类结论：

- `已确认事实`：来源直接支持；
- `条件性推断`：由事实和 JD 推导，写明前提；
- `待确认缺口`：公开信息不足，不能补造。

## 5. 完成条件

满足以下条件后才进入问题预测：

- 三至六项核心 JD 能力均已映射；
- 已解释公司和目标业务为什么需要该岗位；
- 已找到目标业务链路、关键指标/结果和至少一个当前矛盾；
- 已理解岗位在链路中的位置、主要交付和协作对象；
- 已完成高相关面经尝试并记录原题、追问或无有效结果；
- 所有时效性事实已按当前时间验证。

若关键业务线、岗位职责或轮次证据不足，继续生成降级版本，但必须把影响传递给问题预测，降低
置信度，不能用通用题库填满空缺。
