# Context / Memory 类 AI 产品经历深挖

本参考只在经历真实涉及长对话、跨会话个性化、用户画像、任务状态、记忆读写、上下文拼装或
压缩恢复时加载。目标是验证信息如何影响模型行为以及记忆如何被治理，不把“保存聊天记录”
自动视为记忆系统。

## 1. 上下文目标与信息边界

先确认模型完成当前任务最需要哪些信息、信息来自哪里，以及哪些内容不应进入上下文。围绕四个
维度追问：

- **完备性**：缺少什么会让模型无法判断或只能猜测；
- **噪声**：哪些历史、日志或资料会干扰当前任务；
- **状态**：当前进度、已确认事实和待补槽位如何表达；
- **动态组装**：不同用户、阶段和意图如何加载不同信息。

要求用一次真实跑偏、遗忘、前后矛盾或上下文过长案例说明问题，不接受“上下文越多效果越好”。

## 2. 三类记忆与职责

按生命周期区分实际机制：

- **短期记忆**：维持当前会话连续性，如窗口、摘要或最近若干轮；
- **长期记忆**：跨会话保留稳定偏好、历史事实或可复用经验；
- **工作记忆**：记录当前任务槽位、计划、步骤、状态和中间产物。

继续追问每类信息存在哪里、何时写入、何时读取、保留多久、由谁消费。把所有历史塞进同一个
向量库不算完成分层。

## 3. 读写、遗忘与冲突治理

对于长期记忆和用户画像，确认：

- 什么事实达到写入门槛，模型推测能否直接保存；
- 用户是否知情、可查看、修改或删除；
- 来源、时间、置信度和适用范围是否保留；
- 过期、重复、矛盾和错误记忆如何发现；
- 新旧信息冲突时谁是来源真相，如何重新确认；
- 敏感信息、跨租户数据和下游共享如何限制。

优先深挖一次错误记忆、错误召回或隐私风险，以及它如何推动产品规则变化。

## 4. 长上下文与恢复

长任务或工具输出较大时，追问真实采用的压缩、摘要、卸载和按需重取机制：

- 哪些核心约束必须常驻；
- 哪些工作信息滚动更新；
- 哪些历史只保留摘要、引用或外部文件位置；
- 何时触发压缩，压缩丢失如何检测；
- 中断、切换会话或压缩后如何从状态恢复；
- 是否保存了完成判据、关键决策、未决问题和产物引用。

“做了摘要”不是充分证据；要验证恢复后是否仍能继续正确执行。

## 5. 评测与业务结果

根据经历选择真实指标：

- 信息召回正确率、过期/冲突记忆率；
- 槽位完成率、重复追问率、跨轮一致性；
- 长任务恢复成功率和上下文压缩后的质量变化；
- Token、时延、成本与隐私事件；
- 个性化是否真正改善完成率、返工或用户留存。

至少比较一次无记忆或旧方案基线，控制模型和任务差异；不能把普通模型升级带来的改善归功于
记忆系统。

## 6. 追问边界

每轮优先选择会影响以下判断的一个缺口：信息是否必要、记忆是否可信、状态是否可恢复、隐私
是否可控、效果是否可归因。用户只负责交互或产品规则时，深挖其写入确认、纠错、删除、状态
展示和异常体验设计，不要求其解释未参与的存储实现。
