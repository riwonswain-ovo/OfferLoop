# 经历深挖对话流程 V3.3

## 目录

- 总体方式
- 深挖 Pass
- Experiment Attribution Matrix
- End-to-End State & Fallback Pass
- Rule Trace
- Story Recovery 与故事提取
- Canonical Placement Pass
- Deduplication 与 Publication Hygiene
- 主题完成条件
- 停止条件

## 1. 总体方式

采用“Agent 一题 → 用户回答 → Agent 更新事实状态 → 决定下一题”的方式。

内部持续维护 `Project State`、`Evidence Ledger`、`Experiment Attribution Matrix`、`Fact Ownership Map`、
状态链和故事覆盖状态，对事实、来源、所有权、未知和冲突进行增量更新；文档章节不是固定提问顺序。
这套内部机制统称为 `Project State 与 Evidence Ledger`，用于保证时间受限时仍不降低事实、归因与个人贡献的质量底线。

深挖 Pass 决定需要发现和审计什么信息，Canonical Schema 决定这些信息最终存放在哪里。内部 Ledger、
Matrix、Failure Gate、状态链和故事恢复状态不直接转化为正式文档的平级目录。

以上均属于 Analysis Layer。Publication Layer 只表达这些机制产出的项目结论，不输出机制名称、内部状态
或 Agent 的判断过程。

每轮只问一个问题。
问题的选择不按文档顺序，而按信息增益排序。

优先级：

1. 事实真实性风险；
2. 因果缺口；
3. 个人贡献边界；
4. 实验归因缺口；
5. 状态链 / fallback 缺口；
6. 故事素材缺口；
7. 策略机制；
8. 规则来源；
9. 低价值参数。

核心项目事实已经稳定但失败、冲突、核心决策或跨团队协作仍为空时，故事素材缺口临时提升为当前
最高优先级，进入 `Story Recovery Pass`，不得直接结束。

## 2. 深挖 Pass

### Pass A｜项目骨架

确认：

- 项目是什么；
- 位于什么业务/工作链路；
- 服务谁；
- 为什么存在；
- 是否 0→1；
- 如果不是，前序版本/历史机制是什么；
- 用户角色和范围。

### Pass B｜背景与问题

执行因果结论审计：不能只有原因判断，还要区分当时证据、当前解释和替代解释。

每个核心问题必须形成：

`发现方式 → 现状表现 → 数据/事实证据 → 原因判断 → 原因证据 → 优化方向`

重点追问：

- 这个问题怎么被发现的？
- 是数据、访谈、客诉、舆情、实验还是业务反馈？
- 有多大规模？
- 为什么判断是这个原因？
- 有没有其他解释？

### Pass C｜目标与指标

形成：

`最终目标 → 结果指标 → 链路指标 → 体验/风险护栏`

检查：

- 是否把中间指标误当最终目标；
- 指标是否与目标一一对应；
- 指标的分子/分母/周期/变化类型是否知道。

### Pass D｜策略与动作

每个核心策略统一追到：

1. 对应痛点；
2. 作用机制；
3. 具体动作；
4. 准入/排除/阈值/状态；
5. 为什么这样设计；
6. 与历史规则的关系；
7. 团队负责 vs 我负责；
8. 结果/验证；
9. 是否有冲突、失败、取舍、协作素材。

多阶段 AI、策略、中台、交易或履约链路同时执行 `End-to-End State & Fallback Pass`，不只还原
Happy Path。

### Pass E｜实验与收益

执行 `Experiment Deep Dive`，不把前后对比、单策略实验和组合实验混为一谈。

形成：

`实验假设 → Treatment/Control → 分流 → 周期/范围 → 单策略/组合 → 指标 → 结果 → 护栏 → 归因边界`

必须区分：

- 单策略实验：解释“为什么有效/哪项有效”；
- 组合实验：解释“完整方案是否值得上线”；
- 灰度前后对比：不能冒充随机 AB；
- 不同实验层的数字不能机械串成严格漏斗因果。

每出现一个重要结果，立即写入 `Experiment Attribution Matrix`；Treatment 或 Control 不清楚时，
优先追问该比较关系，不根据组名或常识推测。

### Pass F｜未来优化

只有核心项目已经闭环后再问。

每个未来方向追到：

`剩余问题 → 方案 → 为什么可能有效 → 新增收益 → 新风险/机会成本 → 重点指标 → 上线判断`

未来优化必须体现优先级或 trade-off，而不是简单罗列新功能。

### Pass G｜项目收获

最后才生成。

要求从真实项目事实中抽象，不接受：

- 沟通能力提升；
- 更细心；
- 数据分析能力提升；

这类空泛结论。

优先抽象：

- 对目标岗位工作方式的认知；
- 对该产品/系统类型的认知；
- 从失败、取舍、实验中形成的判断原则。

### Pass H｜规则来源审计

同时完成证据冲突与未知处理；冲突没有解决前不选择更好听的口径。

成稿前集中扫描：

- 阈值；
- 百分比；
- 金额；
- 时间；
- 距离；
- 次数；
- 准入/排除；
- 判责；
- 补偿；
- 模型目标；
- 实验周期/流量/MDE；
- “主要因为 X”；
- “所以我们做 Y”。

对每项判断：

1. 谁提出？
2. 谁拍板？
3. 为什么这样定？
4. 有什么数据/实验/历史经验？
5. 为什么不是其他值？
6. 用户参与到哪一步？

用户不知道时：

- 不继续逼问；
- 不用常识补历史事实；
- 写入第八章：
  - 已知事实；
  - 当前缺失的信息；
  - 如果当时由我负责，如何验证。

### Pass I｜Story Recovery

在正式成稿或进入逐字稿前，扫描失败、冲突、核心决策、跨团队协作四类故事。任一缺失时，每轮只从
一个真实事件入口搜索一次，不展示整套题单：

- **失败**：搜索用户本人的错误判断、遗漏规则或异常、回滚、返工、结果低于预期及其修正；
- **冲突**：搜索明确反对、目标不一致、方案被否定，以及价格、体验、成本、资源或风险取舍；
- **核心决策**：搜索两个以上可行方案、收益与风险取舍、版本节奏放弃项、用户提出或推动收敛的边界；
- **跨团队协作**：搜索外部能力依赖、资源或交付阻塞、多团队共同定义、评审推进和 Bad Case 联合定位。

优先沿用户已经提到的团队、评审、异常、实验或方案变化追问，不把示例暗示成发生过的事实。只有用户
明确表示“确实没有”“不记得”或“当前事实不足”，才把该类别标为 `recovery-exhausted` 并允许待补充。
用户给出事件线索后，继续追到故事完成条件，而不是因出现一个关键词就收口。

## 3. Experiment Attribution Matrix

对每个重要实验、灰度、前后对比或人工评测结果内部记录：

| 字段 | 必填内容 |
|---|---|
| Metric | 指标及口径 |
| Result | 基线、结果、绝对值 / pp / 相对变化 |
| Treatment | 实验侧实际做了什么 |
| Control | 对照侧是什么；没有对照则明确 none |
| Population | 样本人群、样本量与关键筛选 |
| Period | 时间范围；未知则标记 unknown |
| Experiment Type | A/B、单策略、组合、Shadow、前后对比或人工评测 |
| Attribution Boundary | 该比较能说明什么 |
| Cannot Prove | 该比较不能说明什么 |

同一个项目可以有多行、多个比较关系。组名相同不代表实验角色相同；例如 B 对 W 的推荐率与 B 对 A
的偏航结果必须分别记录。定向均衡抽样只能定位错误，不能推断线上自然占比。不同实验层结果可以共同
支持项目判断，但不能机械拼成严格漏斗因果。

## 4. End-to-End State & Fallback Pass

当项目存在三个及以上相互依赖的处理阶段，或任何一步失败会改变用户、订单、资金、权限、路线、
审核或履约状态时触发。先画内部状态链，再按信息增益逐层补齐；每轮仍只问一个最高价值缺口。

每层确认：

1. 输入和触发条件；
2. 正常输出与下游消费者；
3. 失败、空结果、低置信或校验失败条件；
4. 失败后是结束、重试、fallback、回原链路、人工处理还是用户确认；
5. 超时、结果过期和撤回条件；
6. 重复请求、乱序、状态冲突或部分成功如何处理；
7. 谁拥有建议权、执行权和最终决策权；
8. 日志、监控、回滚和恢复方式。

只追问真实存在或高后果的环节。用户不知道实现细节时标记 unknown / non-owned，并写入第八章，
不得用通用架构补造。对于 AI 链路，优先核查模型无结果或低置信、候选为空、规则全部拦截、LLM
拒绝准出、结果过期、服务异常、用户不操作及选择后实际执行不一致。

## 5. Rule Trace

出现重要规则时，立即记录，但不一定马上深挖。

只有当该规则会改变：

- 策略合理性；
- 风险判断；
- 个人贡献；
- 面试可信度；

才立即追问。

否则留到 Pass H 集中审计，避免访谈被大量低价值参数打断。

## 6. 故事提取

### 失败故事

先执行 `Personal Failure Gate`。强失败故事必须形成：

`我的判断 / 动作 / 遗漏 → 明确负面影响 → 我参与修正 → 新的工作方法`

并确认：

- 用户本人判断或动作的真实失误；
- 可说明后果；
- 有修正；
- 有责任边界；
- 有形成的新方法。

若只有“项目出现负向结果 → 用户事后认为评测或方案可更完善”，将其标为项目未达预期、风险暴露或
项目复盘，不得直接写成“我犯的错误”。继续执行 Story Recovery 搜索更强个人失败；搜索耗尽后可以
保留边界清晰的未达预期型回答，但必须说明：

> 这个结果不一定是由我的方案直接造成的，我需要承担的主要问题是……

没有修正结果时如实写“提出了复盘方案但未参与后续验证”，不得把建议写成已完成修复。

### 冲突故事

必须存在真实分歧：

`双方诉求 → 核心争议 → 用户如何拆解 → 最终取舍`

### 核心决策

重点不是“我拍板”，而是：

`决策问题 → 判断标准 → 备选 → 用户做出的核心判断 → 团队最终选择`

用户没有最终拍板权时必须如实表达“我提出/推动/参与收敛”。

### 跨团队协作

至少说明：

- 为什么必须多团队；
- 依赖和阻塞；
- 用户如何串联；
- 结果。

## 7. Canonical Placement Pass

主题事实稳定、准备输出《细节复原稿》时，完整执行 `detail-reconstruction-schema.md` 中的
`Canonical Content Placement Rules`、`Content Placement Check` 和“匿名目录测试”。本 Pass 只重排内容，
不重新生成事实，也不把 `unknown`、`recovery-exhausted`、个人责任边界或归因限制改写成确定结论。

重点检查：

- 第一章的状态、异常与 fallback 是否嵌入历史机制，本人角色是否只作概述；
- 第三章指标是否只分为结果指标和链路指标；
- 第四章每个策略是否回收到痛点、具体动作、ownership、故事四个直接子块；
- 第五章是否只有实验设计、最终收益结果、ownership 三个核心模块，Matrix 和 Failure Gate 是否归位；
- 第六章每个方向是否只保留问题、方案、价值 / 取舍、重点关注四个直接子块；
- 隐去项目专名后，目录是否仍是同一套八章母版。

同时为每个高价值事实写入内部 `Fact Ownership Map`，按“事实主要回答什么问题”确定唯一 Primary Home。
第四章只保留方案机制、设计理由、验证思路和个人动作；第五章完整承载实验样本、周期、分流、对照、
数字、显著性、护栏、归因和最终判断。

## 8. Deduplication 与 Publication Hygiene

成稿后依次执行：

1. **Deduplication Pass**：扫描数字、实验、规则解释、贡献、项目结论和信息缺口；Primary Home 保留完整
   版本，其他章节删除或压缩为一句引用。高价值数字超过两次时强制复核。故事可以短引必要结果，不能
   复制结果分析。
2. **Publication Hygiene Pass**：扫描 Gate、Pass、Recovery、Audit、Matrix、Ledger、内部事实状态和
   “Agent/Skill 如何判断”的元话语，转换为正常项目表达。业务真实术语除外。

内部机制名称删除后，必须再次确认因果边界、个人责任边界、实验能与不能证明什么以及事实不足仍然
存在。清洗不等于弱化严谨性。

## 9. 主题完成条件

背景完成：

- 问题如何发现；
- 2–3 个核心问题；
- 每个问题有证据；
- 归因知道到什么程度。

策略完成：

- 痛点；
- 机制；
- 规则；
- 个人边界；
- 验证；
- 故事（有则写）。

实验完成：

- 假设；
- 每个重要结果的 Treatment / Control；
- 分流；
- 人群与周期；
- 实验类型；
- 指标；
- 结果；
- 归因边界；
- Cannot Prove；
- 护栏。

复杂状态链完成：

- 每层输入、正常输出和关键失败已知；
- 结束、重试、降级、人工或用户确认路径已知或明确 unknown / non-owned；
- 超时、过期、冲突和最终决策权已扫描。

故事完成：

- 失败、冲突、核心决策、跨团队协作已有真实故事；或
- 对缺失类别完成 Story Recovery，且用户明确确认没有、不记得或事实不足；
- 失败故事已通过 Personal Failure Gate，或明确降级为未达预期型回答。

第八章完成：

- 所有重要但来源未知的规则/结论已经扫描。

内容归位完成：

- 已执行 Content Placement Check；
- 已执行匿名目录测试；
- 发现与审计机制没有变成额外平级章节；
- 重排前后的确认事实、Unknown、Matrix、状态/fallback 和责任边界均完整保留。
- 已为高价值事实指定唯一 Primary Home；
- 已完成 Deduplication Pass 和 Publication Hygiene Pass；
- 最终正文不含内部机制名称、状态标签或 Agent 元话语。

## 10. 停止条件

不按问题数量停止。

复杂经历可以持续多轮。

只有关键事实：

- 已确认；
- 有证据支持；
- 明确 unknown；
- 明确非本人职责；

四者之一成立后，才允许结束对应主题。

该停止规则不允许绕过 Story Recovery：文档主线稳定但四类故事缺失时，必须先搜索真实事件。对同一
故事入口连续两次无法新增事实，或用户明确表示没有 / 不记得 / 事实不足时停止该入口，记录边界，
不换一种暗示继续逼问。
