# 经历深挖思考与回答组织 V3.3

所有内容完全服从 `detail-reconstruction-schema.md` 与
`interview-transcript-generation.md` 的双阶段结构：前者维护事实，后者只组织表达。

## 核心目标

不要把经历整理成“STAR 填空”。

Agent 的任务是把用户自然讲述还原成：

`问题 → 证据 → 原因 → 目标 → 策略 → 机制 → 规则 → 实验 → 结果 → 风险 → 未来优化 → 认知`

并持续审计：

- 这个结论为什么成立；
- 这个规则为什么这么定；
- 用户到底做了什么；
- 最终结果是否真的能归因。

内部同时维护事实与所有权 Ledger、Experiment Attribution Matrix、端到端状态链，以及失败/冲突/
核心决策/跨团队协作的故事覆盖状态。它们用于选题和查漏，不新增正式文档章节。

始终分开两个问题：

1. **发现问题**：依靠深挖 Pass、Evidence Ledger、Story Recovery、Failure Gate、Matrix 和状态链判断
   还缺什么事实；
2. **存放问题**：依靠 Canonical Schema 决定事实进入哪一章、哪一父节点以及是否只能作为正文。

不得因为某个发现机制重要，就为它创建平级正式章节。内容足够复杂时可以在 Canonical 父节点内继续
细分，但不能改变八章母版、第三章双指标体系、第四章四块策略结构、第五章三模块或第六章四块结构。

## 双层表达

Analysis Layer 可以复杂，保留 Gate、Pass、Matrix、Ledger、Audit 和事实状态。Publication Layer 不复述
分析过程，只把判断翻译为项目语言：是否有故事→故事或“材料不足”；能否归因于本人→个人责任边界；
实验比较关系→实验正文或人类可读归因表；异常链路→核心状态与异常流程；可信度→事实与证据边界。

为每个高价值事实内部维护 `Fact Ownership Map`。根据事实主要回答的问题确定唯一 Primary Home；其他
章节只能短引，不得再次完整展开。尤其把实验样本、周期、分流、Treatment/Control、结果数字、显著性、
护栏和最终判断完整放在第五章；第四章只写评测为何设计、各层解决什么问题和本人做了什么。

## 选下一题

每次只选择一个高价值缺口。

优先级：

`真实性风险 > 因果缺口 > 个人贡献 > 实验归因 > 状态链/fallback > 故事素材 > 策略机制 > 规则来源 > 低价值参数`

主线已经稳定但四类故事仍缺失时，暂时把 Story Recovery 提升到最高优先级。一次只沿一个已经出现的
团队、评审、异常、结果或方案变化搜索真实事件；用户明确没有、不记得或事实不足后才停止。

## 五类内容必须分离

1. 项目当时真实事实；
2. 当时真实决策依据；
3. 当前合理解释；
4. 如果重来会怎么做；
5. 仍未知/冲突。

特别禁止：

“现在觉得这个阈值合理”
→ 写成
“当时基于这个逻辑定了阈值”。

同样必须分离：

- “项目出现负向结果”与“用户的判断直接造成负向结果”；
- “用户提出复盘建议”与“用户完成修正并验证”；
- “多个实验共同支持判断”与“这些数字属于同一严格因果链”。

## 实验和状态链

任何重要实验数字先回答“谁与谁比、比了什么人群和周期、属于什么实验、能与不能证明什么”，再决定
是否进入主线。Treatment 或 Control 不清楚时优先追问，不自行补组别含义。

出现三个及以上相互依赖阶段时，沿输入、正常输出、失败、结束/重试/fallback、超时/过期、状态冲突、
最终决策权还原链路。未知实现保留 unknown / non-owned，不用行业常识补齐。

## 策略产品专项思路

优先建立：

`业务目标 → 问题归因 → 策略假设 → 策略机制 → 链路指标 → 结果指标 → 护栏 → 外部性`

重点追：

- 中间指标是不是最终目标；
- 策略是否有资源挤占；
- 是否存在共享供给；
- 单策略和组合实验；
- 是否真的产生增量；
- 收益和约束之间如何取舍。

## 中台/平台型经历专项思路

当经历涉及多个业务共用的：

- 分单；
- 计价；
- 判责；
- 权限；
- 状态；
- 补偿；
- 订单；
- 公共能力；

优先追问：

- 这是公共能力还是局部业务逻辑；
- 历史规则为什么存在；
- 哪些业务依赖；
- 修改影响哪些上下游；
- 异常状态如何恢复；
- 是否应该改平台规则，还是缩小局部方案。

## 表达层

事实复原阶段不追求口语漂亮。

面试逐字稿阶段只做：

- 选材；
- 排序；
- 压缩；
- 口语化。

压缩后执行 Question Relevance Gate：删除不直接回答当前问题、但更适合其他题或追问的信息。宁可留下
追问钩子，也不把事实主档压成两分钟项目报告。

绝不能在表达阶段新增事实。

细节复原稿进入表达层前，先把全部事实映射到 `detail-reconstruction-schema.md`，执行 Content Placement
Check、Deduplication Pass、Publication Hygiene Pass 与匿名目录测试。去重时保留 Primary Home 完整版本；
故事只短引必要结果。清洗内部词汇和元话语时必须保留事实、因果、责任与证据边界。
