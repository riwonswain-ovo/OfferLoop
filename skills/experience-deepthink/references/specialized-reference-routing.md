# 专项 Reference 路由

只在经历确实出现相应产品机制时加载专项 reference。不要因为目标岗位名称包含“AI”，或用户只使用过
通用 AI 工具，就批量加载所有专项。

## AI 与算法项目

经历确有 AI、算法、Agent、RAG、Workflow 或 AI Coding 等机制时，先读取：

- `project-playbooks/ai-technology-application.md`

再根据项目中真实存在的机制选择最小专项：

- Agent 或 Skill 产品：`project-playbooks/ai-agent-skill-products.md`；
- 会创建、修改或发送业务对象的 Agent：`project-playbooks/ai-action-agent-products.md`；
- 审核、风控或质检：`project-playbooks/ai-audit-products.md`；
- RAG 或知识库：`project-playbooks/ai-rag-knowledge-products.md`；
- 上下文或记忆：`project-playbooks/ai-context-memory-products.md`；
- Prompt 或工作流编排：`project-playbooks/ai-prompt-workflow-products.md`；
- 工具生态：`project-playbooks/ai-tool-ecosystem-products.md`；
- 模型训练：`project-playbooks/ai-model-training-products.md`；
- AI Coding 产品交付：`project-playbooks/ai-coding-product-delivery.md`。

通用产品视角始终由 `role-playbooks/product.md` 提供。专项 reference 只补充对应机制的判断与追问，不
替代七阶段对话流程，也不改变固定八章和固定七题结构。

专项 reference 中对贡献、技术边界和证据强度的要求只用于内部验真与追问选择。成稿时只正向写用户和
协作方实际完成的动作；未知或未参与的部分按输出规范省略或集中归入第八章，内部验真过程不进入正文。
