# MCP / A2A / 工具生态类 AI 产品经历深挖

本参考只在经历真实涉及 AI API 产品接入、MCP、A2A、Function Call、插件平台、跨模型工具
接入、跨 Agent 协作或外部系统读写时加载。普通 API 经历重点验证接口契约和产品闭环；协议
经历重点验证为什么需要协议、工具契约与生产治理。只使用实际命中的部分，不考察无关协议字段。

## 1. 先判断连接对象

先区分实际连接的是：

- **确定性工具或数据源**：输入相对明确、执行后返回结果；
- **有独立判断的 Agent**：可能追问、拒绝、长时间运行并经历多次状态变化。

再判断交互是一次请求还是异步多轮、是否需要任务状态和中间产物。由此解释为何选择普通 API、
Function Call、MCP、A2A 或混合方式。协议“更先进”或“更标准”不能作为唯一理由。

### 普通 API 接入的真实性

即使没有 MCP 或 A2A，只要经历核心是 AI API 接入，也要还原最小端到端链路：

`业务输入 → 请求契约（地址/认证/模型/参数/Schema） → 模型响应 → 校验与后处理
→ 下游产品动作`

分别确认：

- 在聊天网页中得到回答；
- 程序通过 API 成功收到响应；
- 响应经结构化校验、异常处理和业务规则进入真实产品流程。

三者证据强度不同。“调通接口”只证明连接，不证明产品完成、质量可用或业务闭环。用户未亲自
编码时，继续深挖其定义的输入输出、验收标准、异常流程、权限边界和跨团队推动。

接入失败或质量异常时，优先从官方最小示例验证地址、认证、模型、请求格式和连通性，再一次只
改变一个变量定位问题。先区分配置/格式、网络/权限、限流/服务、响应解析、模型能力和产品逻辑，
不得把所有失败都归因于“模型不行”。涉及实时字段和版本时以项目当时官方文档为准。

## 2. 工具契约三分离

把以下三层分别还原：

1. **工具存在**：全量注册了哪些能力；
2. **模型可见**：当前任务为什么只暴露其中一部分；
3. **运行可执行**：身份、权限、风险和环境是否允许真正执行。

继续追问工具描述、输入输出 Schema、错误格式、只读/写入属性、并发安全、破坏性等级和版本
兼容。重点寻找工具过多导致误选、Schema 不一致、模型选对但执行被拒绝等真实案例。

## 3. 权限与渐进信任

涉及真实读写时确认：

- 默认权限、最小授权和授权范围；
- 何时弹出确认，是否支持本次/长期授权；
- 高风险参数是否二次展示；
- 身份、租户、数据和产物是否隔离；
- 谁、在何时、调用了什么、结果如何是否可审计；
- 越权、提示注入或伪造 Agent 身份时如何拒绝。

不能把模型“承诺不会调用”视为权限机制。用户未负责安全实现时，转向其定义的交互、范围、验收
和跨团队推动。

## 4. MCP 产品化

若使用 MCP，深挖其真实增量：

- 相比逐个 API 集成，减少了哪些重复接入、迁移或维护成本；
- Resource、Tool 或 Prompt 暴露了什么，为什么这样划分；
- 能力发现、认证和配置如何完成；
- 超时、重试、限流、熔断和服务不可用如何处理；
- Server 版本、兼容、灰度、回滚和供应链审计如何治理；
- 公共 Server、自建 Server 和传统 API 如何取舍。

协议接通只证明技术连通，不证明用户任务完成。

## 5. A2A 与多 Agent 生命周期

若协作对象是 Agent，追问：

- 为什么需要拆成独立 Agent，而不是一个 Agent 或普通工具；
- 对方的能力、认证、输入输出和服务边界如何发现；
- 任务如何经历提交、执行、追问、完成、失败或取消；
- 中间消息与最终 Artifact 如何区分；
- 最大轮次、超时、Token/成本预算和部分结果返回；
- Agent 冲突、级联失败和下游不可用时如何降级。

拆分的主要价值应落在专业边界、上下文/权限隔离、独立迭代或长任务协作，而不只是“并行更多”。

## 6. 评测与业务价值

根据经历确认：

- 工具选择和参数正确率；
- 调用成功率、端到端完成率与人工接管率；
- 认证失败、超时、重复调用和错误写入；
- 时延、成本、迁移效率和维护负担；
- 多 Agent 任务完成、冲突率和取消/恢复能力；
- 协议接入是否真正改善用户任务或业务流程。

所有提升必须有真实基线和口径。匿名课程案例、生态规模、推荐超时和限流数值不能作为默认事实。

## 7. 追问选择

优先追问协议选择背后的连接对象和交互模式、一次真实工具或协作失败、一次权限/兼容决策，以及
协议接入到业务价值之间的连接。若候选人只在平台上勾选现成插件，重点深挖其场景、工具选择、
权限体验和验收，不冒认 Server 或协议实现。
