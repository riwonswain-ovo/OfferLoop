# 行动型 Agent 产品经历深挖

本参考只在 Agent 会查询私有业务数据，或会创建、修改、发送、发布、审批、分配、关闭等
改变外部系统或业务对象状态的经历中加载。纯问答、只读公开检索和不落地的生成草稿不触发。

它用于检查自然语言理解怎样被约束为安全、可恢复、可审计的业务动作；每轮只追一个最高风险
或最能证明个人产品判断的缺口。

## 目录

1. 产品形态与人机介入
2. 业务对象—状态—动作
3. 身份、权限与数据范围
4. 意图—槽位—草稿—确认—执行
5. 审计、失败恢复与幂等
6. 数据—风险—可执行动作闭环
7. 高风险失败关闭与追问优先级

## 1. 产品形态与人机介入

先按真实任务选择交互，而不是因为使用大模型就默认聊天框：

- 单次咨询或轻量追问可使用对话；
- 批量选择、比较、编辑、审核、重跑和发布更适合工作台；
- 需嵌入原系统的局部辅助可使用插件或侧边栏；
- 系统间稳定调用可提供 API；
- 高风险写入应使用可检查的表单、卡片或审批界面承载确认。

追问用户在哪一步看见计划、补充信息、修改草稿、批准动作、检查结果和撤销。若产品形态无法
承载这些动作，Agent 架构再复杂也没有形成可用的人机协作。

## 2. 业务对象—状态—动作

先确认 Agent 操作的真实对象，例如工单、邮件、任务、合同、订单、审批或报告。对每个关键
对象说明：

- 字段和必填信息；
- 允许存在的状态；
- 各状态允许的动作和操作者；
- 动作发生后的字段与目标状态；
- 非法转换、并发修改和重复提交如何处理。

状态机必须由后端或确定性业务逻辑强制执行，不能只存在于对话历史，也不能让模型凭自然语言
决定某个状态转换是否合法。

## 3. 身份、权限与数据范围

行动权限至少由认证身份、组织/租户/项目和角色共同决定。继续确认：

- Agent 使用的是谁的身份，用户自报身份是否会被采信；
- 只读、草稿、写入、审批和管理权限如何分级；
- 记录级数据范围在哪一层过滤；
- Prompt、模型可见工具和运行时实际权限是否分离；
- 越权请求由前端、工具层还是后端拒绝，拒绝是否可审计。

隐藏页面不等于数据权限；模型承诺“不调用”也不是权限机制。

## 4. 意图—槽位—草稿—确认—执行

把对话动作拆成：

`识别意图 → 提取必填槽位 → 追问缺失或冲突 → 生成可编辑草稿 → 展示将发生的变化
→ 有权限用户确认 → 工具执行 → 返回结果`

重点检查：

- 知识咨询、业务查询、写入请求和混合意图是否分流；
- 模型能从上下文提取什么，哪些字段必须由用户选择；
- 不确定信息是否显式标记，而不是静默猜测；
- 用户能否修改、取消和理解确认内容；
- 一句话同时包含“判断 + 执行”时，是否先完成有证据的判断，再单独确认动作。

人工确认不是在回答末尾写“请复核”，而是由有权限者在执行前看见关键字段、副作用和撤销
方式，并作出明确决定。

## 5. 审计、失败恢复与幂等

每次真实状态变化应能还原：

`谁 / 代表谁 → 何时 → 基于什么输入与确认 → 调用了什么 → 旧值与新值 → 结果与失败原因`

区分运行日志和业务审计：日志用于调试，审计用于责任、合规和过程还原。

继续追问：

- 超时或未知结果时怎样判断是否已执行；
- 重试如何避免重复建单、重复发送或重复扣费；
- 部分成功怎样展示和补偿；
- 失败后是否保留用户已填内容；
- 哪些动作可撤销，哪些只能补偿或升级人工；
- 长任务是否有检查点、局部重算和恢复入口。

## 6. 数据—风险—可执行动作闭环

行动型 AI 的价值不能停在“回答很专业”。检查是否形成：

`可信数据 → 当前状态 → 风险或机会判断 → 有依据的策略 → 可执行业务对象 → 状态追踪`

策略至少应能绑定对象、证据、责任人、时限、资源、前置条件和完成标准。像“加强沟通”
“合理安排时间”这类可复制到任何项目的建议，不构成可执行闭环。

最终成功不能只看工具返回 200 或 Agent 声称完成，还要检查业务对象是否正确改变、用户是否
完成任务、错误是否被发现和处理。

## 7. 高风险失败关闭与追问优先级

当动作依赖规范、医疗、法律、财务或企业制度等权威知识时，知识服务为空、冲突、过期或超时，
不得静默退回模型预训练记忆并继续执行。先明确：

- 哪些情况必须拒绝、追问、重试或转人工；
- 哪些低风险说明允许降级，以及如何向用户标记非权威性；
- 谁拥有最终决定权和专业责任；
- 权威来源、版本和调用状态是否进入审计记录。

优先追问：

1. 最不可逆或错误代价最高的动作；
2. 权限和状态机是否由系统强制；
3. 一次真实误理解、重复执行或部分失败；
4. 人工确认是否真正发生在执行前；
5. 业务对象是否形成可追踪结果，而不只是生成文本。

## 边界

- 纯只读公开问答不要求完整写入状态机，但仍需来源、访问范围和失败降级。
- 预授权自动化可以减少逐次确认，但必须说明范围、额度、时窗、监控和撤销/补偿。
- 用户只配置现成平台时，重点深挖其定义的业务对象、权限、交互、验收和异常，不要求冒认
  底层鉴权、幂等或存储实现。
