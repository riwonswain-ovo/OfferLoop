# 能力训练答案就绪门

## 核心原则

判断“是否问够了”看的是**决策完整性**，不是维度数量，也不是是否覆盖所有
可能性。只要仍有一个未回答的关键问题可能改变结论、优先级或方案，就没有
就绪；如果新增内容只会增加例子和细节，不会改变判断链，就应停止追问。

本门槛控制的是何时继续追问、何时让用户正式作答、何时公开 Agent 参考答案，
以及何时生成最终答案。不得因为对话轮数、用户篇幅或提到很多关键词而放行。

## 四种状态

### `not_ready`

任一硬门槛缺失。只指出最影响结论的一处缺口，提出一至两个非诱导追问。
不得替用户补齐逻辑，不得生成完整答案。

### `ready_for_formal_answer`

用户的原始材料已经具备决策完整性，可以让用户先独立组织第一版自上而下的
正式答案。此时 Agent 仍不得代写或公开参考答案。

### `ready_for_reference`

用户已完成第一版正式答案，且能在一至三分钟内清楚表达主张、理由和必要
边界。此时才可公开冻结的 Agent 参考答案并做差异诊断。

### `ready_for_finalization`

用户完成差异诊断、方法卡和二次作答，并修复本轮决定性缺口。此时 Agent
才可综合生成最终参考答案、1 分钟版、3 分钟版和训练文档。

## 七项硬门槛

判断 `ready_for_formal_answer` 时逐项检查；任一决定性缺失都保持
`not_ready`，不要算总分。

1. **直接结论**：明确回答主判断任务；需要条件时，结论带必要成立条件。
2. **同层支撑**：有二至四个使用同一关系或划分标准的理由，能够共同推出
   结论，而不是把原因、结果、例子和方案混在一层。
3. **因果闭环**：每个决定性理由至少形成
   `事实或假设 → 作用机制 → 对目标的影响`。
4. **关键变量已处理**：没有遗漏会反转结论的参与方、业务阶段、约束、
   口径或前置条件。
5. **取舍有依据**：说明为什么当前因素、方案或顺序优先于主要替代路径，
   不用“需要平衡”代替决策。
6. **证据身份清楚**：区分事实、用户观察、作者观点、假设和推断；已处理
   与结论冲突的重要证据，或明确说明待验证。
7. **边界可以验证**：至少有一个与核心主张相连的反方、失败条件、适用边界、
   反事实或最小验证方式。

不是每题都必须说满七项。若某项对本题不决定结论，可标记“不适用”并说明
原因；不能用“不适用”跳过可能翻转结论的变量。

## 题型附加就绪条件

在七项硬门槛之外，只检查主判断任务对应的一组：

- **机制解释**：说清被改变的用户行为或利益，并说明没有该机制时会怎样。
- **比较与定位**：使用共同基准，指出最决定结果的差异及其来源。
- **商业与策略**：明确业务阶段、目标和关键约束；按需处理单位经济、
  回收期、规模、弹性或生态代价，不能只报 ROI。
- **产品或场景设计**：明确目标用户、关键场景、优先问题、方案对应关系和
  成功信号。
- **优先级与取舍**：说明排序标准、机会成本和条件变化后何时改选。
- **指标异动**：先确认是真异常，再给主要贡献环节、核心假设和验证顺序，
  不能只列原因清单。
- **费米估算与行业研究**：定义范围、口径和方程，保持单位一致，暴露敏感假设，完成数量级
  或独立路径校验，并说明估算结果支持什么产品或业务决策。
- **AI 产品**：明确被解释的产品或竞争现象，说明 AI 能力变化如何改变用户
  行为、成本、控制权或参与方利益；指出价值迁移到哪里、优势为何可积累或
  被复制、主要竞争回应，以及一个会让结论反转的条件。技术实现细节不替代
  这些判断。

## 每轮运行方式

1. 把用户当前回答拆成原子判断。
2. 对照主判断任务，逐项检查七项硬门槛和一组题型附加条件。
3. 找出**最可能改变结论**的缺口，而不是最容易补的缺口。
4. 若存在该缺口，标记 `not_ready`，只问一至两个问题。
5. 用户补充后重新从主判断检查，不机械沿用上一轮标签。
6. 若所有决定性缺口均关闭，立即停止横向扩展，标记
   `ready_for_formal_answer`，让用户自行完成正式答案。

追问必须由用户已说出的内容触发。不要把 Agent 底稿的维度改写成问题逐项
喂给用户，也不要为了“显得全面”遍历利益相关方清单。

## 停止追问测试

在进入正式答案前，内部做两问：

1. **翻转测试**：现在是否还有一个合理答案，能在不增加冷门事实的情况下
   推翻用户的结论或优先级？若有，缺口是什么？
2. **增量测试**：下一次追问会改变结论链，还是只会增加例子、措辞和背景？
   若只增加细节，停止追问。

只有翻转测试无未处理的决定性变量，且增量测试显示继续追问收益很低时，才
进入 `ready_for_formal_answer`。

## 正式表达与生成权限

- 第一版正式答案须由用户先说，Agent 只做结构检查。
- 若第一版仍无法在一至三分钟内先结论后论证，保持
  `ready_for_formal_answer`，只指出一个表达结构问题，不公开参考答案。
- 第一版达到表达要求后标记 `ready_for_reference`，再公开冻结底稿。
- 二次作答若仍未修复决定性缺口，不生成“最终优化版”替用户掩盖问题；
  继续一次针对性修订或按用户要求保存为 `incomplete`。
- 只有 `ready_for_finalization` 才生成 Agent 最终参考答案及 1 分钟、3 分钟版本。

## 典型判例

- `商业化就是在收入和体验之间找平衡。`
  `not_ready`：没有业务阶段、目标、作用机制、优先级和护栏；维度虽正确，
  但无法支持决策。
- `留存下降可能是产品、用户、渠道、竞争和季节性。`
  `not_ready`：只是原因清单，未确认异常、定位主要贡献或给验证顺序。
- `当前处于验证付费意愿阶段，因此先向高频刚需用户测试会员；它通过节省
  明确时间创造付费价值，但用频次门槛控制对低频用户的伤害。若试点组的
  留存下降超过收入增益，或回收期超过目标周期，就不扩大。`
  若其他关键事实不冲突，可视为 `ready_for_formal_answer`：已有条件化结论、
  机制、取舍和证伪信号；继续补更多商业化名词不会改变主判断。
