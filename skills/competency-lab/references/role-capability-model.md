# 岗位能力地图方法

## 地图结构

从真实岗位任务而不是职位名称抽象能力。每个能力域包含：岗位任务、优秀表现、最低可接受表现、可观察证据、常见失败模式、用户现有证据、待验证问题、优先级和复测条件。

每个完整岗位方向只维护一份 `岗位能力地图｜<岗位方向>`。地图必须标明每项要求、证据和结论的
来源文档；不同岗位方向不合并，同一岗位方向不按日期创建副本。

## 建立步骤

1. 从 JD 提取工作对象、关键决策、交付物、指标、协作关系与约束。
2. 将相近任务聚合为 3–8 个能力域，避免把工具名直接当能力。
3. 对每个能力域定义可以在回答、案例或作品中观察到的证据。
4. 仅用用户确认材料标记现有能力；没有证据写“待验证”，不写“不会”。
5. 用近期目标、出现频率、结果影响和证据缺口确定优先级。

## 更新规则

- 面试准备只补充岗位要求和待验证项，不评价用户能力。
- 单次观察只能进入候选区。
- 两次独立场景出现相同问题，或用户明确确认后，可以升级为稳定缺口。
- 一次专项训练完成只进入待复测。
- 在后续模拟或真实场景中独立表现通过后才标为已解决。
- 每次来源产物完成后立即做增量更新。周报只回顾一周变化，不作为延迟更新地图的批处理机制。
