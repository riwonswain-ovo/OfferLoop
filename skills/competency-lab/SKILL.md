# Competency Lab

把目标岗位需要的能力、用户已有证据和待验证缺口连接成可持续训练闭环。训练仍以用户独立初答、非诱导追问、方法提炼、二次作答和复测为核心；原产品 Sense 方法作为产品经理岗位模板保留，而不是整个 Skill 的边界。

运行相对路径前先从当前 `SKILL.md` 定位 Skill 根目录。

## 用户画像前置门禁

本 Skill 的第一项动作是完整读取
`../.offerloop-runtime/references/profile-gate.md` 并执行用户画像前置门禁。必须在读取本 Skill
其他参考、询问训练方向、生成题目、读取能力观察或写入训练产物前完成。画像为 `missing` 或
`empty` 时不得启动本 Skill，转由 `career-profile` 一次只问一个问题并自动保存；门禁通过后
才返回本次岗位能力训练。

## 开工前材料路由

| 场景 | 必须读取 | 缺失时 |
|---|---|---|
| 首次训练某岗位 | 用户画像、目标岗位/JD；若无岗位能力地图则先建立 | 只追问当前必需的岗位信息 |
| 根据模拟或真实面试补弱项 | 用户画像、岗位能力地图、未解决 `AbilityObservation`、来源复盘 | 唯一匹配自动读取；零个、多匹配或冲突时再询问 |
| 继续历史训练 | 用户指定的训练文档、关联能力观察 | 找不到时停止延续，不猜“最新版” |
| 每日三题 | 用户画像、岗位能力地图、未解决观察、近期面试安排、近 30 天训练历史 | 缺项时使用其余已确认材料并标明降级 |

开始实质训练前，用一句话列出本轮实际读取的材料。未读取到表中明确必需的材料时，不得声称已经完成岗位化训练。OfferLoop 私有知识空间中唯一匹配的材料可直接读取，不要求用户重复粘贴。

## 岗位能力地图

每个完整岗位方向只维护一份长期文档，标题为 `岗位能力地图｜<岗位方向>`。不同岗位方向分别维护，
不得把多个岗位方向合并到同一文档，也不得为同一岗位方向按日期重复新建。

未存在地图时，根据岗位名称、JD、用户目标和已有面试材料建立 3–8 个能力域。每个能力域记录：

- 能力名称、岗位任务和可观察证据；
- 当前证据与来源；
- 待验证缺口和错误模式；
- 优先级、近期训练目标和复测条件。

岗位未命中模板时直接从真实 JD 抽象，不要求用户改选相近岗位。模板不能覆盖 JD 和用户确认。

地图由 `competency-lab` 统一写入，并按来源区分更新权限：

- `interview-prep` 只更新岗位要求、本轮面试重点和待验证能力，不形成个人强弱结论；
- `mock-lab` 更新有具体回答证据的模拟表现与候选缺口；
- `talk-review` 更新有真实面试证据的表现、缺口和追问信号；
- 本 Skill 的专项训练更新训练进度、方法掌握情况和复测状态。

相关 Skill 每次完成并保存产物后，立即触发对应岗位地图的增量更新，不等待定时任务。周报是独立的
回顾产物，只汇总一周内的变化、证据、训练与下周重点，不代替或延迟岗位能力地图更新。

## 能力观察联动

消费统一 `AbilityObservation`：

- `source_skill`、`source_artifact_url`、`source_run_id`；
- `role_direction`、`competency_tag`；
- `observed_behavior`、`evidence_summary`、`gap`；
- `confidence`、`suggested_training`；
- `status`：`candidate`、`confirmed`、`dismissed`、`training`、`retest`、`resolved`。

单次表现默认是 `candidate`。它可以影响下一批题目的权重，但只有用户确认或多次独立证据一致后才能写入稳定画像。用户可纠正或忽略观察。

## 训练流程

1. 选择最高优先能力缺口，说明本题与哪条证据或岗位任务相关。
2. 只给回答所需的中性事实，让用户独立初答；初答前不泄露框架或参考答案。
3. 每轮只追问一个最影响结论的缺口，同一缺口最多连续追问三次。
4. 达到答案就绪门后，让用户完成第一版正式答案，再展示参考思路和证据。
5. 对照用户答案与参考路径，区分合理差异、证据不足和方法问题。
6. 提炼可迁移的方法卡，并要求二次作答。
7. 完成后把观察标为 `retest`；只有后续独立场景验证通过才标为 `resolved`。

`mock-lab` 负责真实模拟，本 Skill 负责拆解训练。不得把专项训练伪装成完整模拟面试。

## 每日三题

每日生成三题，不要求固定为产品题型。按以下权重动态分配：

1. 已确认且临近面试相关的短板；
2. 待复测能力；
3. 长期未训练的岗位核心能力；
4. 已连续验证通过的能力降权。

同一批题尽量覆盖不同能力域；30 天内不重复同题。题目必须说明训练目标，但不得在题干泄露解题框架。用户拒绝题目时记录原因并用于下一批降权。

当天三道题固定写入一份 `每日三题｜<日期>`，保存到
`05｜岗位能力与训练/每日三题`。该文档只保存题目、必要的中性背景、训练目标和来源，不保存用户答案、
诊断或参考答案；工作台仍可保留同一题单入口，但不能替代知识库文档。

## 专项训练归档

每道完成训练的题目单独保存为一份 `训练题｜<题目名称>`，不得把一天三题的答案合并到每日题单。
先按本题的主要训练目标选择且只选择一条归档路线：

- 方法论训练：可迁移的判断、拆解、设计、估算、归因或表达方法，保存到
  `05｜岗位能力与训练/专项训练/方法论训练/<对应方法论文档>/训练题｜<题目名称>`；
- 行业认知训练：特定行业的参与方、业务链路、供需结构、盈利模式、竞争、监管或关键指标，保存到
  `05｜岗位能力与训练/专项训练/行业认知训练/<对应行业认知文档>/训练题｜<题目名称>`。

方法论或行业认知主文档本身是可编辑飞书云文档，也是训练题的父节点。唯一匹配时复用，零匹配时
自动创建并写入当前已确认的方法或行业认知，多匹配时让用户选择。题目同时涉及方法与行业时按主要
训练目标归入一处，不复制答案文档；无法确定主要目标时询问用户。每日三题文档与训练题文档互相链接。

## 岗位能力周报

每周生成一份覆盖本周所有岗位方向的 `岗位能力周报｜<开始日期>—<结束日期>`，保存到
`05｜岗位能力与训练/周报`。周报汇总本周完成的面试准备、模拟面试、真实面试复盘和专项训练，
列出各岗位方向新增或变化的证据、待验证问题、稳定短板、已训练与待复测能力，以及下周优先事项，
并链接来源产物和岗位能力地图。周报每周新建，不覆盖历史；未配置具体自动化时间前不得声称会自动生成。

## 完成与保存

保存前读取同级隐藏目录 `../.offerloop-runtime/references/artifact-contract.md`，按其固定目录、标题和幂等规则处理。

- 岗位能力地图固定保存为 `05｜岗位能力与训练/岗位能力画像/岗位能力地图｜<岗位方向>`。
- 每日题单固定保存为 `05｜岗位能力与训练/每日三题/每日三题｜<日期>`。
- 每道训练题按主要训练目标保存到对应方法论或行业认知主文档下，标题为 `训练题｜<题目名称>`。
- 周报固定保存为 `05｜岗位能力与训练/周报/岗位能力周报｜<开始日期>—<结束日期>`。
- 完整结束保存 `completed`；暂停、时间到或提前结束保存 `incomplete`，保留已完成内容、缺口与续训清单。
- 岗位能力地图、每日题单、逐题训练文档和周报分别按上述固定路径保存。遵循共享契约的自动保存、
  同名更新和用户显式例外规则，并返回知识库路径和 URL。
- 保存失败时在对话交付完整 Markdown；不得声称已写入飞书。

训练结果同时更新对应能力观察状态和人类可读岗位能力地图，不新增业务 Base。

## 边界

- 不把单次回答失误永久贴标签。
- 不为迎合 JD 编造经历或能力证据。
- 不在用户初答前给标准答案。
- 不把技术知识题包装成业务判断题；岗位确实需要技术理解时按真实任务训练。
- 不生成发布文章、图片、HTML 或 ZIP。
