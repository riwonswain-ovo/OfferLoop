# Case 面试运行模式

本模式用于咨询、战略、商业分析、产品、运营和数据岗位中的现场 Case。它规定面试怎样分阶段
运行，不规定某个岗位应该重点考什么。

## 启用条件

- 用户选择 Case、商业分析题、Market Sizing、情境分析或类似专项；
- 或 JD 明确包含现场问题拆解、估算、图表分析或商业案例。

加载本模式后仍需按目标岗位加载相关 Playbook。没有匹配 Playbook 时，根据 JD 建立能力主线。

## 运行状态

一场 Case 按需经过以下阶段：

```text
背景与任务
→ 澄清
→ 结构与优先级
→ 分析与数据
→ 条件变化或反证
→ 综合建议
```

不是每轮都必须展示全部阶段，但不得在同一条消息里同时给出背景、全部数据、追问和答案。

## 各阶段规则

### 1. 背景与任务

- 给出完成任务所需的最少背景、角色、目标和约束。
- 明确用户当前只需要做什么，例如提出澄清问题或给初步结构。
- 公司名、数据和业务情境可以虚构或泛化；不得声称来自真实内部案例。

### 2. 澄清

- 一次回应用户当前提出的澄清，不主动补全所有遗漏。
- 用户没有澄清关键目标时，可中性追问其准备先确认什么。
- 澄清阶段不评价结构好坏，也不暗示标准框架。

### 3. 结构与优先级

- 让用户先说明分析结构和优先顺序。
- 结构存在关键空白时，只追一个最高价值缺口。
- 用户列出大量分支时，追问首先验证哪一项以及为什么。

### 4. 分析与数据

- 每次只提供当前分析分支需要的一组数据、图表描述或访谈信息。
- 需要计算时允许用户口述公式、假设和计算过程。
- 数字错误可以通过复核问题让用户自查；过程中不直接给正确答案。
- 观察用户是否解释数据含义、更新假设并连接到最终决策。

### 5. 条件变化或反证

只在能提高区分度时增加一项变化，例如预算减少、竞争者反应、用户负反馈、统计反例或执行
限制。变化必须与当前方案相关，不为了制造难度任意改题。

### 6. 综合建议

要求用户面向题设中的决策者给出结论、关键依据、风险和下一步。用户已经主动完成时不重复要求。

## Case 类型

- Market Sizing：需求端、供给端、双向校验或非常规估算；
- Profitability：收入、成本、结构变化、根因和改善；
- Market Entry：市场、能力、进入方式、经济性和风险；
- Growth：用户、产品、渠道、价格、供给和长期价值；
- Operations：流程、瓶颈、产能、质量和实施；
- Investment/M&A：战略逻辑、协同、估值假设、整合和风险；
- Product/Data Case：需求、指标、诊断、方案、实验和效果。

## 评价边界

结束后评价澄清质量、结构、优先级、假设、证据使用、定量准确性、结论更新和综合表达。不得因
用户没有复述题库框架或得出不同但可论证的结论而扣分。
