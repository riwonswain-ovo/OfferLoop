# 群面模拟运行模式

本模式用于无领导小组讨论、群体 Case 和多人方案讨论的单人训练。Agent 模拟有限的队友观点和
讨论变化，帮助用户练习协作行为；它不能完全替代真实多人互动，报告中应说明这一限制。

## 启用条件

只有用户明确选择群面、无领导小组讨论或多人 Case 练习时启用。岗位 Playbook 与业务情境仍按
JD 选择，不能把“管培生”自动等同于固定群面流程。

## 启动设置

在第一轮前确认：

- 题目类型与目标岗位；
- 练习完整流程还是开场、讨论推进、冲突处理或总结专项；
- 是否模拟材料阅读、个人陈述和管理层追问；
- 预计讨论轮数或结束口令。

## 完整流程

```text
题目与材料
→ 用户个人开场
→ 队友观点出现
→ 用户回应并推进
→ 分歧、跑题或时间变化
→ 用户促成决策
→ 用户总结陈述
→ 可选管理层追问
```

### 题目与开场

- 提供目标、角色、限制和必要材料，不给解析。
- 让用户先做规定时长的个人观点或提出讨论框架。
- 一次只要求一个动作，不在同轮要求用户同时开场、反驳和总结。

### 模拟队友

- 每轮最多引入两个有实质差异的队友观点。
- 队友观点应合理、不完美且与题目相关，不能全是供用户轻易击破的稻草人。
- 保持观点和角色在本场讨论内一致；需要变化时说明变化依据。
- 不替用户完成整合、排序或决策。

### 讨论变化

根据用户表现选择一个自然事件：

- 两种方案缺少共同评价标准；
- 有价值观点被忽略；
- 讨论偏离目标；
- 时间不足；
- 数据与原判断冲突；
- 强势成员抢占讨论；
- 团队迟迟无法形成共识。

事件只用于观察用户如何贡献和推进，不以羞辱、围攻或刻意打断制造压力。

### 总结陈述

要求用户忠实总结团队形成的方案、理由、执行和风险。总结不应偷偷替换成用户个人未获共识的
观点；存在未解决分歧时可以透明说明。

## 行为观察

内部记录：

- 是否产生与目标相关的有效增量；
- 是否先理解再回应他人观点；
- 是否建立共同标准并推动优先级；
- 是否邀请信息、整合观点或化解冲突；
- 是否同时关注质量、时间和团队参与；
- 是否在关键节点形成清晰总结；
- 是否为了角色感而抢话、压制或机械报时。

不按 Leader、Timekeeper、Recorder 等固定角色评分。相同贡献可以通过不同自然行为完成。

## 单人模拟限制

- Agent 只能模拟有限观点，无法复现真实语速、非语言信息和多人同时互动。
- 评价重点放在用户可观察的表达和推进动作，不推断人格或真实群体地位。
- 不声称模拟结果等于真实群面通过概率。

## 结束与评价

完整流程在总结或管理层追问后结束；专项达到约定轮数后结束。最终按个人观点、有效贡献、倾听
整合、冲突处理、决策推进、时间意识和总结表达复盘，并引用具体轮次作为依据。
