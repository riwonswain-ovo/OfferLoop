# AI Coding 与产品交付问题模式

当候选人声称用 Coding Agent、低代码或托管平台完成应用/MVP/生产交付时按需使用。它是动态
追问变量，不是工程知识考试。

## 1. 所有权链

- 原始需求、PRD、仓库、提示词和技术栈分别来自哪里；
- 哪个关键产品判断是候选人做的；
- AI、模板、第三方平台、研发和候选人分别交付什么；
- 条件改变后候选人能否重新做方案选择；
- 哪个结果最能证明不是只跟做教程。

## 2. Spec 到验收链

- 一个模糊需求如何被澄清为可验收规格；
- 如何拆阶段、确定非目标和完成标准；
- 说一条真实测试输入、预期和实际结果；
- Agent 说“完成”后候选人亲自做了什么；
- 哪次验收导致返工、回退或修改规格。

## 3. 系统边界链

选择一条真实业务动作，追问：

```text
前端交互 → API 输入/输出 → 后端规则 → 数据状态
→ 身份/权限 → 异常与恢复 → 审计
```

用户不能解释底层实现时，确认其职责边界，再追其真实参与的需求、接口、验收和协作。

## 4. Harness 链

- 如何向 Coding Agent提供项目规则和当前状态；
- 长任务或多会话如何防止遗忘和漂移；
- 工具、权限和修改范围如何控制；
- 如何隔离并行改动并留下版本；
- 如何用外部测试和人工判断纠正模型自评。

## 5. 生产证据链

- 本地运行、可分享部署、MVP、试点和生产中的哪一级；
- 谁实际使用、使用什么数据、持续多久；
- 有哪些测试、环境、监控、告警、回滚或故障记录；
- 密钥、角色权限和数据隔离如何验证；
- 如果只有链接，不能证明的部分是什么。

## 6. 约束变化

每次只追加一个：

- 用户数据变为敏感数据；
- 从单用户变为多租户；
- Agent 修改错误文件；
- 托管服务不可用或成本上升；
- 核心 E2E 通过但出现越权；
- 已部署但没有真实用户；
- 研发团队接管 AI 生成的代码。

观察候选人是否更新方案、成熟度口径和人机分工。

同一证据缺口最多连续追问三次；充分回答后停止。
