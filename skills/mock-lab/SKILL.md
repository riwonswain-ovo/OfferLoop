# Mock Lab

保持真实面试节奏：一次一题，依据回答追问，过程中不泄露评分或参考答案，结束后统一复盘。

运行相对路径前先从当前 `SKILL.md` 定位 Skill 根目录。

## 前置读取

1. 完整读取 `references/interview-protocol.md`。
2. 定位兄弟 `offerloop-workspace`，完整读取其 `references/artifact-contract.md`。
3. 读取 `lark-wiki` 和 `lark-doc` Skill；有事件/Base 时再读取 `lark-base`。
4. 检查 `current_resumes`、兼容目录键 `resume_deepthink` 和 `mock_lab`；首次创建节点前展示目标并
   取得确认。

schema v4、依赖或权限未就绪时路由到 `offerloop-setup`，不要自行扩大权限。

## 确认范围与读取材料

1. 每次开始先询问并确认本次面试方向。
2. 询问用户是否有更详细的岗位 JD；有则读取或接收，没有则明确按用户确认的方向模拟。
3. 列出 `02｜当前简历` 中的版本并让用户选择，按标题精确匹配后读取全文。
4. 从 `03｜经历深挖` 中选择岗位方向匹配、且与当前简历要点或本次 JD 相关的经历文档；先读
   产物信息再读正文，不按简历版本排除同一真实经历，不读取方向不符或无关经历。
5. 用户指定面试准备文档或问题时一并读取。
6. 按一面、二面、三面和 HR 面四种视角构建题目；可以按用户选择只练部分环节，但完整模拟必须
   覆盖四种视角。没有 JD 时不得虚构具体公司内部流程。

不得读取或依赖本地 `mock-interview` Skill。

开始前只确认模拟范围、面试角色、预计题量、是否允许压力追问和结束口令。不要展示完整题单。

## 模拟

1. 一次只问一个主问题。
2. 根据用户回答中的证据缺口、矛盾或岗位要求自然追问。
3. 不在过程中点评、纠错、鼓励性总结或给答案。
4. 记录每题、追问、回答要点、证据使用和观察，但不向用户实时展示评分。
5. 用户说“结束模拟”等明确口令时立即停止；普通停顿不视为结束。
6. 不冒充特定真人，不虚构公司内部流程；面试官角色只是训练设定。

## 结束与保存

按 reference 完成逐题评价、总体表现、分轮观察、改进表达和训练任务。生成 `run_id` 和
Markdown，校验后保存到 `06｜模拟面试`。文档必须记录面试方向、JD 状态、简历
版本和读取过的经历深挖文档。完整结束为 `completed`，用户明确提前结束为
`incomplete`。

从本轮主问题和追问中整理后续训练任务并保留在报告中。报告可以建议运行
`experience-deepthink` 或 `pm-sense`，但不得自动修改简历。保存失败时交付完整 Markdown 和原
`run_id`。
