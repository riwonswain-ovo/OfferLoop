# Base 完成状态同步契约

本文件约束 `笔面试中心` 与 `求职进展` 的同步。文件名为兼容既有安装清单而保留；当前链路不创建或读取飞书原生任务，也不发送每日签到卡。

## 真源与时间语义

- `笔面试安排` 是唯一物理数据表；`全部安排` 与各环节入口都是它的视图，所有视图共享同一条记录和同一个 `完成状态` 单元格，不存在跨表复制或双向同步。
- `开始时间` / `结束时间` 是用户确认的计划完成时段；`截止时间` 是招聘方的真实截止。二者必须独立保存，任何运行时同步都不得互相覆盖。
- 日历只由 `recruiting-reminder` 在用户确认计划后创建或更新。运行时不创建、移动或删除日历事件。
- 不再需要 `飞书任务GUID`、`未参加任务GUID`、`飞书任务链接` 或任务清单 GUID。

## 单表实时触发器

`笔面试安排` 只有一条启用的 Base workflow。`SetRecordTrigger` 只监听 `完成状态`，用户在 `全部安排` 或任一环节视图修改后，立即由 `HTTPClientAction` POST 当前 `recordId` 到 `/openapi/job-progress-sync/reminder-reconcile`。

请求必须使用独立的 `X-OfferLoop-Workflow-Secret` 头鉴权，密钥只保存在 workflow 加密配置和妙搭环境变量中。服务读取这条单表记录并更新所有关联求职进展。workflow 排除自动化批量更新触发，避免服务回写形成循环。

## 完成状态映射

- `待完成`：只单调推进到对应邀请状态，不修改计划时间或真实截止时间。
- `已完成`：根据事件 `环节` 单调更新每条 `求职记录ID` 的 `最近完成节点` 与 `进展状态`。
- `已错过`：仅在没有更晚可靠邀请时把求职进展设为 `状态待确认`。

同步不得覆盖 Offer、未通过、主动放弃、岗位关闭等人工终态，也不得让较晚节点倒退。

## 补偿触发器

`offerloop-base-reconcile` 是漏事件兜底，其调度频率不代表正常同步延迟：

1. 待完成邀请单调同步关联求职记录的 `进展状态`。
2. 已完成事件补偿推进 `最近完成节点` 与下一状态。
3. 已错过事件仅在没有更晚可靠邀请时把求职进展设为 `状态待确认`。
4. 不调用 Tasks API 或 Calendar API，不回写任何时间字段。

重复运行必须是 no-op。单条关联记录失败不得阻塞其他关联记录。

## 验收

- 在 `全部安排` 或任一环节视图修改 `完成状态` 后，其他视图立即显示相同值，并即时推进求职进展。
- 计划时间与真实截止时间保持原值。
- 运行时源代码和部署环境不包含每日签到卡、卡片回调、Tasks API、任务清单 GUID 或任务 due 回写。
- 对账密钥缺失或错误时拒绝请求，不在响应和日志中泄露密钥。
