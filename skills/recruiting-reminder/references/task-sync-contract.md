# Base 每日确认卡片同步契约

本文件约束 `笔面试中心`、每日群卡片和 `求职进展` 的同步。文件名为兼容既有安装清单而保留；
当前链路不创建或读取飞书原生任务。

## 真源与时间语义

- `笔面试安排` 是唯一物理数据表；`全部安排` 与各环节入口都是它的视图，所有视图共享同一条
  记录和同一个 `完成状态` 单元格，不存在跨表复制或双向同步。
- `开始时间` / `结束时间` 是用户确认的计划完成时段；`截止时间`是招聘方的真实截止。二者必须
  独立保存，卡片同时展示，任何运行时同步都不得互相覆盖。
- 日历只由 `recruiting-reminder` 在用户确认计划后创建或更新。运行时不创建、移动或删除日历事件。
- 不再需要 `飞书任务GUID`、`未参加任务GUID`、`飞书任务链接` 或任务清单 GUID。

## 每日分类

每日卡片分页读取 `笔面试安排` 中的 `待完成` 与 `已完成` 记录，并按 Asia/Shanghai 自然日分类：

1. 今日计划：计划时间在今天；没有计划时间时，才以真实截止落在今天作为兜底。
2. 计划未完成：计划时间早于今天、仍为 `待完成`，且真实截止为空或尚未到达。
3. 已过真实截止：发送卡片时真实截止已经过去且仍为 `待完成`。
4. 今日已完成：`已完成` 且计划时间在今天；没有计划时间时才以真实截止兜底。

“计划未完成”卡片必须同时显示计划时间和真实截止，使次日提醒表达为“昨天安排的事项未完成，
真实截止为……”。不得因为进入该分类而自动改期。

## 卡片操作

卡片使用 schema 2.0 的 callback behavior，值只允许：

- `{ "action": "completed", "record_id": "rec..." }`
- `{ "action": "incomplete", "record_id": "rec..." }`

处理前必须校验 Verification Token、`card.action.trigger`、App ID、唯一所有者 open_id、固定群
chat_id、按钮 tag 和 record ID 格式。回调 URL 支持飞书 challenge 验证，并须在 3 秒内返回 HTTP 200。

- `completed`：把当前笔面试安排记录的 `完成状态` 写为 `已完成`，随后按事件
  `环节` 单调更新每条 `求职记录ID` 的 `最近完成节点` 与 `进展状态`。不得修改 `环节`，
  不得覆盖 Offer、未通过、主动放弃、岗位关闭等人工终态，也不得让较晚节点倒退。
- `incomplete`：验证记录仍为 `待完成` 后只返回提示，不写 Base，不改计划或真实截止，不创建任务，
  不改日历。次日再次由每日分类选中。
- 重复点击 `completed` 必须幂等；已不是待完成的记录不能接受 `incomplete`。

## 单表实时触发器

`笔面试安排` 只有一条启用的 Base workflow。`SetRecordTrigger` 只监听 `完成状态`，用户在
`全部安排` 或任一环节视图修改后，立即由 `HTTPClientAction` POST 当前 `recordId` 到
`/openapi/job-progress-sync/reminder-reconcile`。请求必须使用独立的
`X-OfferLoop-Workflow-Secret` 头鉴权，密钥只保存在 workflow 加密配置和妙搭环境变量中。
服务读取这条单表记录并更新所有关联求职进展。workflow 排除自动化批量更新触发，避免服务回写
形成循环。

## 补偿触发器

`offerloop-base-reconcile` 是漏事件兜底，其调度频率不代表正常同步延迟：

1. 待完成邀请单调同步关联求职记录的 `进展状态`。
2. 已完成事件补偿推进 `最近完成节点` 与下一状态。
3. 已错过事件仅在没有更晚可靠邀请时把求职进展设为 `状态待确认`。
4. 不调用 Tasks API 或 Calendar API，不回写任何时间字段。

重复运行必须是 no-op。单条关联记录失败不得阻塞其他关联记录。

## 验收

- 今日卡片包含“今日计划 / 计划未完成 / 已过真实截止 / 今日已完成”四类中的实际非空项。
- 计划时间与真实截止不同时，卡片分别显示且保持原值。
- 点击“尚未完成”后没有 Base、任务或日历写请求，第二天仍会提醒。
- 点击“已完成”后单表记录和所有关联求职进展最终收敛，且 `环节` 不变。
- 在 `全部安排` 或任一环节视图修改 `完成状态` 后，其他视图立即显示相同值，并即时推进求职进展。
- 运行时源代码和部署环境不包含 Tasks API、任务清单 GUID 或任务 due 回写。
- 多人群、成员分页不完整、所有者或回调身份不匹配时拒绝发送或处理。
