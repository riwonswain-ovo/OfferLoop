# 原生飞书任务同步契约

本文件只约束 `笔面试中心` 与 OfferLoop 飞书原生任务的自动同步。邮件抽取、日历和求职进展
字段规则仍以 `SKILL.md` 为准。

## 真源与责任边界

- `全部安排` 主表是笔面试事件真源；只处理 `完成状态 = 待完成` 的记录。
- 飞书原生任务是用户操作入口。创建和读取任务必须使用发送每日群卡片的同一飞书应用身份。
- `recruiting-reminder` 只写事件，不以个人身份另建任务。Loop Runtime 负责创建、回填和对账。
- 运行时必须配置固定任务清单 GUID 和 OfferLoop 所有者 open_id；不得按任务清单标题猜测。

## 主表字段

以下字段只存在于 `全部安排` 主表，均为隐藏技术字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `飞书任务GUID` | 文本 | 主任务 GUID |
| `未参加任务GUID` | 文本 | “未参加”子任务 GUID |
| `飞书任务链接` | URL | 主任务的飞书客户端链接 |

字段缺失时运行时必须失败并报告，不得静默创建另一个 Base 或猜测替代字段。

## 幂等创建

每轮对账先分页读取所有待完成事件。缺少任务映射时：

1. 用 `record_id + completed` 派生稳定 UUID，创建主任务并加入固定任务清单；负责人是配置中的
   OfferLoop 所有者。
2. 用 `record_id + not_attended` 派生另一稳定 UUID，在主任务下创建
   `未参加（仅未参加时勾选）` 子任务。
3. 把两个 GUID 和主任务 URL 一次回填主表，再读取任务状态。

稳定 UUID 必须传给飞书 Tasks API 的 `client_token`。即使创建成功后 Base 回填失败，下次重试也
只能取回同一任务，不能生成副本。已有 GUID 但当前应用无权读取时，不得覆盖，需记录为跳过并报警。

主任务标题按 `笔试或面试｜公司｜岗位｜环节` 生成，空字段跳过。任务时间优先使用 `开始时间`，
没有开始时间时使用 `截止时间`。任务描述只包含事件 record ID、必要链接和注意事项，不复制邮件正文。

## 状态映射

对账顺序固定为：

1. “未参加”子任务为 `done` → `完成状态 = 已错过`；
2. 否则主任务为 `done` → `完成状态 = 已完成`；
3. 否则检查任务 due 是否变化并同步时间。

完成与未参加沿用 `SKILL.md` 的单调求职进展规则。重复对账必须是 no-op。

若事件原有 `开始时间`，任务 due 变化时更新开始时间，并按原时长平移结束时间；若事件只有
`截止时间`，只更新截止时间。两者都为空时，任务 due 可用于补充截止时间，但不得猜测事件时长。

## 群卡片

- 每日卡片只使用 `open_url`，不使用 callback 按钮，不要求公网回调地址。
- 单条事件优先打开对应主任务；总入口打开固定任务清单。
- 群成员检查必须完整分页，且唯一真人必须是配置中的 OfferLoop 所有者。
- 对账触发器固定命名为 `offerloop-task-reconcile`，默认每 30 分钟运行一次；卡片文案必须明确
  “在飞书任务中更新”。

## 验收

- 新建一条无任务 GUID 的待完成事件，一轮对账后恰好生成一个主任务和一个未参加子任务。
- 重复对账不产生副本。
- 完成主任务、完成未参加子任务、修改 due 分别正确回写 Base。
- 多人群、成员分页不完整、所有者不匹配时不发送每日卡片。
- 模板、安装文档和部署环境中不存在 Vercel、`card.action.trigger`、回调 verification token 或
  relay secret 依赖。
