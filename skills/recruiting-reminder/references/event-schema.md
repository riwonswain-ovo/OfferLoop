# v2.0.0 笔面试中心数据契约

本文件是 `笔面试安排` 的字段、选项和受管视图唯一真源。仓库更新不等于真实 Base 迁移；迁移、
删除旧字段和部署都必须分别取得用户授权。

## 唯一业务表与字段

唯一笔面试业务表为 `笔面试安排`，字段顺序和类型如下：

| # | 字段 | 类型 | 固定规则 |
|---:|---|---|---|
| 1 | 安排名称 | Formula（主字段） | 公司、岗位、环节组合；不含时间 |
| 2 | 环节 | SingleSelect | 测评、笔试、群面、一面、二面、三面、面试、HR面；旧值“面试（轮次待确认）”只兼容历史数据 |
| 3 | 公司 | Text | 必填 |
| 4 | 业务线 | Text | 邮件明确时填写 |
| 5 | 岗位 | Text | 不从公司招聘汇总猜测 |
| 6 | 关联求职记录 | Text | 关联记录的可读名称 |
| 7 | 开始时间 | DateTime | 计划或招聘方固定开始时间 |
| 8 | 结束时间 | DateTime | 邮件时长优先、区间取上限；缺失时面试 +60 分钟、测评/笔试 +90 分钟 |
| 9 | 截止时间 | DateTime | 招聘方真实截止；不得被计划时间覆盖 |
| 10 | 预计时长（分钟） | Number | 邮件值优先、区间取上限；没有开始时间也必须保存 |
| 11 | 进行方式 | SingleSelect | 同步、异步 |
| 12 | 平台 | Text | 必要信息 |
| 13 | 链接 | URL | 不自动访问 |
| 14 | 注意事项 | Text | 不复制整封邮件 |
| 15 | 面试准备文档 | URL | 非面试事件保持为空 |
| 16 | 面试复盘文档 | URL | 非面试事件保持为空；完成复盘由 talk-review 回填 |
| 17 | 完成状态 | SingleSelect | 待完成、已完成、已错过；completed 复盘回填时与文档 URL 原子更新为已完成 |
| 18 | 事件状态 | SingleSelect | 有效、已取消 |
| 19 | 求职记录ID | Text | JSON 字符串数组 |
| 20 | 来源邮件ID | Text | 第一封邮件的 canonical ID，永不改写 |
| 21 | 关联邮件ID | Text | 含 canonical ID 的去重 JSON 字符串数组 |
| 22 | 日历状态 | SingleSelect | 待安排、已建日程、操作失败、已取消 |
| 23 | 已建日程ID | Text | 更新/取消原日程的稳定键；取消成功后也保留 |

`安排名称` 公式：

```text
IF(
  ISBLANK([岗位]),
  [公司] & "－" & [环节],
  [公司] & "－" & [岗位] & "－" & [环节]
)
```

## 受管视图

| 视图 | 筛选 |
|---|---|
| 全部安排 | 无筛选 |
| 测评 | 环节 = 测评 |
| 笔试 | 环节 = 笔试 |
| 群面 | 环节 = 群面 |
| 一面 | 环节 = 一面 |
| 二面 | 环节 = 二面 |
| 三面 | 环节 = 三面 |
| HR 面 | 环节 = HR面 |
| 其他面试 | 环节 = 面试；迁移期兼容“面试（轮次待确认）” |

统一排序为 `开始时间 desc, 截止时间 desc, 公司 asc`，空时间在有时间记录之后。只维护上述
受管视图的筛选与排序，不删除用户自定义视图。

## 运行状态表

另建内部表 `OfferLoop运行状态`，不作为笔面试中心业务视图。字段为：`幂等键`（Text 主字段）、
`类型`（Text）、`状态`（待执行、成功、失败、发送中、已发送、发送失败、发送结果未知）、`来源ID`
（Text）、`步骤`（Text）、`日期`（Text）、`分页序号`（Number）、`结果引用`（Text）、`消息ID`
（Text）、`错误`（Text）、`更新时间`（DateTime）。它只保存最小运行账本，不保存邮件正文或事件内容。
`幂等键` 必须唯一；重复键视为部署错误并停止发送。

## v1 → v2 迁移映射（只作候选方案）

先备份和回读核验，再执行：

- `笔试类型=性格测评/行测` → `环节=测评`；`笔试/技术笔试` → `环节=笔试`。
- `笔试子类型=同步笔试/异步笔试` → `进行方式=同步/异步`。
- 初始化 `事件状态=有效`；`关联邮件ID=[来源邮件ID]`。
- 按已有开始/结束时间差回填 `预计时长（分钟）`；无法推导时面试填 60，测评/笔试填 90。
- 旧 `日历状态=未建日程` → `待安排`；已有 ID 的记录 → `已建日程`。
- 全量回读、备份和验收通过后，才可另行授权删除 `笔试类型` 与 `笔试子类型`；不得在候选版本确认时修改真实数据。
