# 岗位迁移判断与写入前确认

本文件定义硬筛通过后的岗位偏好判断和写入门禁。`投递进度=待确认` 是企业记录写入后的
投递决策状态，不能替代本文件的写入前确认。

## 1. 偏好语义

- `target_cities` 是城市硬条件，也是从 `career-profile` 的 `岗位选择偏好｜<显示名>` 镜像到
  `用户偏好` 的运行字段；`全国` 表示用户已明确不限制城市，不代表软筛。偏好文档缺失、未完成
  或有待补节点时必须在扫描前转入 `career-profile`，`job-collection` 不得询问任何求职偏好或把
  缺失当作无限制。
- `selected_industries` 是目标行业硬条件；明确空列表表示不限制行业。缺失值不等于空列表。
- `excluded_industries`、`excluded_companies` 和 `excluded_recruitment_types` 继续作为硬排除。
- `target_job_preferences` 是岗位软偏好，也是从岗位选择偏好文档镜像的运行字段，可包含岗位名称、方向和用户
  认可的同义表达。字段缺失时转入 `career-profile`，不能擅自当作不限岗位。
- 岗位选择偏好文档中的 `直接匹配方向` 和 `可迁移方向` 是岗位适配的长期判断依据；可迁移方向必须带有
  用户确认的迁移路径。
- `当前未见清晰迁移路径` 只表示现有文档没有显示必要的学科、技术、执业或长期训练基础，
  不是永久岗位黑名单；只有用户明确确认的方向才进入“用户明确不考虑”。
- 用户的性格、情绪、兴趣和语言习惯不得参与硬筛、迁移淘汰或 `specialized_only` 判断。

`selected_industries` 与 `excluded_industries` 冲突时停止写入并请用户修正；不得猜测哪一边优先。
行业或城市无法从来源可靠判断时按硬条件不可验证处理，不进入写入前岗位确认。

## 2. 路由决策

对每条完成拆批次和标准化的候选固定按以下顺序路由：

1. 任一城市、目标行业或其他硬条件不满足/不可验证：`hard_filtered`，不写入。
2. 全部硬条件满足，且岗位属于直接匹配方向：`auto_write`。
3. 全部硬条件满足，岗位虽非同名方向，但命中已确认的可迁移路径：`auto_write`。例如用户没有
   PMO 实习，但经管专业、产品实习和项目推动经历已被确认为 PMO 迁移路径时，不得因岗位名称
   不同进入淘汰或确认。
4. 可靠来源展示了该企业当前招聘的完整岗位范围，且全部岗位都属于岗位选择偏好文档中“用户明确
   不考虑的方向”：`prewrite_confirmation`。原因写明用户已确认的边界；不得写“用户不能做”。
   仅被 Agent 归入“当前未见清晰迁移路径”但未经用户确认的岗位不能按此条处理，应进入第 5 条。
5. 岗位字段为空、无法确认来源是否覆盖全部岗位、迁移路径未确认或匹配置信度不足：
   `prewrite_confirmation`，在用户决定前不写入。

岗位判断同时查看 `job_positions`、`project_name`、可靠的公告标题和来源是否声明完整岗位范围。
优先使用用户原始表达、明确同义词和已确认迁移路径。不因公司知名或“可能有合适岗位”擅自判为
匹配，也不因缺少同名实习擅自判为不匹配。可靠完整范围全部命中用户明确不考虑方向时，必须作为
写入前确认项，不直接写入。

## 3. 交互式确认

先完成全局去重，再把本轮 `prewrite_confirmation` 候选合并成一次确认清单；同一公司、批次、
入口完全相同才可合并岗位。每条至少展示：编号、公司、岗位、城市、行业、批次、截止时间、入口，
以及迁移判断或不确定原因。仅有高专业门槛岗位时，同时展示来源是否覆盖完整岗位范围、涉及的
门槛和画像中缺少的迁移基础。候选较多时每批最多 20 条，保留稳定编号分页确认。

明确提供以下操作，不要求用户逐条重述招聘信息：

- 写入全部；
- 全部不写入；
- 仅写入指定编号；
- 除指定编号外都写入。

只有明确接受的候选才按 `excel-insert.md` 双写，写入后的默认投递进度仍为 `待确认`。明确拒绝的
候选记为 `confirmed_skipped`，不创建企业主表或子表记录。用户未回复、回复含糊或只讨论偏好时，
保持 `awaiting_confirmation`，不得把沉默解释为同意或拒绝。

用户接受某个边界外岗位只代表本次机会获准写入，不自动扩大 `target_job_preferences` 或岗位迁移
边界；只有用户确认长期迁移路径时才交给 `career-profile` 更新画像。

## 4. 游标与无人值守任务

来源游标只能在本轮所有候选都完成以下任一终态后推进：重复/补全完成、`hard_filtered`、
`auto_write` 写入并验收、用户接受后写入并验收，或用户明确拒绝为 `confirmed_skipped`。
只要存在 `awaiting_confirmation`，保留该来源旧游标，并在摘要中给出待确认数量和稳定候选编号。

无人值守任务不能代替用户决策：照常写入 `auto_write`，但不写入 `prewrite_confirmation`；发送或
输出写入前确认清单，并保留该来源旧游标。下一次交互式运行重新扫描重叠窗口、全局去重后继续确认。
不得为了让定时任务“成功”而把待确认候选写成 `投递进度=待确认`，也不得静默丢弃并推进游标。

## 5. 运行摘要

逐来源至少报告：候选、硬筛淘汰、硬筛通过、岗位匹配直写、写入前待确认、用户确认写入、
用户确认不写、尚未决定、重复、补全、新增、失败，以及旧/新游标。`awaiting_confirmation > 0`
时来源状态写为“等待用户确认”，不能称为同步完成。
