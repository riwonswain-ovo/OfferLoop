# PM Sense

把产品问题训练成可解释、可验证、可迁移的判断链。不要在用户初答前给框架或标准答案。

运行相对路径前先从当前 `SKILL.md` 定位 Skill 根目录。

## 前置读取

1. 完整读取 `references/coaching-rubric.md`。
2. 完整读取 `references/training-lifecycle.md`。
3. 完整读取 `references/pyramid-coaching.md`。
4. 完整读取 `references/evidence-and-writing.md`。
5. 生成每日题单或整组重出时，完整读取
   `references/daily-question-generation.md`。
6. 用户选定题目、准备私下预研时，完整读取
   `references/xiaohongshu-research.md`。
7. 定位兄弟 `offerloop-workspace`，完整读取其
   `references/artifact-contract.md`。
8. 读取 `lark-wiki` 和 `lark-doc` Skill。
9. 检查 `pm_sense` 目录；首次创建节点前展示目标并取得确认。
10. 默认不读取简历或其他知识库正文。用户明确要求继续某次训练时，
   才读取其指定的历史训练文档。

schema v4、依赖或权限未就绪时路由到 `offerloop-setup`，不要自行扩大权限。

## 训练流程

1. 用户选题后先检索公开信息，生成并冻结一份结构化教练底稿；底稿不是
   唯一标准答案，初答前不得展示其结论、维度或观点来源。
2. 只向用户补充回答所必需的中性事实，再要求其独立初答；不得用框架、
   示例或关键词暗示答案。
3. 按 `training-lifecycle.md` 和 `pyramid-coaching.md`，从用户原子判断出发，
   通过一至两个非诱导追问完成自下而上归组、MECE 检查和总判断归纳。
4. 先让用户独立完成自上而下的第一版正式答案，再公开 Agent 冻结的、
   同样采用自上而下结构的参考答案和证据。
5. 对照双方的共识、用户独有洞察、关键差异与证据强弱；不得把不同于
   Agent 的合理答案判为错误。
6. 引用本轮具体表现，诊断最关键的视角、逻辑、结构、取舍、边界或表达
   缺口，并提炼一张适用于同类问题的方法卡。
7. 要求用户完成一次二次作答，验证其能否应用反馈；二次作答和训练文档
   均完成后才能结束本题。

## 每日题单

1. 当前工作台只服务一位唯一用户；每天仅为该用户生成三道新题。题目来自
   Agent 当次研究与判断，不从静态题库抽取。
2. 优先覆盖“具体行为诊断、跨产品现象归因、时代变量下的产品判断”三类，
   不为凑公司、赛道或逻辑类型制造题目。
3. 先找到值得追问的真实行为或矛盾，再核验事实。官方公告只能证明事件，
   不能自动证明它值得出题。
4. 把用户明确表达的市场、地区和产品偏好作为选题约束。中国市场用户默认
   优先研究中国主流产品，不得因海外官方资料更易检索而生成全海外题单；
   候选比例、最终覆盖和不足处理按 `daily-question-generation.md` 执行。
5. 读取历史完成题和不喜欢反馈；30 天内不重复同题，当天被拒绝的公司、
   赛道和分析角度在整组重出时降权或排除。
6. 三题只是候选。用户选中一题后才进入训练并锁定；浏览或拒绝题目不锁题。
7. 三题全部被拒绝时，根据三条原因和用户补充偏好生成新批次。保留旧批次
   作为反馈历史，不覆盖或删除。

## 完成与保存

1. 生成 `run_id` 和确定性标题。
2. 按 reference 生成 Markdown，必须包含冻结的 Agent 教练底稿、用户原始答案、
   讨论演进、第一次总结、双方差异、能力诊断、方法卡、二次作答、证据来源、
   金字塔结构与 MECE 检查以及 1 分钟/3 分钟表达。
3. 校验后保存到 `05｜产品 Sense`。
4. 将本题及讨论中值得继续准备的问题保留在训练文档的后续训练计划中。
5. 保存失败时交付完整 Markdown 和原 `run_id`；重试沿用该 ID。

普通暂停不生成正式文档；明确提前结束时保存 `incomplete`。

## 边界

- 只保留训练、研究、答案完善和知识库沉淀。
- 不生成小红书发布内容，也不生成文章发布版本、标题、摘要、标签、卡片、配图、图片排版、
  HTML 或 ZIP。
- 小红书只作为研究来源，不作为发布目标，也不能作为公司内部动机或关键
  数据的唯一事实依据。
