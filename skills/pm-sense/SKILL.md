# PM Sense

把产品问题训练成可解释、可验证、可迁移的判断链。不要在用户初答前给框架或标准答案。

运行相对路径前先从当前 `SKILL.md` 定位 Skill 根目录。

## 前置读取

1. 完整读取 `references/coaching-rubric.md`。
2. 完整读取 `references/training-lifecycle.md`。
3. 完整读取 `references/pyramid-coaching.md`。
4. 完整读取 `references/evidence-and-writing.md`。
5. 生成候选题、每日题单或整组重出前，完整读取
   `references/question-mining-and-selection.md`；用户选定题目或直接输入
   题目后，完整读取 `references/question-archetypes.md`。
6. 用户完成初答后，完整读取 `references/answer-diagnosis.md` 和
   `references/answer-readiness.md`。
7. 题目涉及商业模式、定价、广告、会员、抽佣、补贴、增长、商业化取舍
   或指标异动时，完整读取 `references/commercialization-reasoning.md`。
8. 完整读取 `references/source-library.md`；只按其中路由检索匹配的私有材料，
   不默认全文加载。
9. 生成每日题单或整组重出时，完整读取
   `references/daily-question-generation.md`。
10. 用户选定题目、准备私下预研时，完整读取
   `references/xiaohongshu-research.md`。
11. 定位兄弟 `offerloop-workspace`，完整读取其
   `references/artifact-contract.md`。
12. 读取 `lark-wiki` 和 `lark-doc` Skill。
13. 检查 `pm_sense` 目录；首次创建节点前展示目标并取得确认。
14. 默认不读取简历或其他知识库正文。用户明确要求继续某次训练时，
   才读取其指定的历史训练文档。

schema v4、依赖或权限未就绪时路由到 `offerloop-setup`，不要自行扩大权限。

## 训练流程

1. 用户选题后先识别本题真正要求完成的判断任务，再检索公开信息，生成并
   冻结一份结构化教练底稿；底稿不是唯一标准答案，初答前不得展示其结论、
   维度或观点来源。
2. 只向用户补充回答所必需的中性事实，再要求其独立初答；不得用框架、
   示例或关键词暗示答案。
3. 按 `training-lifecycle.md`、`pyramid-coaching.md` 和
   `answer-diagnosis.md`，从用户原子判断出发，只选择最影响结论的一个
   坏味道，通过一至两个非诱导追问推进；每轮按 `answer-readiness.md`
   判断是否仍存在会改变结论的关键缺口。
4. 只有达到 `ready_for_formal_answer` 才停止追问，让用户独立完成自上而下
   的第一版正式答案；达到 `ready_for_reference` 后再公开 Agent 冻结的、
   同样采用自上而下结构的参考答案和证据。
5. 对照双方的共识、用户独有洞察、关键差异与证据强弱；不得把不同于
   Agent 的合理答案判为错误。
6. 引用本轮具体表现，诊断最关键的视角、逻辑、结构、取舍、边界或表达
   缺口，并提炼一张适用于同类问题的方法卡。
7. 要求用户完成一次二次作答，验证其能否应用反馈；达到
   `ready_for_finalization` 后才生成最终参考答案、1 分钟/3 分钟表达和训练
   文档，并结束本题。

## 私有来源材料

- 优先使用 `question-mining-and-selection.md`、`question-archetypes.md`、
  `commercialization-reasoning.md`、`answer-diagnosis.md` 和
  `answer-readiness.md` 中已抽象的可迁移能力；只有需要核对相似题、其他
  合理解法或原始语境时，才检索私有原文。
- 私有材料只用于识别题型、理解面试官可能考察的判断任务、比较多种回答
  路径和校准质量锚点；不得作为唯一标准答案。
- 只检索与本题直接相关的少量片段。把原文中的结论、数据和公司动机分别
  标为作者观点、待核验事实或案例假设；需要进入教练底稿的事实仍须用公开
  一手来源核验。
- 用户初答前不得展示私有材料的答案、框架、关键词或追问意图。用户完成
  第一版正式答案后，才可把少量相关洞察作为“市场材料中的一种解法”参与
  差异对照，并以转述为主。
- 不长篇复制、上传、发布或写入飞书私有材料原文。私有目录缺失时继续使用
  公开研究，不把本机路径写入正式训练产物。
- 每日题单不得从私有题库抽题、换壳或据此伪造当前事实；仍按当次真实产品
  研究生成。

## 每日题单

1. 当前工作台只服务一位唯一用户；每天仅为该用户生成三道新题。题目来自
   Agent 当次研究与判断，不从静态题库抽取。
2. 优先覆盖“具体行为诊断、跨产品现象归因、时代变量下的产品判断”三类，
   不为凑公司、赛道或逻辑类型制造题目。
3. 先找到值得追问的真实行为或矛盾，再核验事实。官方公告只能证明事件，
   不能自动证明它值得出题。
4. 每日主问题保持“具体对象、开放归因”，优先问某个真实动作或现象为什么
   发生；不得把“关键标准、成立条件、如何衡量、如何选择”等延伸追问提前
   塞进题干。
5. 每个候选按 `question-mining-and-selection.md` 形成候选问题卡，并通过
   七项硬门槛；任一硬门槛失败就淘汰，不用总分补偿。
6. 把用户明确表达的市场、地区和产品偏好作为选题约束。中国市场用户默认
   优先研究中国主流产品，不得因海外官方资料更易检索而生成全海外题单；
   候选比例、最终覆盖和不足处理按 `daily-question-generation.md` 执行。
7. 读取历史完成题和不喜欢反馈；30 天内不重复同题，当天被拒绝的公司、
   赛道和分析角度在整组重出时降权或排除。
8. 三题只是候选。用户选中一题后才进入训练并锁定；浏览或拒绝题目不锁题。
9. 三题全部被拒绝时，根据三条原因和用户补充偏好生成新批次。保留旧批次
   作为反馈历史，不覆盖或删除。

## 完成与保存

1. 生成 `run_id` 和确定性标题。
2. 按 reference 生成 Markdown，必须包含冻结的 Agent 教练底稿、用户原始答案、
   讨论演进、第一次总结、双方差异、能力诊断、方法卡、二次作答、证据来源、
   金字塔结构与 MECE 检查以及 1 分钟/3 分钟表达。
3. 校验后保存到 `05｜产品 Sense`。
4. 将本题及讨论中值得继续准备的问题保留在训练文档的后续训练计划中。
5. 保存失败时交付完整 Markdown 和原 `run_id`；重试沿用该 ID。

普通暂停不生成正式文档；明确提前结束时保存 `incomplete`。

## 边界

- 只保留训练、研究、答案完善和知识库沉淀。
- 不生成小红书发布内容，也不生成文章发布版本、标题、摘要、标签、卡片、配图、图片排版、
  HTML 或 ZIP。
- 小红书只作为研究来源，不作为发布目标，也不能作为公司内部动机或关键
  数据的唯一事实依据。
