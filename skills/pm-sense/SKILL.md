# PM Sense

把产品问题训练成可解释、可验证、可迁移的判断链。不要在用户初答前给框架或标准答案。

运行相对路径前先从当前 `SKILL.md` 定位 Skill 根目录。

## 前置读取

1. 完整读取 `references/coaching-rubric.md`。
2. 完整读取 `references/pyramid-coaching.md`。
3. 完整读取 `references/evidence-and-writing.md`。
4. 生成每日题单或整组重出时，完整读取
   `references/daily-question-generation.md`。
5. 用户完成自主总结、准备研究时，完整读取
   `references/xiaohongshu-research.md`。
6. 定位兄弟 `offerloop-workspace`，完整读取其
   `references/artifact-contract.md`。
7. 读取 `lark-wiki` 和 `lark-doc` Skill。
8. 检查 `pm_sense` 目录；首次创建节点前展示目标并取得确认。
9. 默认不读取简历或其他知识库正文。用户明确要求继续某次训练时，
   才读取其指定的历史训练文档。

schema v4、依赖或权限未就绪时路由到 `offerloop-setup`，不要自行扩大权限。

## 训练流程

1. 用户有题目时只确认题目并要求其独立初答；没有题目时提供三个不同
   题型的开放题供选择。初答前不得泄露框架、分类维度或标准答案。
2. 点评初答时，先提炼用户已经形成的核心判断和最有价值的部分，再指出
   当前最影响答案质量的一个问题；不要立即重写全文。
3. 把初答拆成事实、假设、因果判断、价值判断和未知项；先复述用户已经
   说出的原子判断，不替用户补结论。
4. 自下而上推进：让用户归并相关判断、为每组提炼一句组结论，再检查各组
   是否同层、是否使用同一划分标准。
5. 用 MECE 做相对检查：找出重复、混层、关键缺口和无法支撑总判断的分支。
   不要追求穷尽，也不要强迫固定三点。
6. 每轮只解决一个结构问题，追问一至两个判断。优先追问因果跳跃、分组
   依据、关键取舍、反例或证伪条件，不按万能清单机械扫题。
7. 用户说“不知道”时，依次用具体场景、选项比较、现象判断和少量提示
   降低难度；仍不得直接公布完整答案。
8. 每完成一个关键部分，简要收束已确认判断、仍属假设、关键缺口和下一步，
   避免讨论不断扩散。
9. 让用户从组结论中归纳总判断，并先自主完成自上而下表达：结论先行，
   展开二至四个并列理由，再补事实、机制、边界和验证。
10. 只有用户完成自主总结后才开始外部研究。除官方产品、公司公告、财报、
    研究报告和可靠数据外，执行登录态小红书检索以寻找用户观察、相似观点、
    反例和争议。
11. 明确区分事实、官方口径、作者观点、个人观察、第三方推广、假设和推断；
    私人材料不上传外部网站。
12. 结合证据检验而非替换用户判断。证据支持时补强因果链，冲突时展示修订
    过程，最终补充反方观点、边界条件、失败风险和验证指标。

## 每日题单

1. 每个用户每天生成三道新题；题目来自 Agent 当次研究与判断，不从静态题库抽取。
2. 优先覆盖“具体行为诊断、跨产品现象归因、时代变量下的产品判断”三类，
   不为凑公司、赛道或逻辑类型制造题目。
3. 先找到值得追问的真实行为或矛盾，再核验事实。官方公告只能证明事件，
   不能自动证明它值得出题。
4. 读取历史完成题和不喜欢反馈；30 天内不重复同题，当天被拒绝的公司、
   赛道和分析角度在整组重出时降权或排除。
5. 三题只是候选。用户选中一题后才进入训练并锁定；浏览或拒绝题目不锁题。
6. 三题全部被拒绝时，根据三条原因和用户补充偏好生成新批次。保留旧批次
   作为反馈历史，不覆盖或删除。

## 完成与保存

1. 生成 `run_id` 和确定性标题。
2. 按 reference 生成 Markdown，必须包含用户原始答案、讨论演进、证据来源、完整分析链、
   金字塔结构与 MECE 检查、1 分钟答案、3 分钟答案、追问和迁移方法。
3. 校验后保存到 `06｜训练与题库/产品思维`。
4. 整理本题及讨论中值得继续准备的候选题，向用户确认哪些题要加入统一面试题库。
5. 只把用户确认的题交给 `interview-question-bank`；本 Skill 不直接修改题库。
6. 保存失败时交付完整 Markdown 和原 `run_id`；重试沿用该 ID。

普通暂停不生成正式文档；明确提前结束时保存 `incomplete`。

## 边界

- 只保留训练、研究、答案完善和知识库沉淀。
- 不生成小红书发布内容，也不生成文章发布版本、标题、摘要、标签、卡片、配图、图片排版、
  HTML 或 ZIP。
- 小红书只作为研究来源，不作为发布目标，也不能作为公司内部动机或关键
  数据的唯一事实依据。
