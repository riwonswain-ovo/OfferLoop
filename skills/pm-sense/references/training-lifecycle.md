# PM Sense 训练生命周期

## 目标

把每道题训练成“Agent 先形成独立参考、用户独立思考、教练式追问、金字塔
表达、差异诊断、方法迁移和二次实践”的闭环。Agent 的预研答案是教练参照，
不是唯一标准答案。

## 阶段一：选题与私下预研

用户选定题目后先锁定该题，再开始训练。用户自由输入题目时同样执行本阶段。

1. 按 `question-archetypes.md` 识别主判断任务，写一句内部任务定义：
   “需要判断什么，以及该判断支持什么决策”。不要把题型框架展示给用户。
2. 商业模式、广告、会员、定价、补贴、增长、商业化取舍或指标异动题，按
   `commercialization-reasoning.md` 选择最短的一棵驱动树，不默认展开全部维度。
3. 检索公开信息，核验题目事实，寻找支持、反方、边界和失败案例。
4. 明确标注可验证事实、官方口径、作者观点、用户样本、假设和推断。
5. 按 `source-library.md` 判断是否需要检索私有市场材料。只读取与本题直接
   相关的少量片段，用于识别面试官可能考察的判断任务、其他合理答案路径和
   常见失误；把这些内容单独标为“市场材料校准”，不得替代事实核验。
6. 生成一份结构化“教练底稿”，而不是记录或输出内部思维过程。底稿包括：
   - 主判断任务和采用的推理关系；
   - 研究时间、来源和事实清单；
   - 一句带成立条件的总判断；
   - 二至四个同层理由；
   - 每个理由下的事实、作用机制和例子；
   - 反方解释、边界和可证伪信号；
   - 可能出现的能力缺口。
7. 在用户初答前冻结底稿首版。后续新增事实另记修订，不得根据用户答案
   悄悄改写首版以制造一致。

预研过程只告诉用户“已完成公开信息核验并准备好教练参考”。初答前不得展示
底稿结论、分析维度、来源观点、关键词组合或参考答案。题目依赖陌生事实时，
只补充不带解释方向的中性背景。

## 阶段二：用户独立初答

要求用户不查资料、不追求完整结构，先说出当前真实判断。初答至少包含一个
判断或明确未知、一条理由和一个不确定点；不要以固定字数代替内容判断。

初答前不得给框架、分类、示范答案或“从用户、平台、商业、竞争分析”等方向。

## 阶段三：自下而上思考

从用户已经说出的内容开始：

1. 拆成事实与观察、假设、因果判断、价值判断和未知项。
2. 按 `answer-diagnosis.md` 判断最影响主判断任务的一种坏味道；不要同时
   给多个诊断标签。
3. 优先补最关键的因果跳跃、受影响对象、取舍、反例或证伪条件。
4. 让用户归并相关判断并为每组提炼一句组结论。
5. 检查分组标准、同层关系、重复、混层、断链、失衡和关键缺口。
6. 从组结论中归纳总判断和必要成立条件。

每轮采用“结构观察 → 一个缺口 → 一至两个追问”。可以用教练底稿发现遗漏，
但不能用诱导式问题把用户推向底稿结论。底稿未覆盖但逻辑和证据成立的用户
观点必须保留。

每轮结束按 `answer-readiness.md` 检查七项硬门槛和对应题型的附加条件：

- 若仍有一个缺口可能改变结论、优先级或方案，保持 `not_ready`，下一轮只
  追问最决定性缺口；
- 若继续追问只会增加例子或细节，不会改变判断链，标记
  `ready_for_formal_answer` 并停止横向扩展；
- 不以轮数、篇幅、维度数量或“听起来已经很多”代替就绪判断。

## 阶段四：用户自上而下总结

达到 `ready_for_formal_answer` 后，先让用户独立完成第一版正式答案：

1. 第一句直接回答原题并给出必要条件；
2. 第二层展开二至四个同层理由；
3. 每个理由只承载对应的事实、机制和例子；
4. 最后说明关键取舍、反方、边界或验证方式。

用户完成前不得代写完整答案。未达到要求时保持
`ready_for_formal_answer`，只指出最关键的一个结构问题，让用户自行修订。
能在一至三分钟内清楚表达结论、同层理由和必要边界后，才标记
`ready_for_reference`。

## 阶段五：公开参考与差异诊断

达到 `ready_for_reference` 后，公开冻结的教练底稿及来源，并明确它只是一种
基于公开信息的合理解释。Agent 的参考答案同样必须自上而下表达。

若使用过私有市场材料，只转述少量与差异诊断直接相关的观点，并明确其属于
作者经验或示范解法，不属于一手事实，也不因用户未采用该结构而扣分。

对照时区分：

- **共识**：双方都识别到的事实、机制和判断；
- **用户独有洞察**：底稿未覆盖但成立的观点；
- **关键差异**：事实、因果、权重、边界或结论上的不同；
- **证据强弱**：哪些差异可由证据判断，哪些仍是合理的解释分歧。

不得把“与 Agent 不同”等同于“用户错误”。

## 阶段六：能力诊断与方法卡

引用本轮具体回答，优先指出最影响质量的二至三个不足：

- **视角**：遗漏决定性参与方、机制或约束；
- **逻辑**：因果跳跃、倒果为因或把相关当因果；
- **结构**：把原因、结果、例子和方案放在同一层；
- **取舍**：只有罗列，没有主次和决策依据；
- **边界**：把有条件判断说成无条件结论；
- **表达**：没有结论先行、同层展开或证据归位。

每项诊断必须包含“用户原表现 → 为什么影响答案 → 如何改进”，不能只给
抽象标签或总分。

随后从本题过程提炼一张可迁移方法卡：

- 题型及其核心任务；
- 第一观察点；
- 核心因果链的搭建方式；
- 关键利益变化或约束；
- 常见误区；
- 推翻结论的条件；
- 可迁移的其他产品现象。

方法卡应来自本题暴露的问题，不复用万能利益相关方清单。

## 阶段七：二次作答与完成

反馈后要求用户用一至三分钟重新回答原题。检查其是否：

- 修复本轮最关键的因果或结构问题；
- 形成明确总判断和同层理由；
- 加入必要边界；
- 实际使用刚提炼的方法。

用户完成二次作答并成功生成训练文档后，才把题目标记为完成。普通暂停保留
当前阶段；用户明确提前结束时保存为 `incomplete`，不解锁下一题。

二次作答修复决定性缺口后标记 `ready_for_finalization`，再生成 Agent 最终
参考答案、1 分钟/3 分钟表达和正式训练文档。若未修复，不用 Agent 优化稿
掩盖训练缺口；再做一次针对性修订，或按用户要求保存为 `incomplete`。

## 完成产物

文档按时间保留：

1. 题目和公开证据；
2. 冻结的 Agent 教练底稿首版；
3. 用户原始初答；
4. 自下而上追问和判断演进；
5. 用户第一次自上而下总结；
6. Agent 参考答案与双方差异；
7. 用户能力诊断；
8. 可迁移方法卡；
9. 用户二次作答；
10. Agent 最终参考答案、1 分钟和 3 分钟表达。
