# 产品分析证据融合与答案表达

## 两阶段研究

用户初答前先完成私下预研并冻结教练底稿。研究可以形成 Agent 自己的判断，
但初答前不得向用户展示结论、框架、来源观点或关键词。用户第一次自主总结后
再公开底稿和证据，并针对用户提出的新假设做补充核验。

冻结底稿是结构化参考材料，不是内部思维过程，也不是标准答案。它必须保留
首版时间和来源；补充研究另记修订，不能覆盖首版。

## 证据取舍

在形成完整答案前，把材料标记为以下类型：

- 可验证事实；
- 官方口径；
- 作者观点；
- 个人观察；
- 第三方推广；
- 假设或推断；
- 未经来源验证的数据。

只保留能够补强因果、提供反例、修正边界或支持关键事实的材料。外部研究
不能覆盖用户已经形成的判断；观点冲突时，说明冲突来自事实差异、条件差异
还是解释差异。

具体用户数、交易量、收入、利润、成本、补贴、功能边界和发布日期优先用
公司官网、官方文档、财报、监管或统计数据交叉验证。无法验证的平台动机
必须使用“可能”“更合理的解释是”“可以推断”等限定语。

## 完整答案

Agent 冻结参考答案和最终参考答案都使用自上而下结构：

1. 先直接回答原题，并给出必要的成立条件。
2. 展开二至四个同层理由，每个理由只承载支持它的事实、机制和例子。
3. 串联关键因果，不把原因、结果、例子和方案混在同一层。
4. 说明反方观点、成本、边界、失败条件和可证伪信号。
5. 需要方案时补充优先级、最小验证方式、核心指标和退出条件。

用户完整答案以原始初答、讨论中确认的判断、第一次总结和二次作答为主线。
外部观点应被消化进统一的推导，不把答案写成资料摘要，也不把作者观点伪装
成用户观点或平台内部事实。证据推翻原判断时，明确记录原判断、证据和修订后
判断。

## 对照、诊断与方法

用户第一次总结后，从共识、用户独有洞察、关键差异和证据强弱四方面对照双方
答案。Agent 底稿未覆盖的有效观点必须保留，不以答案一致度评分。

能力诊断只选最关键的二至三个问题，并记录“用户原表现、影响、改进方式”。
方法卡必须说明题型、第一观察点、核心因果链、关键约束、常见误区、证伪条件
和迁移示例。用户二次作答用于验证方法是否被实际应用。

## 表达要求

- 使用克制、清楚、有推演感的中文。
- 先给判断，再解释原因；段落之间保持因果承接。
- 用具体场景、用户路径和对比解释抽象概念。
- 删除虽正确但不能推进核心结论的内容。
- 避免营销化表达、空泛口号、连续反问和固定三点模板。
- 1 分钟版本只保留总判断、核心理由和一个关键边界。
- 3 分钟版本再展开证据、因果链、反方、方案与验证。

## 交付检查

- 主线是否仍来自用户自己的回答？
- 第二层理由是否同层且共同支持总判断？
- 关键事实是否可追溯，未证实动机是否保留限定语？
- 外部研究是否真正改变或补强了因果链？
- 冻结底稿是否在用户初答前形成，且未被用户答案反向改写？
- 双方差异是否允许多种合理解释，而非把 Agent 当标准答案？
- 能力诊断是否引用具体表现，并由二次作答完成验证？
- 是否包含重要反方、边界或失败条件？
- 方案是否给出验证方式，而不是停留在抽象建议？
- 是否完全排除了发布标题、标签、卡片、配图和图片排版？
