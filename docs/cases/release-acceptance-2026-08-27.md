## 真实飞书核心冷启动

验收在用户明确授权的私有知识空间中执行。开始前只读解析现有资源；原“首页”和未命名默认 Base
保持不变。所有新资源均放入带版本与日期标记的隔离验收根节点，未接管生产 locator。

- 连续的 `00`–`06` 目录及经历、逐字稿、ASR、已完成复盘子目录创建并逐项回读通过。
- `01｜核心求职数据` 下三张独立 Base 均可读取：企业清单、求职进展、笔面试中心。
- 企业清单包含 1 张主表与 5 张分类子表；六张表逐一回读，均为相同的 13 字段契约，无多余字段。
- 求职进展为 schema v6 的 11 个字段；13 个受管视图存在，已完成节点视图包含完整进行中状态清单，
  其中包含 `待测评`，并统一按投递日期降序、公司升序排序。
- 笔面试中心包含唯一业务表 `笔面试安排` 和内部 `OfferLoop运行状态` 表；业务表为 23 字段，
  9 个受管视图的环节筛选与统一排序逐项回读通过。
- 7 个长期 Skill 的落盘路径均有真实飞书对象覆盖：机会整理与招聘跟进使用三张 Base；定制简历、
  经历深挖、面试准备、模拟面试、真实复盘分别写入固定目录的合成文档。
- 端到端合成记录先验证默认求职进展不填入投递岗位和岗位 JD，再推进到待一面。完成规划器返回
  `一面完成 + 待反馈`；执行后回读确认复盘文档与 `完成状态=已完成` 位于同一面试记录，关联求职
  进展实际为 `最近完成节点=一面完成`、`进展状态=待反馈`。
- 使用指南正文回读通过，并明确 OfferLoop 只支持与飞书结合的完整模式，不再声称支持单 Skill
  独立下载。

验收记录不包含知识空间 URL、Base URL、token、record ID、邮箱内容或凭证。隔离验收资源按用户
当前指令保留，便于人工查看；没有执行删除或覆盖现有资源。

## 未选择的可选能力

本次未启用邮箱扫描、日历、群通知、22:10 每日卡片、妙搭同步应用或公网服务，因此没有申请或
验证这些可选能力。目标知识空间是空白冷启动环境，不适用旧工作区原地升级；升级迁移仍由离线测试
覆盖，真实旧空间迁移必须另行取得授权。

以上未选择项不属于 7 Skill + 三张 Base + 私有知识库的核心安装门槛，不阻止本候选同步公开仓库。
