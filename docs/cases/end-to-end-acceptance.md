# OfferLoop v2 合成端到端验收

默认使用本地合成对象、dry-run 和只读核验。真实飞书写入、消息发送、邮箱读取或日历创建需要单独授权。

## A｜安装与知识库

1. 冷安装恰好得到 9 个长期 Skill 和隐藏 `.offerloop-runtime`。
2. 重复安装返回 `already_installed`；旧版升级将 `pm-sense` 迁移为 `competency-lab`，并退役三个一次性 Skill。
3. 配置从旧版升级，版本升级为 5，原字段与 token 保留。
4. 固定知识库目录完整；三张入口指向原 Base 对象，重复升级不产生副本。

## B｜招聘机会闭环

1. 城市或行业明确不满足时不写入。
2. 硬条件缺失时进入待确认，不自行猜测。
3. 硬条件满足但岗位软偏离时展示公司、岗位、偏离原因和推荐理由。
4. 用户选择写入、忽略或不再推荐同类；只有确认后的候选进入去重写入。

## C｜求职进展闭环

1. 邀请只创建待完成事件并更新 `进展状态`，不推进最近完成节点。
2. 用户确认完成或可靠事件证明完成后才推进节点。
3. 跳轮、加面、无笔试、重复回调和乱序事件不造成状态倒退。
4. `笔试中` 只统计 `环节=笔试 且 完成状态=待完成`；已完成笔试立即退出统计。
5. 无法可靠迁移的旧记录进入“迁移复核”视图。

## D｜每日进展确认

1. 计划固定为 `21:30 Asia/Shanghai`。
2. 群成员分页截断、存在多个真人、唯一真人不是所有者或缺少成员读取权限时暂停。
3. 不自动切换私聊，也不发送模糊替代消息。
4. 重复按钮只处理一次；自由文本先产生变更预览，确认前不写 Base。

## E｜能力成长闭环

1. `mock-lab` 和 `talk-review` 输出状态为待验证的 `AbilityObservation`。
2. `competency-lab` 自动读取未解决观察，无需用户重新描述。
3. 训练完成后进入待复测；后续模拟优先抽查，独立验证通过后才标记解决。
4. 单次失败不得永久写入用户能力标签。

## F｜经历深挖时间限制

1. 开始前列出全部主题、优先级和预计耗时。
2. 用户要求 20 分钟时，列出完整、压缩和延期候选，由用户取舍。
3. AI 项目覆盖 AI 必要性、技术路径、人机边界、端到端链路、数据评测、失败降级、方案取舍、个人 ownership 与证据。
4. 时间到保存 `incomplete` 和待续挖清单；有延期项时不得声称完整完成。

## G｜材料与产物

1. Skill 开工前说明实际读取的必需材料。
2. 私有空间唯一匹配自动读取；零匹配、多匹配或冲突时才询问。
3. 完成和暂停产物分别保存为 `completed`、`incomplete`，标题不含 `run_id`。
4. 保存后返回知识库面包屑路径与 URL。

## H｜工作台与残留

1. 工作台显示触发原因、来源、当前结果、确认状态、下一步和暂停原因。
2. 生成式任务只打开原生 Agent 深链接。
3. 源码、模板和部署产物中不存在 `/openapi/agent-worker/*`、Agent Chat、Worker schema、轮询代码或启动项。

通过记录应包含：执行模式、结果、失败原因、待补偿项以及是否发生真实外部写入。
