# OfferLoop 7-Skill 合成端到端验收

默认使用本地合成对象、dry-run 和只读核验。真实飞书写入、消息发送、邮箱读取或日历创建需要单独授权。

## A｜安装与知识库

1. 四种 Agent 冷安装恰好得到 7 个长期 Skill 和隐藏 `.offerloop-runtime`。
2. 重复安装返回 `already_installed`；9-Skill 升级把 `career-profile`、`competency-lab` 移到
   `.offerloop-backups/<时间戳>/`，不再发现两个入口。
3. 工作区配置升级到 schema v7；画像和能力 locator 原样保留但不参与 readiness。
4. 新工作区使用连续的 `00`–`06`，不创建画像、能力训练或空的历史归档目录。
5. 旧工作区迁移时，两个退役目录原节点进入 `99｜历史归档`，活动目录原节点连续改名为
   `02`–`06`；迁移前预演、冲突停写、逐项回读，重复执行无新增操作。

## B｜招聘机会闭环

1. 城市等硬条件明确不满足时不写入；行业只作展示，不参与筛选。
2. 硬条件缺失时进入待确认，不自行猜测。
3. 硬条件满足但岗位软偏离时展示公司、岗位、偏离原因和推荐理由。
4. 用户选择写入、忽略或不再推荐同类；只有确认后的候选进入去重写入。

## C｜求职进展闭环

1. 邀请只创建待完成事件并更新 `进展状态`，不推进最近完成节点。
2. 用户确认完成或可靠事件证明完成后才推进节点。
3. 跳轮、加面、无笔试、重复回调和乱序事件不造成状态倒退。
4. `笔试中` 只统计 `环节=笔试 且 完成状态=待完成`；已完成笔试立即退出统计。
5. 无法可靠迁移的旧记录进入“迁移复核”视图。

## D｜每日进展确认

1. 计划固定为 `22:10 Asia/Shanghai`。
2. 群成员分页截断、存在多个真人、唯一真人不是所有者或缺少成员读取权限时暂停。
3. 不自动切换私聊，也不发送模糊替代消息。
4. 重复按钮只处理一次；自由文本先产生变更预览，确认前不写 Base。

## E｜退役能力链

1. `mock-lab`、`talk-review` 不生成 `AbilityObservation` 或跨任务训练待办。
2. 训练建议留在当前产物，表达与承压练习路由到 `mock-lab`。
3. 旧 `ability_observations` 与相关 `tasks` 加载、持久化后语义不变，不再新增。
4. Runtime 只暴露机会与求职进展两条 workflow，不包含能力 Agent 深链。

## F｜经历深挖时间限制

1. 开始前列出全部主题、优先级和预计耗时。
2. 用户要求 20 分钟时，列出完整、压缩和延期候选，由用户取舍。
3. AI 项目覆盖 AI 必要性、技术路径、人机边界、端到端链路、数据评测、失败降级、方案取舍、个人 ownership 与证据。
4. 时间到保存 `incomplete` 和待续挖清单；有延期项时不得声称完整完成。

## G｜材料与产物

1. Skill 开工前说明实际读取的必需材料。
2. 私有空间唯一匹配自动读取；零匹配、多匹配或冲突时才询问。
3. 完成和暂停产物分别保存为 `completed`、`incomplete`，标题不含 `run_id`。
4. 保存后返回知识库面包屑路径与 URL。

## H｜快照、回滚与残留

1. 创建 retirement snapshot 后再升级；snapshot 文件摘要与私有权限均通过。
2. rollback dry-run 不写入；confirmed 恢复旧 Skill、运行时、配置和 Loop 状态，并返回待确认的
   Base 偏好恢复补丁与知识库目录恢复状态；重复回滚幂等。
3. 回滚不删除下线后产生的简历、面试准备、模拟或复盘文档。

通过记录应包含：执行模式、结果、失败原因、待补偿项以及是否发生真实外部写入。
