# OfferLoop 0.1.0-alpha.8

## 重点变化

- 新增可选 `offerloop-agent`，必须建立在已部署的 `offerloop-workbench` 上。
- 保留工作台右侧智能助手；前端右侧栏、服务端任务队列和 OpenAPI 路由安装进同一个妙搭应用，
  不创建第二个应用。
- 迁移已经验证的 Codex app-server 链路：工作台新建对话会创建原生 Codex task，续聊、停止与
  归档沿用原生能力。
- 本机 worker 改为显式绑定用户自己的工作台 URL、App ID 和飞书用户 ID，不再内置开发者
  应用、身份或绝对路径；共享工作台时不会跨用户领取任务。
- `offerloop-workbench` 保持 provider 无关；当前 `offerloop-agent` provider 仅为 Codex。
- Agent 队列表允许后端服务角色处理全队列，普通用户只能访问自己的行，匿名用户无权访问；
  加装脚本会验证同一 App ID、拒绝覆盖未知布局，并在原子写入前备份接线文件。
- 对话分类优先读取飞书知识库目录，目录接口不可用时回退到内置分类。

## 能力边界

- OfferLoop 现在包含十一个 Skill。
- `full` 仍部署核心空间、业务能力、训练能力与可选工作台，但不会自动安装 Codex Agent。
- `agent` 是单独能力选择，会先检查知识库和已有工作台。
- 未安装或停用 Agent 不影响知识库、三张 Base、招聘同步、提醒或训练 Skill。

## 迁移说明

旧的独立 Agent 妙搭应用不再是运行依赖。本版本只从仓库移除旧本地项目；远端妙搭应用的删除
仍需用户单独确认。已有工作台内已经跑通的 Agent 链路可以由新 Skill 接管并幂等升级。
