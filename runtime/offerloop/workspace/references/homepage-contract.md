# OfferLoop 首页与目录契约（v7）

首页固定为 `00｜OfferLoop 使用指南`，只负责导航、数据边界、机会与面试两条闭环和 7 个长期
Skill 的说明。旧工作台入口已经退役，不得继续展示或作为就绪条件。

## 固定目录

```text
00｜OfferLoop 使用指南
01｜核心求职数据
  ├── 企业清单（原 Base 的知识库快捷节点）
  ├── 求职进展（原 Base 的知识库快捷节点）
  └── 笔面试中心（原 Base 的知识库快捷节点）
02｜定制简历
03｜经历深挖
04｜面试准备
05｜模拟面试
06｜真实面试复盘
  ├── ASR 待复盘
  └── 已完成复盘
```

## 数据边界

- 三张 Base 必须沿用原 token 与记录；知识库节点只是指向同一对象的入口，不得复制 Base。
- Base 是求职事实真源；知识库保存生成产物以及只读的历史归档。
- 首页不得复制业务记录。
- 产物必须按 `artifact-contract.md` 的目录、标题与 `completed` / `incomplete` 状态保存。
- `run_id` 只存在于内部元数据，不进入文档标题。
- 自动化只能更新受控入口块，不能覆盖用户自行维护的正文。
- 新工作区使用连续的 `00`–`06` 活动目录，不创建画像或岗位能力训练目录。
- 升级工作区先创建 `99｜历史归档`，把旧 `02｜用户画像`、`05｜岗位能力与训练` 移入其中并
  去掉编号，再将活动目录原节点依次改名为新的连续编号；不复制、不删除文档。
- 目录迁移必须先运行 `artifact_contract.py plan-directory-migration`，经用户确认后逐项执行并回读。
